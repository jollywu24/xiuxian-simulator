# 资源生产与生命周期规范

新增、替换、移动、删除资源或调整生产管线时，读取对应章节；纯文档、规则或代码任务无资源变化时不触发本规范。本文承接从 AGENTS.md 移出的资源规则。路径以仓库根目录为基准，任务授权遵守 [AGENTS.md](../AGENTS.md)，视觉还原见 [VISUAL_IMPLEMENTATION.md](VISUAL_IMPLEMENTATION.md)。

## 1. 目录与发布输出

| 位置 | 用途 |
| --- | --- |
| `web/assets/<system>/` | 当前运行代码或发布契约实际引用、已验收的发布资源 |
| `art_source/<system>/<pipeline-version>/` | 唯一可编辑或可重建的源母版、配置与管线 README |
| `docs/assets/` | 正文直接引用、当前决定仍依赖的最小一组效果图 |
| `scripts/assets/` | 脚本不可内联的稳定夹具 |
| `.tmp/<task>/` | 本任务可重建、无需长期保留的截图、日志和试验 |

- `web/` 及发布脚本纳入的资源视为准备公开分发；源工程、未采用试稿、设计参考、QA 拼图和试验页不得进入发布目录。评估通过许可、版本、运行时和目标视口验证后，才迁入对应正式目录。
- 一个美术对象保留一份权威源母版与一份当前发布输出。生成脚本从 `art_source/` 读取，向明确目录导出并可生成 QA 图；不得从效果图反向裁切正式资源。源管线 README 记录用途、作者／来源、生成式或第三方素材、许可与分发权、画布、锚点、命令、输出和人工验收项；来源或许可不清楚时不得发布。
- 运行资源须有当前 HTML、CSS、模块、资源目录或 `scripts/release-contract.mjs` 的有效引用；旧代码、注释和废弃选择器不算引用。资源改动运行 `scripts/verify-release-assets.mjs`，检查缺失与孤儿文件，并在受影响视口检查裁切、透明边缘和清晰度。
- 运行资源采用小写 ASCII `kebab-case` 与显式版本后缀；内容或裁切契约变化时升版本并同步引用，不使用“最终版”、空格、中文或日期文件名，不引入内容哈希。默认 WebP，简单可缩放图形用 SVG；确需无损或精确透明时用 PNG。工程文件和图集母版不进 `web/assets/`，Pages 资源不使用 Git LFS。
- 单个新增运行资源超过 `2 MiB`、同一功能新增超过 `10 MiB`、或 `web/assets/` 总量超过 `50 MiB` 时，先记录必要性、移动端下载／内存成本与替代方案；预算不是保留未用资源的理由。源母版过大时先确定受控存储与可重建交付方式。
- 效果图采用稳定语义文件名，更新决定时同步正文；旧稿按下节的授权范围清理，已提交版本由 Git 历史追溯，不另建永久试稿仓库。

## 2. 删除与替换

- 删除前检查动态路径、资源目录、CSS、脚本、测试、文档和当前在制改动；“未跟踪”“文件名旧”或搜不到完整路径不能单独证明可删。候选须有已被替代、功能撤回、可由保留母版重建，或仅为无交付价值临时输出的证据。
- 用户已明确指定删除对象，或已确认清单时，在原范围内执行，不重复确认。笼统的“清理”“优化”不足以授权删除；先给出路径／完整分组、数量、大小、依据、引用影响和 Git 恢复能力，只询问未授权部分。未跟踪文件明确说明 Git 无法恢复；新增对象或实质扩大影响时补充确认。
- 不擅自删除、覆盖或通过移动清空用户原有素材。本任务自行生成、可重建且无交付价值的临时文件可自行清理，先核实绝对路径位于本任务临时目录；此例外不适用于用户原有或来源不明文件。工具权限要求仍须满足。
- 删除正式资源时同步清除失效引用、废弃生成入口和空目录，更新发布契约及相关测试、文档；不得迁往仓库内的 `backup/`、`old/` 或 `archive/` 变相保留。
- 正式资源删除后执行孤儿／缺失引用审计、`git diff --check`、`npm run test:release` 及受影响系统测试；影响界面时补对应浏览器与视口检查。仅清理本任务日志等临时输出不触发游戏验收。

## 3. 可组合美术的生产与验收

- 效果图、单张 AI 图片和偶然对齐的样例不能充当生产规范。涉及可组合美术时，必须先固定共同母版、画布、锚点、插槽、层级、遮罩、兼容规则与组合验收，再制作批量资源；
- 新方案先完成一个有明确验收条件的最小纵切。规则、组合美术与界面分别执行适用的测试、图板和视口检查；有限组合可穷举，开放状态用关键路径与边界覆盖，不把“穷举”扩展成无限状态要求。通过后继续完成用户已要求的内容。
- 组合图板只有在人物以可辨识尺寸展示、逐格人工检查并明确核对头身比例、领口、肩线、手脚、接缝、遮挡和透明边缘后才算通过；“文件可生成”“尺寸一致”或“浏览器无报错”都不能替代视觉验收；
- 视觉验收发现结构性错位时，当前资源不得发布，也不得把自动测试通过描述为美术通过；必须收回不合格选项，回到共同母版重做；
- 若问题来自底层结构或资产契约，立即停止逐图偏移、局部遮盖和特例 CSS 等补丁式修复，回到方案与生产管线重做。
