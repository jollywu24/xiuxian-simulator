# 《武道》效果图还原工作流

本文规定确认效果图从“视觉参考”进入正式网页的固定流程。目标是让还原工作可以测量、复查和回归，不再依靠反复目测修补。

## 1. MVP视口合同

当前MVP只制作两种可玩布局：

- `1280×720`桌面基准；
- `844×390`手机横屏基准。

若用户确认的效果图有独立设计标尺，例如`1672×941`，则该标尺用于逐项量取比例，并在两个运行基准中等比落地。

`390×844`手机竖屏不再制作游戏布局，只验证：

- 显示清楚的横置提示；
- 正式游戏界面不可误触；
- 页面没有横向溢出；
- 旋转到横屏后可正常进入当前流程。

竖屏完整适配在MVP玩法、信息结构与美术语言稳定后单独排期，不能在每次界面还原时顺带处理。

## 2. 固定八步流程

### 第一步：冻结唯一参考

一次只还原一张已确认效果图、一个界面状态和一个设计视口。开始前必须写清：

| 项目 | 必填内容 |
| --- | --- |
| 参考图 | 仓库中的稳定路径 |
| 页面状态 | 例如“默认选中世家旁支”或“打开回春丹详情” |
| 设计视口 | 效果图原始宽高 |
| 运行视口 | `1280×720`、`844×390` |
| 保留内容 | 必须出现的文字、按钮、资源和状态 |
| 明确差异 | 因可读性、交互或资源限制而允许的差异 |

参考改变时先更新这张表。不得一边实现，一边把另一张效果图中的局部样式混入当前页面。

### 第二步：量取，而不是目测

从参考图记录：

- 顶栏、主栏、侧栏和底栏的边界；
- 各区域占视口的百分比；
- 图片显示框比例和安全区；
- 标题、正文、标签、按钮的字号与行高；
- 主要间距、内边距、边框和圆角；
- 默认、选中、锁定、危险、悬停、弹层等状态。

尺寸优先写成少量CSS变量，禁止在文件末尾不断追加只修一个截图的魔法数字。

### 第三步：先还原灰盒

先用纯色块和真实文字完成区域、比例、滚动与触控目标。灰盒通过前，不生成正式原画，不调整纹理和装饰。

灰盒验收：

- 所有主区域边界与参考一致；
- 关键按钮无需滚动即可到达；
- 文字不会因真实长度破坏结构；
- 横屏不横向溢出；
- 竖屏门禁生效。

### 第四步：按槽位生产资源

正式资源必须先确定目标画布、裁切方式和安全区，再生成或拆分。资源进入：

- 可重建源文件：`art_source/`；
- 正式网页资源：`web/assets/<system>/`；
- 仅供验收的确认稿：`docs/assets/references/`。

不得用CSS缩放、负边距或遮盖来补救人物脚底、领口、装备格、热点等资产对位错误。

### 第五步：补齐真实状态

页面不是静态海报。必须逐项实现并检查效果图涉及的状态：

- 默认与选中；
- 可用、不可用与条件详情；
- 打开、关闭和返回；
- 使用、装备、替换或确认；
- 信息流上推、滚动锚点和刷新恢复；
- 桌面与手机横屏的同一规则状态。

### 第六步：确定性截图

通过固定存档、固定状态或调试入口，在约定视口生成截图。截图必须来自浏览器真实运行页，不能用设计稿代替。

每个界面通常只保留：

- 一张桌面基准截图；
- 一张手机横屏截图；
- 一张竖屏门禁截图；
- 必要时一张弹层或选择后状态截图。

### 第七步：叠图比较

把运行截图与参考图同尺寸叠加，按以下顺序修正：

1. 外框和主分区；
2. 图片框、人物和主要物件；
3. 字号、行高和文字宽度；
4. 按钮、格位和间距；
5. 颜色、纹理、阴影与动效。

不允许在结构未对齐时先花时间修颜色和纹理。每轮只解决一层差异，并记录刻意保留的偏差。

### 第八步：把几何约束写进回归

视觉验收通过后，把易复发的关系写进浏览器回归，例如：

- 三栏宽度比例；
- 等大格位和等距间隔；
- 人物中轴与脚底基准；
- 关键按钮是否在视口内；
- 场景热点是否落在原物件上；
- 弹层是否先于实际装备操作；
- 横屏无溢出、竖屏只显示横置门禁。

自动断言守住结构，截图保留整体观感。两者都通过才算还原完成。

## 3. 完成定义

一次效果图还原只有同时具备以下产物才算完成：

- 唯一确认稿和状态说明；
- 可复查的尺寸／比例表；
- 对应运行资源及来源；
- 桌面和手机横屏真实截图；
- 竖屏横置门禁检查；
- 至少一条针对关键几何或交互的浏览器断言；
- 设计文档、运行代码和测试口径一致；
- 日常迭代通过`verify:quick`与受影响视觉回归；到可试玩检查点或明确发布时再通过完整质量门禁并上线。

## 4. 时间判断

固定流程不能把一张效果图直接变成可玩的页面。效果图没有DOM、滚动、存档、条件状态和不同文字长度，原画也可能不具备可直接切图的安全区。但流程能把工作从“多轮猜测”改成“先量取、后实现、按差异收敛”，并避免每次为竖屏重做一次信息结构。

若参考、状态和文案在施工中继续变化，应视为目标变更，重新冻结基准；不能把由此产生的返工归入单纯的像素还原时间。

## 5. 当前容貌页冻结基准

| 项目 | 内容 |
| --- | --- |
| 参考图 | `docs/assets/references/appearance-interface-v5.jpg` |
| 页面状态 | 男身、十一类第一项；逐部件验收时单独切到第二项 |
| 设计／桌面视口 | `1280×720` |
| 手机横屏视口 | `844×390` |
| 保留内容 | 姓名、体貌、十一类环绕控件、四套推荐组合、随机与确认 |
| 明确差异 | 十一类各开放两个真实选项并显示`1/2`；不伪造参考图中的`1/8` |

人物资源以男女共同母版锁定年龄、脸部、领口和肩线，再从同一母版派生衣装与局部部件；不得为单个编号增加运行时CSS位移。帽子控制条底边必须与人物头顶至少留`4px`安全距，人物和帽子控制条中轴都必须落在视口中轴。
