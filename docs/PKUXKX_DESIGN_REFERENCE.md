# 《北大侠客行》系统设计拆解与《大曜江湖》适配参考

> 文档用途：研究经典武侠MUD如何用房间、动词、门派、武学、任务和长期状态构成可持续江湖，并提炼适合单人浏览器文字冒险的设计方法。
>
> 核对日期：2026-07-15。
>
> 边界说明：《北大侠客行》是多人在线MUD。本项目不引入其他玩家、多人竞争、交易、排行或在线社区；相关系统只用于分析其为何成立，不进入第一版范围。

## 1. 结论先行

《北大侠客行》自1996年延续至今。它表面上是一款依靠英文指令操作的纯文字游戏，底层却已经具备现代角色扮演游戏的大部分结构：

- 房间连接成世界地图；
- 动词指令构成交互语法；
- 门派、师父和道德决定人物身份；
- 基本功、特殊武学、内功和绝招构成战斗配置；
- 经验、潜能、声望和门派忠诚推动长期成长；
- 小说情节被改造成地点、物品、条件和谜题链；
- 死亡、叛师、年龄、饥渴和伤势留下持续后果；
- 论坛、Wiki、频道、客户端与脚本共同承担教学和内容传播。

它的核心循环可以压缩为：

```mermaid
flowchart LR
    A[观察房间与人物] --> B[移动、询问、搜索或接受任务]
    B --> C[战斗、解谜、护送或练功]
    C --> D[获得经验、潜能、声望、忠诚或物品]
    D --> E[拜师、学习、练习、领悟与激发武学]
    E --> F[进入更深地点、师承和秘密]
    F --> A
```

循环之外还有一层玩家生态：

```mermaid
flowchart LR
    G[游戏内困惑] --> H[频道求助、论坛、Wiki]
    H --> I[路径、别名、触发器与脚本]
    I --> J[更高效率地重复任务与探索]
    J --> G
```

对《大曜江湖》最值得采用的五点是：

1. **稳定的“动词＋对象”交互语法。** 同一套动作可以作用于不同人物、物品和场景。
2. **基本行动与特殊武学分离。** 人物可以学会很多武学，但当前只把其中一门激发到剑法、招架、轻功或内功等基础能力上。
3. **同一动作区分意图。** 比试、攻击、制伏与杀死不是同一个按钮换文案，而会改变死亡、道德和人物关系。
4. **小说情节直接变成条件链。** 地点、道具、人物对话、身体代价和武学副作用彼此相扣。
5. **门派是制度身份。** 师父、忠诚、道德、技能门槛和叛师代价共同决定玩家属于谁。

第一版明确不采用：

- 命令行输入和英文指令记忆；
- 多人频道、交易、比武和排行榜；
- 经验与技能等级的长期重复刷取；
- 必须查Wiki才能知道的隐藏门槛；
- 自动机器人、挂机练功和现实时间任务次数；
- 数十个并行属性、货币与状态栏；
- 无预警的真死掉技能；
- 把多个受版权保护作品直接拼成一个世界。

一句话判断：

> **借它的规则语法、武学激发、身份约束和情节谜题；不借它的操作门槛、多人依赖与挂机成长。**

## 2. 产品背景与分析口径

### 2.1 作品性质

《北大侠客行》是中文武侠MUD。玩家通过网络连接服务器，阅读房间、人物、战斗和系统输出，再输入指令行动。它长期由“巫师”开发者、志愿维护者和玩家社区共同维护，官方论坛至今仍包含公告、开发进程、答疑、玩家攻略、客户端技术与交易等板块。

它与现代商业RPG有三点根本区别：

| 维度 | 《北大侠客行》 | 《大曜江湖》 |
| --- | --- | --- |
| 世界状态 | 持久在线，多人共享 | 单人存档，按玩家选择推进 |
| 操作方式 | 自由文本指令、别名与脚本 | 按钮、数字键与明确条件板 |
| 内容生产 | 数十年增量开发与社区知识 | 小团队高密度篇章与自动校验 |

因此不能用现代首小时留存标准简单否定它，也不能因为它长寿就照搬其历史包袱。

### 2.2 资料等级

| 资料 | 可信用途 | 局限 |
| --- | --- | --- |
| 官方网站、论坛和开发进程 | 当前运营、系统结构、开发方向 | 内容跨度大，规则可能经过多次改版 |
| 官方Wiki | 地点、谜题、武学和条件 | 部分页面由玩家维护，更新时间不同 |
| 精华攻略和客户端教程 | 实际操作流程、成长路线、界面痛点 | 可能代表特定版本或效率玩法 |
| 媒体历史文章 | 诞生背景与长期社区 | 不适合核对具体数值 |

本文只拆解稳定设计结构，不把旧攻略里的具体伤害、等级或任务次数当作当前定案。

## 3. MUD的核心表达：房间、对象和动词

### 3.1 房间是最小世界单位

玩家每到一处，系统通常提供：

- 房间名称；
- 环境描述；
- 明显出口；
- 当前人物、物品或异常；
- 可以进一步询问或操作的线索。

房间通过东、西、南、北、进入、出来、攀爬、渡河等出口连接，最终形成巨大的有向图。玩家不是在连续坐标上移动，而是在具有叙事意义的节点间转换。

这种结构特别适合文字内容，因为每个节点都可以拥有独立规则，而不需要制作连续地形。

### 3.2 动词是统一交互协议

MUD常用动作包括观察、询问、给予、拿取、放入、购买、阅读、练习、打坐、吐纳、接受、攀爬、推动、搜索和战斗等。它们的价值在于复用：

```text
观察 + 人物
观察 + 物品
询问 + 人物 + 话题
给予 + 人物 + 物品
推动 + 场景对象
阅读 + 书籍
```

当动词语义稳定后，开发者只需要新增对象和条件，就能组合出新内容。

### 3.3 优点

- 世界对象都可能被操作，而不是只有带叹号的任务NPC；
- 玩家会主动阅读描述中的名词；
- 同一个动作在不同场景产生不同后果；
- 新内容可以沿用已有规则，制作成本较低；
- 文字能描述图形系统难以承载的武学和奇景。

### 3.4 缺点

- 玩家常常不知道系统接受哪个动词；
- 中文场景配英文指令提高记忆门槛；
- 同义动作可能使用不同命令；
- 错误反馈容易只说“不能这样做”；
- 大量内容最终依赖Wiki、老玩家或客户端宏；
- 玩家会通过枚举动词而不是理解情境解决问题。

### 3.5 《大曜江湖》的适配

不开放自由命令输入，但内部内容结构继续使用“动词＋对象”：

```text
observe:dan_furnace
ask:cao_qing:identity
give:dragon_scale_herb:third_lady
practice:spring_rain_needles
threaten:masked_bladesman
spare:masked_bladesman
```

界面只显示当前合理的三至五个动作，并用按钮文案说明对象、代价和意图。数字键继续作为快捷方式。

这个做法同时保留MUD的系统复用和现代界面的可发现性。

## 4. 空间设计：地图记忆来自路线，而不是坐标

### 4.1 路线知识本身就是成长

北侠玩家需要记忆城市、门派、渡口、山洞和隐秘入口的路径。客户端后来增加本地地图、路径别名和可点击导航，说明“知道怎么去”本身就是重要知识，也说明纯手动方向输入会随世界扩大而变成负担。

路线包含多种状态：

- 固定出口；
- 需要付费或等待的渡口；
- 需要轻功、物品或口令的入口；
- 会变化的山路或阵法；
- 只能通过退出重登离开的特殊空间；
- 会因身份、道德或仇恨受到守门人攻击的地点。

### 4.2 设计价值

- 地点不只是背景，而是能力和身份的考验；
- 走过一次后形成真实的空间记忆；
- 门派所在地与武学气质自然结合；
- 世界可以通过新增房间和出口持续扩展；
- 路线秘密能够成为玩家间交流的内容。

### 4.3 风险

- 重复输入方向很快失去意义；
- 同名房间和长路线令玩家迷路；
- 路径脚本一旦普及，移动本身不再是玩法；
- 地图越大，空房间和纯过道越多；
- 路线错误可能导致不可预见的死亡。

### 4.4 本项目的路线规则

《大曜江湖》只保留具有选择意义的路线节点：

| 路线差异 | 必须改变的内容 |
| --- | --- |
| 水路与官道 | 时间、伤势、见闻或到达时机 |
| 白日与夜路 | 人物、危险或隐蔽程度 |
| 正门与暗道 | 身份检查、关系或暴露风险 |
| 熟路与陌生路 | 行动成本和可见线索 |

走过并掌握的无风险旧路可以一键到达；只有发生新事件、追逐、天气变化或条件判断时才重新展开。

## 5. 人物成长：经验决定上限，潜能支付学习

### 5.1 稳定成长层

北侠长期角色通常同时拥有：

- 膂力、悟性、根骨、身法等基础属性；
- 精神、精力、气血、内力等当前与上限资源；
- 食物与饮水；
- 经验与潜能；
- 道德、杀气、江湖声望和师门忠诚；
- 基本功、特殊武学、知识技能与生活能力；
- 年龄、死亡次数、师承、国籍、职业和装备等长期状态。

其中最关键的成长关系是：

```text
经验：证明经历过多少实战，限制可以达到的能力高度
潜能：用于向师父学习、领悟或修炼的可消费资源
技能：通过学习、读书、练习、领悟和修炼等不同方法提升
```

它比“升级自动加技能点”更有武侠味，因为玩家必须回答：向谁学、读什么、练什么、用什么方法继续突破。

### 5.2 不同学习方法的意义

| 方法 | 叙事意义 | 常见限制 |
| --- | --- | --- |
| 向师父学习 | 正统师承 | 师父上限、忠诚、道德、潜能 |
| 阅读秘籍 | 从文字理解 | 识字、悟性、经验和书籍上限 |
| 反复练习 | 身体熟练 | 气血、内力、武器与环境 |
| 领悟 | 从已有经验推演 | 潜能、悟性、基础功 |
| 修炼内功 | 长期自修 | 时间、潜能、内力和身体条件 |
| 切磋 | 从有效战斗提高 | 对手、风险和技能匹配 |

这种“同一技能有多条学习路径”的结构非常适合表现出身和门路差异。

### 5.3 主要问题

- 数值种类多，玩家很难知道当前真正短缺什么；
- 巨量技能等级导致重复学习和挂机；
- 师父上限与秘籍上限容易迫使玩家查表；
- 高悟性或高效率路线可能成为长期唯一答案；
- 经验、潜能和技能等级会膨胀到难以直观理解；
- 角色已经会很多武学，却可能因数值落后而无法使用。

### 5.4 《大曜江湖》的压缩

继续保留五维、潜能、境界、武学熟练和少量技艺，不新增精力、精神、声望、杀气等独立常驻数值。

需要表达时优先使用状态：

| 北侠数值 | 本项目表达 |
| --- | --- |
| 师门忠诚 | 曹青信任、师徒承诺、是否守约 |
| 道德 | 具体人物和势力记住的行为 |
| 杀气 | 杀人记录、敌意和心神状态 |
| 精神／精力 | 当前场景的心神或疲惫状态 |
| 食物／饮水 | 旅途或丹房篇章中的饱腹、补给 |
| 经验 | 已亲历事件和境界条件 |

数值只有在能跨多个事件稳定发挥作用时才成为永久字段。

## 6. 武学架构：基本功、特殊功夫与激发

### 6.1 基本功是动作类别

基本剑法、基本拳脚、基本招架、基本轻功和基本内功等，代表角色能够执行的通用动作类型。

### 6.2 特殊功夫是具体门派方法

特殊武学提供：

- 独特招式描述；
- 命中、伤害、招架或闪避方式；
- 主动绝招；
- 内功运用；
- 武器、属性、内力和前置技能要求；
- 门派或传承身份。

### 6.3 激发是当前配置

人物可以学会多门剑法或内功，但通常要把一门特殊功夫“激发”到相应基本功上，当前战斗才按这门功夫运作。

```text
基本剑法 ← 当前激发的特殊剑法
基本招架 ← 当前激发的招架方法
基本轻功 ← 当前激发的身法
基本内功 ← 当前运行的内功根基
```

玩家“会什么”和“现在怎么打”因此被分开。这个结构解决了武学收藏与战斗可读性的冲突：可以学很多，但当前配置有限。

### 6.4 主动绝招与内功运用

特殊招式通常还要求：

- 对应特殊武学已激发；
- 基本功和特殊功达到等级；
- 当前内力、精力或气血足够；
- 使用正确武器或空手；
- 部分内功、属性或状态同时满足。

战斗因此形成“普通动作持续进行，玩家在恰当时机插入绝招或运功”的节奏。

### 6.5 最值得采用的部分

《大曜江湖》可以建立更简单的三层语法：

```text
基础行动：刺、挡、退、观察、运气
武学方法：春风针、打鱼杆法、五禽戏
当前根基：鱼跃龙门诀、枯木桩、定海桩
```

每次判定只显示一项基础行动、一门武学和一个根基反应：

```text
封腕
行动：出针
武学：春风化雨针
根基：枯木桩令受伤手臂更稳
结果：命中后封住左腕
```

不让玩家配置十几个槽位。已学武学全部保留，战前只选择一门当前根基，具体行动自动调用合理武学。

## 7. 武学不只是奖励：传承条件与副作用

北侠的秘籍和绝学经常嵌入完整情节。例如官方Wiki记录的冰火岛内容，把一门武学与以下条件连接：

- 到达遥远岛屿；
- 在不同场景取得绳索、火种和食物；
- 制作交通工具；
- 与关键人物建立进入洞穴的条件；
- 进入特殊空间阅读秘籍；
- 武学达到高层后产生伤身或失控副作用；
- 需要另一类知识或医术处理后果；
- 特殊兵器之间还会产生新的传承结果。

这类设计的价值在于：

> 玩家不是捡到一本技能书，而是亲身走完这门武学为什么存在、怎样传下来、练错会发生什么。

### 7.1 本项目的传承模板

每门重要武学至少回答：

1. 谁创造或保存了它？
2. 为什么愿意让玩家接触？
3. 学习前需要哪项生活、关系或身体条件？
4. 练习地点为什么不可替代？
5. 武学与某件物品或事件有什么历史联系？
6. 练得更深会承担什么副作用？
7. 哪种医术、内功或人物能处理副作用？
8. 它会打开哪条新路线，而不是只提高战力？

### 7.2 当前内容可用示例

| 武学 | 传承链应继续补强的内容 |
| --- | --- |
| 鱼跃龙门诀 | 漕帮水路、龙青鱼旧事、闭气代价与临安再会 |
| 五禽戏 | 曹青医理、五种身体方向、养生与强行突破冲突 |
| 春风化雨针 | 白栀云救命、曹青指点、医人和杀人的双用后果 |
| 打鱼杆法 | 王五、黄金钱鳘、水边借力与普通兵器的低位智慧 |
| 枯木／定海桩 | 师徒选择、旅行差异、受伤承载和未来门派立场 |

## 8. 战斗系统：实时文字、自动拆招与意图指令

### 8.1 基本结构

MUD战斗通常在玩家发起攻击后持续自动输出普通拆招，玩家可以在过程中使用特殊攻击、运功、加力、换武学或逃离。现代客户端会把气血、内力、忙乱状态和近期战斗信息单独显示，帮助玩家从高速文字中提取结果。

主要战斗信息包括：

- 当前气血与最大气血；
- 当前内力与加力；
- 精神与精力；
- 命中、闪避和招架；
- 敌我忙乱或控制状态；
- 武学和绝招消耗；
- 伤害与伤势；
- 是否进入致死敌对。

### 8.2 意图不同的攻击指令

北侠存在比试、攻击、叫杀等不同战斗发起方式。即使底层细节随版本和对象变化，这个设计原则非常重要：

```text
切磋：验证武学，不以杀死为目的
攻击：打伤、击倒或逼退
制伏：限制行动并取得后续处置权
杀死：明确承担死亡、道德和仇恨后果
```

《大曜江湖》已经在夜战中提供杀死、制伏和逃离，应把“意图”上升为通用战斗字段，而不是每场单独写分支。

### 8.3 忙乱控制的价值

北侠大量武学围绕“busy”展开：让敌人在一段时间内无法行动，或因绝招失败让自己陷入硬直。这相当于现代战斗中的控制与行动经济。

值得采用的是：

- 强招会暴露失败后的空档；
- 控制招不必造成高伤害也有价值；
- 武器、内功和特殊状态可以提供不同控制方式；
- 连续战斗时，内力消耗使高效招式不能无限使用。

不采用实时秒数和连续指令队列。项目中统一为回合结果：

| MUD状态 | 本项目显示 |
| --- | --- |
| 对手busy | 对手下一回合不能兑现主要意图 |
| 自身busy | 下一回合只能防守或承受代价 |
| 内力不足 | 当前招式变为苦成或无法深入 |
| 加力 | 提高效果但增加伤势或消耗 |

### 8.4 战斗日志的教训

纯文字可以细致描述招式，但高速滚动后，玩家仍需要血条、状态和摘要。现代北侠客户端教程也把战斗面板、血量、内力、危险、忙乱和复盘列为重要功能。

这支持当前项目加入：

- 连续血条和当前／上限数字；
- 明确敌人意图；
- 当前距离；
- 一至三个关键状态；
- 短动画；
- 可折叠战报。

战报用于回味和复盘，不负责告诉玩家此刻该按什么。

## 9. 死亡：记录能够增强人生感，掉级会制造恐惧与保守

北侠人物状态会记录死亡次数、上次死亡地点与死因。部分危险属于“真死”，可能损失技能或长期投入；门派、任务、药物、练功和未知地点都可能造成死亡。

### 9.1 有价值的部分

- 死亡不是模糊的失败提示，而是人物履历；
- 玩家会记住杀死自己的地点和机制；
- 危险武学和任务具有真实威慑；
- 论坛中的死亡故事成为社区共同记忆；
- 死因可以帮助复盘下一次准备。

### 9.2 不适合本项目的部分

- 数百小时技能因未知机制倒退；
- 隐藏真死迫使玩家先查攻略；
- 玩家为了避免损失只做安全任务；
- 机器人出错比玩家选择更容易导致死亡；
- 长期惩罚与剧情失败混在一起。

### 9.3 《大曜江湖》的适配

保留死亡履历，不增加随机掉级：

```text
死亡地点
直接死因
未看破的后手
已带回的见闻
熄灭的命灯
返回的因果节点
此后永久隐藏或开放的行动
```

两盏命灯负责限制尝试次数，伤势、关系和错过负责长期代价。死亡不能抹去已经理解的规则。

## 10. 门派与师承：制度比技能商店更重要

### 10.1 北侠的门派条件

拜师和晋升通常会检查：

- 基本功和门派武学；
- 内力或其他身体资源；
- 师门忠诚；
- 道德正负；
- 悟性、根骨等属性；
- 是否曾叛师；
- 前任师父与当前辈分；
- 特定任务、秘密或物品。

师父能教到什么、是否愿意收徒、玩家能否进入某地和使用某武学因此互相连接。

### 10.2 设计价值

- 门派成为人物身份，而不是技能列表；
- 晋升意味着获得更深关系和制度认可；
- 忠诚和道德让世界评价玩家长期行为；
- 叛师能够换路线，但会支付真实代价；
- 不同门派拥有不同任务效率、战斗方式和生活福利。

### 10.3 风险

- 隐藏收徒条件逼迫查Wiki；
- 忠诚通过重复任务堆积；
- 玩家为了顶级师父被迫学习大量无用前置；
- 道德成为一条可刷正负的抽象数值；
- 叛师清空技能和内力会否定已有时间；
- 门派强弱随版本变化，身份选择退化成效率选择。

### 10.4 本项目的门路阶梯

沈家与曹青可以先验证一条小型师承阶梯：

| 阶段 | 身份 | 真实变化 |
| --- | --- | --- |
| 门外人 | 持沈字铜钱求差事 | 只能接受外院筛选 |
| 丹房苦力 | 曹青允许暂留 | 接触日常和取血代价 |
| 可教之人 | 通过盘问与考校 | 获得医书、五禽戏和继续观察资格 |
| 可信跑腿 | 如实处理沈福银子 | 取得药房、灶房和钓鱼门路 |
| 记名弟子 | 经夜战和人物选择认可 | 选择桩功并承担师徒关系 |
| 利益相关者 | 卷入沈家与药王谷冲突 | 玩家死亡或背叛会影响多人利益 |

每次晋升都必须改变权限、责任和人物态度，不使用重复门派任务填忠诚条。

## 11. 任务系统：重复任务养成长线，秘密任务塑造江湖

北侠的任务大致可以分为两类。

### 11.1 重复任务

常见作用：

- 稳定产出经验、潜能、声望或忠诚；
- 让玩家练习路线、战斗和物品处理；
- 支撑长时间成长；
- 为排行榜、门派和经济提供持续活动。

问题是重复次数巨大后，玩家自然转向别名、触发器和机器人。此时最优玩法不再是理解任务，而是维护自动化脚本。

### 11.2 秘密与剧情任务

这类内容通常包含：

- 不完整的线索；
- 小说或人物知识；
- 多地点物品链；
- 特殊进入方式；
- 属性、武学或身份条件；
- 战斗与非战斗步骤；
- 独特武学、装备或权限奖励；
- 失败、走火入魔或真死风险。

这类任务才是北侠最值得借鉴的内容，因为它把故事知识变成可操作条件。

### 11.3 本项目的取舍

不制作无限重复任务。需要表达长期练功或差事时，使用：

```text
第一次：完整操作，学习规则
第二次：提供一个新变化或人物事件
掌握后：一键结算，并只在资源不足、天气、关系或危险改变时展开
```

每个篇章至少有一个“情节秘密链”，其奖励是人物、武学、地点或制度入口，而不是经验数字。

## 12. 生存与身体：恢复规则让日常有意义

北侠使用气血、内力、精神、精力、食物和饮水等状态。吃喝不只是装饰，会影响恢复；打坐、吐纳、睡觉、服药和内功分别处理不同资源。

这套结构的优点是：

- 练功与战斗之间需要恢复；
- 酒店、茶馆、药物和住处具有用途；
- 长途旅行需要准备；
- 内功不仅是伤害加成，也负责疗伤和恢复；
- 身体状态能够产生生活感。

问题是常驻六条资源会增加操作负担，最终被脚本自动处理。

《大曜江湖》使用篇章内资源：

- 丹房篇章显示体力和饱腹；
- 旅行显示补给、伤势和到达时辰；
- 战斗显示气血和关键伤势；
- 运功只在需要时显示内息或承载；
- 离开相关场景后，不把所有短期资源永久常驻在主界面。

资源存在的标准是能否迫使玩家做一次有意义的选择，而不是能否每天减少。

## 13. 社区、Wiki和频道：它们实际上是游戏系统的一部分

北侠拥有游戏内聊天与求助频道、论坛答疑、Wiki百科、客户端教程、路径分享、交易市场和开发讨论。对新手而言，很多隐藏规则和复杂指令必须通过这些外部知识层理解。

### 13.1 为什么它能成立

- 多人世界允许老玩家实时回答；
- 复杂秘密形成交流话题；
- 门派和任务经验成为社区资本；
- 开发者与玩家长期共同维护资料；
- 服务器寿命足够长，学习成本可以被长期投入摊薄。

### 13.2 为什么不能直接用于本项目

《大曜江湖》没有其他玩家，也不能假设玩家会加入论坛或查攻略。因此北侠由社区承担的内容必须转回游戏内部：

| 北侠外部支持 | 本项目替代 |
| --- | --- |
| 频道问路 | 已走路线与地点卡 |
| 老玩家告知门槛 | 奇遇条件板的已知缺口 |
| Wiki解释武学 | 人物传授与招式“为何”面板 |
| 攻略警告真死 | 旧见闻、危险预告与命灯规则 |
| 论坛复盘 | 死因记录和已成因果 |
| 门派群体身份 | NPC、制度权限和世界反馈 |

单人游戏中的不透明必须能通过游戏内行动逐步解决。

## 14. 客户端与脚本：可编程性既是魅力，也是设计警报

MUD客户端支持别名、触发器、计时器、路径和脚本。玩家甚至会自己开发跨平台客户端。官方社区允许部分辅助功能，同时对全自动任务机器人和自动地图等能力设限。

### 14.1 正面价值

- 稳定文本协议便于辅助工具读取；
- 玩家可以为自己设计界面和快捷操作；
- 路径、状态和战斗摘要能显著改善可读性；
- 编写脚本本身成为一部分玩家的创造乐趣；
- 开放工具生态帮助老游戏跨平台延续。

### 14.2 负面价值

- 重复任务越多，自动化收益越高；
- 新手不会写脚本时与老玩家效率差距巨大；
- 玩家可能在“玩脚本”而不是玩角色；
- 客户端配置成为进入游戏前的第二套教程；
- 机器人出错可能导致真死和长期损失；
- 开发者需要围绕自动化设计检测和限制。

### 14.3 对内容设计的判断

> **如果一个流程在掌握后最合理的处理方式是让脚本无限重复，它就不应继续占用玩家手动操作。**

《大曜江湖》应自动折叠已稳定掌握的重复流程，把玩家时间留给条件变化、人物抉择、危险和新发现。

可编程性只用于开发层：稳定ID、数据驱动效果、内容校验、自动流程测试和存档迁移，不开放给玩家作为效率门槛。

## 15. 长寿内容架构：低耦合扩展与历史包袱并存

北侠能够持续增加门派、地点、武学、任务和客户端功能，得益于MUD内容天然模块化：

```text
新增房间
＋新增NPC
＋新增物品
＋新增指令或条件
＋连接已有经验、潜能、门派和战斗规则
```

### 15.1 值得采用

- 地点与事件使用稳定ID；
- 新内容尽量复用已有动作和效果；
- 门派、武学和任务可以分包增加；
- 开发过程公开讨论，便于提前发现组合问题；
- Wiki式文档记录条件、来源和历史变化；
- 旧角色和旧内容尽量保持可用。

### 15.2 必须警惕

- 数十年追加导致字段和数值不断膨胀；
- 新门派为了有吸引力持续增加特殊规则；
- 旧技能可能没有绝招或失去用途；
- 版本差异令攻略互相冲突；
- 规则说明和实际消耗不一致；
- 某些内容只有原作者或少数老玩家理解。

这验证了当前项目方向：内容包、稳定效果ID、幂等、存档版本、迁移函数和自动坏跳转检查必须从早期就存在。

## 16. 三份竞品参考的互补关系

| 作品 | 最值得借鉴的核心 | 对《大曜江湖》的主要贡献 |
| --- | --- | --- |
| 《逸剑风云决》 | 地点—人物—关系—请教—武学—新地点 | 人物和地点构成成长网络 |
| 《剑隐侠踪录》 | 外功、内功、轻功交叉；弱点与场景活性 | 武学组合、天气和战斗表现 |
| 《北大侠客行》 | 房间—动词语法；激发武学；门派制度；情节谜题 | 可扩展规则骨架、身份与传承条件 |

三者合并后的项目原则是：

```text
用北侠的规则语法搭骨架
用逸剑的人物与地点网络填内容
用剑隐的武学交叉和视觉反馈提高可读性
```

不能合并的是三者的内容规模：不做七十五个以上地点、数百门武学、五人阵、数十年MUD数值和多人生态。

比试：失败的后果是什么

杀死：谁会记住、产生什么仇恨

## 20. 落地优先级

### A级：下一轮内容即可采用

1. 把夜战中的杀死、制伏、逃离抽成通用“战斗意图”；
2. 为现有重要场景建立内部“动词＋对象”表；
3. 为武学区分已学会、当前根基和本次行动调用；
4. 在人物卡加入死亡地点、死因、见闻和回照记录；
5. 下一段原创或核对剧情至少制作一条完整情节秘密链；
6. 把已掌握的丹房日常和安全旅行折叠为快速结算。

### B级：简明战斗系统稳定后

1. 师承身份阶梯和权限面板；
2. 练功的师承、读书、实践和生死领悟差异；
3. 地点图和已掌握路线；
4. 武学身体副作用与医术处理；
5. 可折叠战报和死亡履历页。

### C级：长期再评估

1. 正式门派加入、退出和转投；
2. 多套武学根基切换；
3. 更大的区域图；
4. 年龄、职业和更长期身份；
5. 内容作者使用的可视化事件编辑器。

明确不进入计划：多人频道、玩家交易、比武排行、自由命令行、机器人、每日任务次数和真死掉技能。

## 21. 验收问题

后续设计若声称参考了《北大侠客行》，应能回答：

- 场景是否由稳定动作和对象组成，而不是每个按钮写一套孤立逻辑？
- 玩家能否从描述中理解为什么出现这些行动？
- 已知武学与当前使用方法是否被清楚区分？
- 一门武学是否有师承、地点、条件和副作用？
- 比试、制伏、逃离和杀死是否产生不同长期后果？
- 门派或师承是否同时提供权限和责任？
- 秘密任务是否把故事知识转化为物品、路线和行动条件？
- 死亡是否记录了具体原因并帮助下一次行动？
- 已经稳定掌握的重复流程是否可以快速结算？
- 原本依赖攻略的信息是否能在游戏内通过调查获得？
- 新内容是否复用稳定规则和效果ID？
- 删除多人和挂机后，这段内容是否仍然成立？

若其中三项答不上来，说明只模仿了MUD的文字表面，没有吸收其系统骨架。
