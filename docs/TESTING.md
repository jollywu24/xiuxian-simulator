# 自动化测试与浏览器回归

本文只负责测试入口、覆盖层级、浏览器回归结构和失败定位。系统规则写在`docs/systems/`，发布过程写在`docs/RELEASE.md`，调试状态接口写在`docs/DEBUGGING.md`。

## 1. 三层验证策略

### 1.1 日常迭代

先运行受影响范围的最小测试。混合修改或无法快速判断范围时运行：

```bash
npm run verify:quick
```

该命令执行关键语法、全量纯规则、内容和发布资源检查，但不启动三套长浏览器流程。界面改动再补一套直接相关的`smoke:*`或固定状态浏览器截图；同一代码与输入下已经通过的套件不重复运行。

### 1.2 可试玩检查点

一个页面、玩法纵切或连续剧情已经可以独立试玩时，运行`verify:quick`和所有受影响的浏览器套件。例如只修改出身流程时补`smoke:origins`，不必同时跑完整战斗。

### 1.3 正式发布

推送`main`、完成当前`/goal`或用户明确要求发布前，统一运行：

```bash
npm run verify
```

`scripts/run-quality-gate.mjs`按固定顺序执行：

1. 关键JavaScript文件语法检查；
2. 全量`node:test`规则、迁移和工程契约测试；
3. P0／P1内容目录、节点和跳转校验；
4. 本地发布资源与缓存版本契约；
5. 正篇、三出身和战斗三套自启动浏览器回归。

任一步失败都会立即停止，GitHub Pages不会开始部署。`.github/workflows/test-web.yml`与本地使用同一个`npm run verify`，不维护第二套CI专用命令。

## 2. 命令入口

| 命令 | 用途 |
| --- | --- |
| `npm run verify:quick` | 日常迭代的语法、规则、内容和资源检查，不启动浏览器 |
| `npm test` | 纯规则、状态、迁移、存档和工程契约 |
| `npm run validate:content` | 内容目录、坏跳转、重复ID和内容约束 |
| `npm run test:release` | 运行时资源、关键发布资源和缓存版本 |
| `npm run smoke` | 正篇完整流程 |
| `npm run smoke:origins` | 三出身选择、两条独立序章、汇流与个人事件 |
| `npm run smoke:combat` | 独立战斗与连续战役 |
| `npm run test:browser` | 连续执行全部本地浏览器回归 |
| `npm run verify` | 发布前完整质量门禁 |

局部开发不要求每次跑全量浏览器；正式发布前仍必须跑`npm run verify`。测试选择以改动后的风险为准，不以修改文件数量为准。

## 3. 自启动浏览器回归

`scripts/run-browser-regression.mjs`负责整个环境：

- 与`npm run serve`共用`static-web-server.mjs`，不依赖系统Python；
- 自动寻找Chrome或Edge，也可读取`CHROME_BIN`；
- 自动选择本地静态服务端口和DevTools端口；
- 自动建立独立临时浏览器目录；
- 启动无头浏览器并等待CDP就绪；
- 依次运行指定套件；
- 无论成功失败都关闭浏览器、服务和临时目录。

因此正式验收不要求开发者先运行`npm run serve`、手动打开浏览器或固定占用9225端口。手动执行`node scripts/cdp-*.mjs 9225`只用于临时诊断。

三套本地深回归分别由以下文件负责：

- `scripts/cdp-smoke.mjs`：正篇、存档迁移、恢复、人物／行囊／武学和多视口；
- `scripts/cdp-origins.mjs`：三出身选择、世家旁支／市井子弟序章、三档结果、沈家汇流和个人事件；
- `scripts/cdp-combat-lab.mjs`：战斗动作、敌方阶段、同伴、环境、伤势、死亡和连续战役。

`scripts/cdp-online-smoke.mjs`只在部署后运行最短真实页面流程，不代替本地深回归。

## 4. 必须覆盖的风险

浏览器回归至少持续覆盖：

- 1280×720与844×390可完成核心流程且无横向溢出；390×844只显示横置提示、隐藏正式交互，旋转后可以继续；
- 新旅程、人物建立、三个出身与破庙汇流可达；
- 一次明确死亡回照、一次非致命失败和一次失败推进；
- 固定因果骰不能靠读档刷新；
- 人物、行囊、武学打开、关闭、切换和确认操作；
- 旧存档迁移、主档损坏后的备份恢复和终章继续；
- 页面运行异常数组为空；
- 普通URL不存在调试对象，`?debug=1`接口协议可用。

涉及某个系统的更细验收仍由该系统文档负责；测试脚本只实现并证明这些验收。

## 5. 失败定位

- 语法失败：先看质量门禁输出的具体文件；
- 规则失败：按测试名回到对应纯规则模块，不在DOM层补偿；
- 内容校验失败：检查稳定ID、前后节点与重复奖励；
- 资源失败：运行`npm run test:release`查看缺失路径或缓存版本；
- 浏览器缺失：设置`CHROME_BIN`；
- 浏览器流程失败：单独运行对应`smoke:*`命令，再用`docs/DEBUGGING.md`中的状态接口定位；
- 线上失败：按`docs/RELEASE.md`区分构建号、HTTP资源和真实浏览器启动三层。

不得用规则测试替代真实浏览器布局检查，也不得声称未实际执行的测试已经通过。
