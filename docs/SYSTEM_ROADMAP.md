# 《大曜江湖》完整游戏系统路线图

## 1. 文档目标

本文回答三个问题：

1. 当前首章已经具备哪些可复用系统；
2. 把原著后续第三十至第一百二十七章做成完整单世界游戏，还缺哪些系统；
3. 这些系统应按什么依赖和里程碑制作。

剧情事实以 [《大曜江湖》完整剧情线参考](STORY_BIBLE.md) 为准，现有交互基线以 [《武道》高武江湖设计文档](GAME_DESIGN.md) 为准。本文负责生产顺序，不替代二者。

## 2. 完整游戏的完成定义

“完整游戏”指玩家可以从破庙醒来连续游玩到第一百二十七章对应的浩然四诗断点，并满足：

- 全程只发生在大曜武道世界；
- 不出现现实世界、论坛、其他玩家、玩家交易或上学情节；
- 原著中的双世界功能已经转写为江湖内部的修炼、交易、情报和期限；
- 每个核心篇章至少包含进入条件、可选目标、资源代价、失败结果、关系变化和能力兑现；
- 战斗、医治、炼丹、调查、潜入、交涉和旅行不是单纯换文案；
- 玩家可以安全退出、失败回照、错过事件，也可以承担风险追求更深结果；
- 新能力在一至两个场景内至少获得一次亲手使用机会；
- 存档可跨版本迁移，手机与桌面完整流程均可恢复；
- 内容数据、规则测试、浏览器流程和剧情文档保持一致。

## 3. 当前系统盘点

### 3.1 已经可复用

| 能力 | 当前实现 | 可复用程度 |
| --- | --- | --- |
| 世界入场与人物车卡 | 世界介绍、出身、初心、姓名、债务 | 高 |
| 五维与逆天改命 | 已有属性重分、有效属性判定 | 高 |
| 双灯照命 | 死亡、熄灯、回到指定节点 | 中 |
| 固定奇遇 | 条件展示、一次性领取、锁定时机 | 中 |
| 人物选择 | 龙青鱼与曹青的阶段选择和好感 | 中 |
| 日常行动 | 三时段、体力、饱腹、研习与休息 | 中 |
| 武学研习 | 潜能、进度、门槛和一次属性增长 | 中 |
| 简单关系 | 单一好感与关系称谓 | 低至中 |
| 简单炼丹 | 火候选择、失败重试、品质和产物 | 中 |
| 本地存档 | 单存档、版本3迁移与恢复 | 中 |
| 手机交互 | 响应式布局、数字键与事件委托 | 高 |

### 3.2 目前只有剧情特例

| 能力 | 当前限制 |
| --- | --- |
| 条件板 | 每个页面单独拼接，不能自动解释缺失条件和代价 |
| 事件状态 | 多用布尔字段，缺少未见、已知、进行中、失败、过期、已解决等统一状态 |
| 伤势与治疗 | 只有根骨扣减和死亡，没有部位、严重度、毒性、失血和恢复过程 |
| 战斗 | 预写选择直接结算，无法复用敌人意图、招式、距离和环境 |
| 物品 | 多为独立状态字段，没有统一目录、数量、品质、来源和用途 |
| NPC关系 | 主要是好感，不能表达信任、恐惧、债务、把柄和身份误认 |
| 时间与地图 | 只支持丹房一天和若干路线按钮，没有连续日历、旅行、窗口和区域状态 |
| 调查 | 线索写在旁白里，没有证据、推测、确证和错误结论 |
| 势力 | 沈家、漕帮等仅存在于文案，没有声望、警戒、权限和追捕 |
| 内容生产 | 场景、规则和状态写在大文件中，扩展九十八章会快速失控 |

### 3.3 完全缺失或不足以支撑后续

- 可复用的多回合文字战斗；
- 伤势、毒素、精神影响与治疗；
- 诊断病例、药材、丹方、毒方和品质链；
- 世界地图、旅行时间、宵禁、天气和限时窗口；
- 跟踪、反跟踪、潜入、证据和怀疑；
- 势力声望、通缉、身份权限和组织渗透；
- 多维人物关系与关系记忆；
- 数据驱动剧情、内容校验和分支自动巡检；
- 多存档、关键版本迁移和坏档保护；
- 覆盖核心分支的浏览器回归矩阵。

## 5. 优先级定义

| 优先级 | 定义 | 允许推迟的内容 |
| --- | --- | --- |
| P0 | 不完成就无法制作第三十至五十四章的前三个完整闭环 | 高级势力战、复杂组织渗透、重复玩法 |
| P1 | 不完成就无法制作第五十五至八十五章的独立生存与戒严金陵 | 后期心神体系、浩然文道 |
| P2 | 不完成就无法制作第八十六至一百二十七章的成熟武者阶段 | 大规模重玩优化和终局扩展 |
| P3 | 不阻塞主线，但决定完整度、重玩价值和长期维护成本 | 可在主线闭环后集中完善 |

优先级不是“先把P0系统做成最终形态”。每个系统先交付能够支撑当前篇章的纵切版本，再随剧情升级。

## 7. 剧情里程碑

### M0：系统骨架

交付SYS-01、SYS-08和SYS-07的最小版本，不增加新剧情。现有首章全流程必须继续可玩，版本3存档迁移成功。

### M1：三夫人病危（第三十至三十八章）

首次同时验证：诊断、药材、紫龙换血丹、关系债务、救治失败、春风化雨针，以及新能力的救人／杀人双用法。

### M2：第一次杀人与拜师选桩（第三十九至四十八章）

首次验证：多回合战斗、部位伤势、敌人意图、第一次杀人、正式拜师、桩功二选一和锻体突破。

### M3：八月十五灵猴遗迹（第四十九至五十四章）

首次验证：连续日历、限时旅行、返回旧地图、灵猴关系、猴儿酒分配和隐藏区域。

### M4：曹青离场与沈福反目（第五十五至六十八章）

首次验证：联系人离场、经济渠道、追踪逃亡、NPC长期转变、杀与不杀，以及关系断裂后的永久世界变化。

### M5：戒严金陵与王卓战（第六十九至八十五章）

首次验证：城池状态、官面身份、医治燕惊鸿、跟踪反跟踪、东湖伏击和心法晋升。

### M6：金刚、七杀与毒蛇帮（第八十六至一百零八章）

首次验证：名声、榜单、打虎、多桩功、帮会清剿、毒经和机制接管。

### M7：归墟与浩然四诗（第一百零九至一百二十七章）

首次验证：卧底身份、心神控制、奇遇融合、官面政治和文道考验。

### M8：完整游戏收束

补齐主要错过、失败和安全退出路线；完成存档、手机、性能、文本与发布检查。

## 8. 推荐实际施工顺序

```text
事件数据契约
  → 内容校验器
  → 存档版本4
  → 物品与状态效果
  → 关系与秘密
  → 医治和炼丹
  → 战斗与伤势
  → 武学与突破
  → 时间与地图
  → 三夫人完整闭环
  → 第一次杀人与拜师
  → 灵猴遗迹
  → P1城市和调查系统
  → P2组织与心神系统
```

不要先制作庞大的开放世界、随机生成江湖或完整经济模拟。下一阶段的唯一验证目标是让“三夫人病危”成为比首炉炼丹更深、但仍可完整测试的一条闭环。

## 9. 跨系统数据边界

| 数据 | 唯一事实来源 | 其他系统如何使用 |
| --- | --- | --- |
| 当前场景与事件阶段 | SYS-01 | UI读取，不自行改写 |
| 属性、境界、武学进度 | SYS-02 | 战斗、医术只请求有效值 |
| 生命、伤势、毒和战斗状态 | SYS-03 | 医术通过公开效果治疗 |
| 物品、配方、银钱和品质 | SYS-04 | 事件通过统一效果增减 |
| NPC关系、秘密、势力警戒 | SYS-05 | 条件板只读取判断结果 |
| 日期、地点、天气和证据 | SYS-06 | 事件通过统一旅行与调查接口改变 |
| 存档版本、显示偏好和测试状态 | SYS-07 | 业务规则不得依赖视觉布局 |
| 内容清单、引用和校验结果 | SYS-08 | 不进入玩家存档 |

## 10. 每个系统的共同完成标准

- 核心规则位于无DOM、无网络、JSON可序列化的纯模块；
- 同一奖励不能因刷新、回照或重复点击领取两次；
- 条件失败会说明世界内原因，不显示内部字段或开发术语；
- 关键状态由`createInitialState()`提供默认值并有迁移策略；
- 至少包含正常、失败、错过、重复进入和旧存档五类测试；
- 新增场景同步渲染、交互、视觉模式、存档、测试和文档；
- 390×844无横向溢出，数字键和原生焦点仍可用；
- 玩家可见动态文本经过`escapeHtml()`；
- 不引入现实、其他玩家和旧版修仙剧情；
- 通过规则测试和对应浏览器流程后才能进入下一里程碑。
