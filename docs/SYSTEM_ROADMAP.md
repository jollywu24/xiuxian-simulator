# 《大曜江湖》完整游戏系统路线图

## 1. 文档目标

本文回答三个问题：

1. 当前首章已经具备哪些可复用系统；
2. 把原著后续第三十至第一百二十七章做成完整单世界游戏，还缺哪些系统；
3. 这些系统应按什么依赖和里程碑制作。

剧情事实以 [《大曜江湖》完整剧情线参考](STORY_BIBLE.md) 为准，现有交互基线以 [《武道》高武江湖设计文档](GAME_DESIGN.md) 为准，战斗参考取舍以 [《武道》战斗系统参考与转化](COMBAT_DESIGN_REFERENCE.md) 为准。本文负责生产顺序，不替代这些文档。

路线图同时吸收《博德之门3》《逸剑风云决》《剑隐侠踪录》《北大侠客行》《烟雨江湖》《大侠立志传》《活侠传》等现有参考拆解的共同结论。参考作品只用于确认“局面、多解、人物权限、能力兑现、失败推进、地点回流和人生回响”等设计原则，不把其地图规模、武学数量、队伍规模、随机系统或长线运营结构直接加入本项目。

## 2. 完整游戏的完成定义

“完整游戏”指玩家可以从破庙醒来连续游玩到第一百二十七章对应的浩然四诗断点，并满足：

- 全程只发生在大曜武道世界；
- 不出现现实世界、论坛、其他玩家、玩家交易或上学情节；
- 原著中的双世界功能已经转写为江湖内部的修炼、交易、情报和期限；
- 每个核心篇章至少包含进入条件、可选目标、资源代价、失败结果、关系变化和能力兑现；
- 战斗、医治、炼丹、调查、潜入、交涉和旅行不是单纯换文案；
- 玩家可以安全退出、失败回照、错过事件，也可以承担风险追求更深结果；
- 新能力在一至两个场景内至少获得一次亲手使用机会；
- 每个核心篇章以一个可理解的“江湖局面”组织，而不是按系统清单或纯文本章节堆叠；
- 玩家先决定行动意图，固定因果骰只决定完成质量与意外代价，不替玩家决定立场、感情或已知事实下的常识；
- 人物关系至少改变一项实际权限、责任、风险或危机行为，不只改变好感文案；
- 带价成功、失败推进、安全错过和死亡是不同结果，失败后世界仍然继续；
- 章节收势能依据真实状态生成可追溯的“江湖留痕”，说明玩家如何成为现在这个人；
- 存档可跨版本迁移，手机与桌面完整流程均可恢复；
- 内容数据、规则测试、浏览器流程和剧情文档保持一致。

### 3.3 完全缺失或不足以支撑后续

- 人物权限、组织身份阶梯、NPC见证行为和联系人生命周期；
- 不义之财的来源、知情者、归属、暴露风险与渠道替换；
- 完整分段跟踪、反跟踪、潜入、错误结论和跨篇章证据流转；
- 地点持久变化、有限势力警戒、通缉和身份权限；
- 跨篇章关系记忆、秘密传播、联系人替换与关键人物离场后的继续路线；
- 行为痕迹、人物回声和章末江湖留痕；
- 条件化语言／情报行动，用秘密、关系和立场改变敌人意图或谈判条件；
- 毒方、复合配方与长期治疗，但只随对应剧情纵切扩展；
- 更广的分支自动巡检和旧章内容数据迁移；
- 多存档、关键版本迁移和坏档保护；
- 覆盖核心分支的浏览器回归矩阵。
- 玩家首次聚气时的主内功、真气恢复、常式／催动和三种用途纵切。
- 战场场景覆盖层、节点选择、路径与敌招预览、视线遮挡和横竖屏交互纵切。

以下内容不再作为P1前置：每日随机物价、通用动态天气、全NPC日程、抽象人格数值条、完整势力模拟，以及超出SYS-09边界的复杂战斗公式。装备纵切已经交付，不再阻塞M5正文生产；后续仍不扩展随机词缀、强化、套装与耐久。

### 3.4 参考拆解后的统一修订原则

| 统一原则 | 路线图处理 |
| --- | --- |
| 用局面而非任务链组织内容 | 每个篇章先写稳定事实、人物欲望、解法矩阵、失败推进和共同回流点 |
| 关系等于权限、责任与危机行为 | 好感之外记录人物愿意透露、传授、引见、包庇或牺牲什么 |
| 身份是离散的社会位置 | 先做沈家身份阶梯，每次变化同时改变地点、行动、态度和风险，不做经验条 |
| 能力必须跨系统兑现 | 每门武学至少有战斗、调查／旅行或人物事件中的两类用途，并在两幕内首次使用 |
| 玩家决定意图，随机决定质量 | 保留固定因果骰和四档结果，禁止随机替玩家决定立场或通过读档刷新 |
| 失败也是内容 | 普通失败继续局面；带价成功保留代价；错过、撤离和死亡分别结算 |
| 世界只模拟能形成选择的部分 | 时间、天气、路线、价格和日程只有能改变按钮、代价或关闭风险时才出现 |
| 日常服务人物与机会成本 | 不增加更多日常按钮；为现有行动补行为痕迹、人物回声和快结算 |
| 分支密度受控 | 每个事件最多三种核心变体，其余状态用短回声承认，避免条件组合爆炸 |
| 系统反馈属于叙事 | 右侧叙事栏解释发生了什么、为何变化、会改变什么；章末生成可追溯江湖留痕 |

## 5. 优先级定义

| 优先级 | 定义 | 允许推迟的内容 |
| --- | --- | --- |
| P0 | 不完成就无法制作第三十至五十四章的前三个完整闭环 | 高级势力战、复杂组织渗透、重复玩法 |
| P1 | 不完成就无法制作第五十五至八十五章的独立生存与戒严金陵 | 后期心神体系、浩然文道 |
| P2 | 不完成就无法制作第八十六至一百二十七章的成熟武者阶段 | 大规模重玩优化和终局扩展 |
| P3 | 不阻塞主线，但决定完整度、重玩价值和长期维护成本 | 可在主线闭环后集中完善 |

优先级不是“先把P0系统做成最终形态”。每个系统先交付能够支撑当前篇章的纵切版本，再随剧情升级。

### 6.2 P1：独立生存与城市博弈

P1不再按“先把经济、势力、日程等系统分别做完”推进，而分成两个连续局面：先用M4在沈家小范围验证独立生存和永久关系后果，再用M5把已经跑通的权限、警戒和渠道扩展到戒严金陵。

#### 6.2.1 已完成的跨篇章基础

## 10. 每个系统的共同完成标准

- 核心规则位于无DOM、无网络、JSON可序列化的纯模块；
- 每个篇章先定义一个玩家十秒内能理解的局面，并提供稳定事实、人物欲望、解法矩阵和共同回流点；
- 玩家先决定行动意图，随机只决定完成质量和意外代价；
- 每个核心局面至少有三条过程，其中至少两条不以正面战斗为中心；
- 带价成功、失败推进、安全错过和死亡分别存在，普通失败不能只导向读档；
- NPC只根据亲见、被告知或可靠传播的行为反应；高好感不能覆盖人物底线；
- 关系或身份变化至少改变一项地点、行动、门路、责任或风险；
- 新武学、技艺或身份在一至两个场景内首次兑现，并至少拥有一个跨系统用途；
- 分支汇合后仍保留伤势、债务、关系、证据、身份和地点状态，不用一句共同文案抹平；
- 每个篇章最多三种核心内容变体，其余状态通过短回声承认；
- 已稳定掌握且无新判断的日常和安全旅行允许快结算；
- 章末江湖留痕中的每句话都能追溯到真实状态，不泄露未见内容；
- 同一奖励不能因刷新、回照或重复点击领取两次；
- 条件失败会说明世界内原因，不显示内部字段或开发术语；
- 关键状态由`createInitialState()`提供默认值并有迁移策略；
- 至少包含正常、失败、错过、重复进入和旧存档五类测试；
- 新增场景同步渲染、交互、视觉模式、存档、测试和文档；
- 390×844无横向溢出，数字键和原生焦点仍可用；
- 玩家可见动态文本经过`escapeHtml()`；
- 不引入现实、其他玩家和旧版修仙剧情；
- 通过规则测试和对应浏览器流程后才能进入下一里程碑。
