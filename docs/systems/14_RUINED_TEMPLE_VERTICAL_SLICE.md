# 雨夜破庙垂直切片

本文定义第一场雨夜破庙的现行玩法、状态契约和后续施工顺序。当前网页已经完成P0垂直切片：三块微区域、十二个可交互对象、对象二次利用、八刻局面时间、乌沉药匣、伤者处置、三出身信息差、龙青鱼行为反馈、追兵多解法、见闻更新和离场持久化已经组成一条可玩闭环。

## 1. 目标体验

玩家第一次进入破庙，应当亲手完成以下循环：

> 进入场景 → 自由观察和移动 → 选择值得花时间的行动 → 找到药匣或伤者 → 雨势与来人自动推进 → 龙青鱼读取此前行为 → 旧对象变成破局手段 → 人、物、关系、伤势和见闻带出破庙。

这一切不使用连续三选一，也不要求玩家清空全部热点。玩家可以看见所有对象，但不可能在来人前把所有深度行动做完。

## 2. 成熟方案与采用边界

本纵切采用仓库已有参考中已经验证的最小结构：

- 参考《博德之门3》的手工局面：有限地点内放置有明确状态和后续用途的环境对象，不建设通用开放世界模拟；
- 参考《极乐迪斯科》的空间／叙事分工：左侧负责地点、对象与当前所见，右侧负责已经发生的叙事记录和局面推进；
- 采用跑团场景的主持逻辑：观察不消耗稀缺时间，承诺一次深入行动才推进局面；主持人按时钟引入新压力，而不是等待玩家点“继续”。

明确不采用：

- 实时倒计时；它会惩罚阅读速度，不适合文字核心玩法；
- 精确奇遇条件、完成率和全对象清单奖励；它们会把探索变成清单劳动；
- 自由移动角色与碰撞导航；当前只需要三个有意义的区域切换；
- 为破庙另建通用天气、全NPC日程或第二套战斗公式；
- 复制任何参考作品的专有数值、台词或剧情。

本阶段没有引入第三方运行时或新美术许可。三个区域暂时复用现有破庙场景图，只过滤对应热点，属于可交互白盒；以后制作区域美术时必须保持对象ID和场景坐标契约不变。

## 3. 当前场景结构

| 区域 | 对象 | 第一用途 | 可继续利用 |
| --- | --- | --- | --- |
| 庙前 | 雨中庙门、门阶泥印、漏风破窗、半塌侧墙 | 听来路、辨抬货痕、查风口、看退路 | 顶住破窗、清出荒坡退路 |
| 大殿 | 将熄余火、无像供桌、供桌下香架、断首残像 | 救火、查山桃、辨绳结、看旧货签 | 压暗余火、拆松香架 |
| 庙后 | 贴墙湿柴、新砌暗墙、石阶旧血、梁下抓痕 | 找藏物处、发现药匣、找到脚夫、察异常 | 做柴堆夹层、查匣／取匣／拆封、处置伤者 |

当前恰好十二个对象，每个区域四个。对象的“已发现”和“已行动”分开保存：点热点只是看见；在“所见”卡里选择动作才改变对象和局面。

## 4. 局面时间

破庙使用八刻局面时钟，不对应通用日历分钟：

- 区域切换：不耗时；
- 打开热点、阅读“所见”：不耗时；
- 一般行动：一刻；
- 深入、搬动或拆解：两刻；
- 第四刻：雨势转急；
- 第七刻：门外出现脚步；
- 第八刻：龙青鱼入庙，未获救的脚夫死亡，场景自动推进；随后追兵逼近。

时钟只在玩家确认行动后推进。达到阈值时，阶段旁白自动写入右侧叙事卷轴；达到第八刻后不再要求玩家点击“等待来人”。龙青鱼先根据现场给出反馈，玩家只需表明当前态度，追兵危机随即接续。

## 5. 状态契约

纯规则位于`web/temple-exploration.mjs`，不得访问DOM、存储或网络。核心状态为：

```js
{
  areaId: "hall",
  elapsed: 0,
  phase: "quiet",
  seenObjectIds: [],
  objectStates: {},
  originClueIds: [],
  casket: { discovered: false, inspected: false, opened: false, holder: "wall", lost: false },
  porter: { discovered: false, alive: null, rescued: false, questioned: false, searched: false, aidSpent: false },
  lady: { arrived: false, trust: 0, suspicion: 0, debt: 0, observations: [] },
  crisis: { active: false, resolved: false, method: null, pursuers: "unseen", playerWound: null },
  completed: false
}
```

约束：

- 对象、动作和阶段使用稳定ID；
- 同一动作只能结算一次，重复点击不得重复推进时间或奖励；
- 对象状态必须是JSON可序列化值；
- 规则返回叙事结果和阶段事件，界面只负责渲染；
- 存档版本13补齐药匣、脚夫、龙青鱼和追兵状态。版本2至12会补齐安全默认状态；旧火堆、暗墙、旧药匣与东郊脚夫结果会尽量映射，旧青衣妇人对话中的存档会汇入新的来客场景；已经离开破庙的旧档不倒退。

## 6. 药匣、脚夫与三出身

暗墙探到第二层后出现乌沉药匣。药匣保存“是否发现、是否细查、是否拆封、由谁持有、是否遗失”五项事实，原样拿走、查后拿走与拆开带走会分别改变出身差事和后续交付。

石阶旧血会引出受伤脚夫。玩家可分别执行救治、问话、搜货与放弃：救治耗两刻并撕掉一块御寒内衬；未先救治不能稳定问话；搜货可独立进行；到时仍未获救或明确放弃，脚夫死亡。

三种出身在门阶泥印、新砌暗墙、断首残像与药匣上各有不同认知。它们写入稳定见闻，不只替换一句对白：

- 世家旁支辨认药房步法、封匣细麻、旧式黄蜡与账房折角；
- 市井子弟辨认脚夫换肩、秦淮交割结、外港桐油和换手货签；
- 身世成谜由玉佩、旧步法、火印和残缺名册触发零碎记忆。

## 7. 龙青鱼与追兵危机

龙青鱼不会从固定好感开始。她入庙时读取玩家是否救人、是否拆封、药匣在哪里，以及余火、香架、塌墙、柴堆和破窗的状态，分别形成信任、戒心和人情。三者承担不同用途，不能互相折算成一根数值条。

追兵危机有四条现行收束：

| 方法 | 条件 | 主要结果 |
| --- | --- | --- |
| 暗火倒架 | 余火已压暗、香架已拆松 | 困住先入者，追兵退入雨中，无必然伤势 |
| 塌墙撤离 | 侧墙退路已清开 | 人可撤走；药匣若仍留在暗墙则会失去 |
| 柴堆藏匣 | 柴堆已留空腔、药匣已发现 | 药匣留在破庙，追者循假痕离开 |
| 守门迎敌 | 始终可用 | 读取力道与根骨，胜后留下轻伤或中伤 |

P0不在这里复制完整战斗引擎。守门只完成一次有属性后果的短冲突；完整六节点战场与武学轮转仍属于后续战斗场景。

## 8. 界面规则

- 三个区域入口固定放在场景左上，显示当前位置，不伪装成右侧剧情选项；
- 局面时钟固定放在场景右上，同时显示阶段和剩余刻数；
- 热点与原图物件对齐，点击空白处关闭“所见”；
- “所见”卡展示对象描述、当前状态和一至两个可执行动作；
- 动作结算写入右侧叙事信息流，旧记录自然上推；
- 到时自动推进时，右侧必须出现可读的阶段变化，不能只改变内部字段；
- 桌面与手机横屏均保持左场景、右叙事的2:1结构；竖屏只保留横置提示。

## 9. 见闻与离场持久化

破庙当前可更新五组有用见闻：乌沉药匣、破庙山桃、受伤脚夫、紫金河夜船、破庙追兵，以及龙青鱼本人。见闻只收录玩家亲见、问到或进一步印证的片段，不显示总量与完成率。

危机落定后，离场页立即展示药匣归属、脚夫生死、追兵去向、龙青鱼态度、衣料代价与伤势。随后进入心法与紫金河路线时，这些状态仍在主存档中；伤势进入`p0.wounds`，药匣进入或离开行囊，脚夫结果同步到见闻，龙青鱼关系继续开放后续人物权限。

## 10. 已撤销的旧门槛

以下内容不再属于现行破庙流程：

- 必须依次点完火堆、随身物和山桃才看见暗墙；
- 敲墙一千次；
- 临时洗属性才能处理墙体；
- 显示精确奇遇条件或完成率；
- 点击按钮等待青衣妇人出现；
- 把普通选错直接结算为死亡。

旧函数和旧文本若仍为迁移或后续章节所需，可以暂留代码，但不得从新旅程可达。

## 11. 当前验收与测试

当前第一阶段必须满足：

- 三个区域可自由切换，共十二个对象；
- 观察和移动不耗时，确认动作才耗时；
- 至少余火、破窗、塌墙、香架、柴堆和暗墙存在连续状态；
- 八刻内不可能完成所有对象动作；
- 雨急、脚步、来人按固定阈值自动触发；
- 桌面和手机横屏能切区、看物、行动、关卡片并进入后续场景；
- 药匣、脚夫和三出身信息差可由纯规则独立验证；
- 龙青鱼反馈读取既有行为，追兵至少有两条不同解法可达；
- 离场后药匣、人物、伤势、资源和见闻仍保留；
- 版本2至12旧档可迁移，已离开破庙的旧档不倒退。

规则测试：`tests/temple-exploration.test.mjs`。

浏览器回归：`scripts/cdp-smoke.mjs`与`scripts/cdp-origins.mjs`。

## 12. 后续施工顺序

1. P1环境资源：让山桃、干柴、水与简单药物成为可携带并可在后续使用的场景资源；
2. P1奇遇征兆：只展示山桃与梁下抓痕的异常，不提前显示完整条件；
3. P1出身物互动：腰牌、牙牌、玉佩在破庙中各产生一次额外用途；
4. P1离场路线：继续加强鱼跃龙门诀、脚夫证言与药匣状态在紫金河和沈家入口的差异；
5. P2区域专用美术、完整战斗、完整奇遇和更大世界系统。

下一阶段不得先用长对白掩盖对象和时间玩法。新增资源、奇遇和路线必须继续读取本阶段已经建立的对象状态、人物结果和局面时间。
