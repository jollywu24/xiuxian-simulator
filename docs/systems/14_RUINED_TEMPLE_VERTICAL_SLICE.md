# 雨夜破庙垂直切片

本文定义第一场雨夜破庙的现行玩法、状态契约和后续施工顺序。当前网页已经完成第一阶段：三块微区域、十二个可交互对象、对象状态与二次利用、局面时间和自动推进。乌沉药匣完整事件、脚夫局面、龙青鱼行为反馈、追兵多解法、见闻闭环与离场回响仍按后续阶段制作，不能描述为已经完成。

## 1. 目标体验

玩家第一次进入破庙，应当亲手完成以下循环：

> 进入场景 → 自由观察和移动 → 选择值得花时间的行动 → 对象状态发生变化 → 雨势与来人自动推进 → 此前动过的对象获得第二种用途。

这一切不使用连续三选一，也不要求玩家清空全部热点。玩家可以看见所有对象，但不可能在来人前把所有深度行动做完。

## 2. 成熟方案与采用边界

本纵切采用仓库已有参考中已经验证的最小结构：

- 参考《博德之门3》的手工局面：有限地点内放置有明确状态和后续用途的环境对象，不建设通用开放世界模拟；
- 参考《极乐迪斯科》的空间／叙事分工：左侧负责地点、对象与当前所见，右侧负责已经发生的叙事记录和局面推进；
- 采用跑团场景的主持逻辑：观察不消耗稀缺时间，承诺一次深入行动才推进局面；主持人按时钟引入新压力，而不是等待玩家点“继续”。

明确不采用：

- 实时倒计时；它会惩罚阅读速度，不适合文字核心玩法；
- 精确奇遇条件、完成率和全对象清单奖励；它们会把探索变成清单劳动；
- 自由移动角色与碰撞导航；当前只需要三个有意义的区域切换；
- 为破庙另建通用天气、全NPC日程或第二套战斗公式；
- 复制任何参考作品的专有数值、台词或剧情。

本阶段没有引入第三方运行时或新美术许可。三个区域暂时复用现有破庙场景图，只过滤对应热点，属于可交互白盒；以后制作区域美术时必须保持对象ID和场景坐标契约不变。

## 3. 当前场景结构

| 区域 | 对象 | 第一用途 | 可继续利用 |
| --- | --- | --- | --- |
| 庙前 | 漏雨山门、泥地车辙、接雨陶缸、塌墙缺口 | 看来路、辨车痕、验雨水、查退路 | 清开塌墙，准备离场通道 |
| 大殿 | 将熄余火、破窗、无像神台、供桌下的香架 | 救火、听风、查供奉、看灰尘 | 压低火光、撑住破窗、拆松香架 |
| 庙后 | 湿柴堆、新砌暗墙、梁上抓痕、石阶旧血 | 找干柴、辨新灰、察异常、查伤者痕迹 | 做藏物空腔、探明暗墙范围 |

当前恰好十二个对象，每个区域四个。对象的“已发现”和“已行动”分开保存：点热点只是看见；在“所见”卡里选择动作才改变对象和局面。

## 4. 局面时间

破庙使用八刻局面时钟，不对应通用日历分钟：

- 区域切换：不耗时；
- 打开热点、阅读“所见”：不耗时；
- 一般行动：一刻；
- 深入、搬动或拆解：两刻；
- 第四刻：雨势转急；
- 第七刻：门外出现脚步；
- 第八刻：来人入庙，场景自动推进。

时钟只在玩家确认行动后推进。达到阈值时，阶段旁白自动写入右侧叙事卷轴；达到第八刻后不再要求玩家点击“等待来人”。当前第一阶段只自动引入青衣来客，追兵压力将在“追兵危机与多解法”阶段接入。

## 5. 状态契约

纯规则位于`web/temple-exploration.mjs`，不得访问DOM、存储或网络。核心状态为：

```js
{
  areaId: "hall",
  elapsed: 0,
  phase: "quiet",
  seenObjectIds: [],
  objectStates: {},
  triggeredPhaseIds: [],
  completedActionIds: [],
  arrived: false
}
```

约束：

- 对象、动作和阶段使用稳定ID；
- 同一动作只能结算一次，重复点击不得重复推进时间或奖励；
- 对象状态必须是JSON可序列化值；
- 规则返回叙事结果和阶段事件，界面只负责渲染；
- 存档版本12新增`templeExploration`。版本2至11会补齐安全默认状态；旧火堆与暗墙结果尽量映射，但不会把玩家送回已经撤销的三行动门槛；已经离开破庙的旧档不倒退。

## 6. 界面规则

- 三个区域入口固定放在场景左上，显示当前位置，不伪装成右侧剧情选项；
- 局面时钟固定放在场景右上，同时显示阶段和剩余刻数；
- 热点与原图物件对齐，点击空白处关闭“所见”；
- “所见”卡展示对象描述、当前状态和一至两个可执行动作；
- 动作结算写入右侧叙事信息流，旧记录自然上推；
- 到时自动推进时，右侧必须出现可读的阶段变化，不能只改变内部字段；
- 桌面与手机横屏均保持左场景、右叙事的2:1结构；竖屏只保留横置提示。

## 7. 已撤销的旧门槛

以下内容不再属于现行破庙流程：

- 必须依次点完火堆、随身物和山桃才看见暗墙；
- 敲墙一千次；
- 临时洗属性才能处理墙体；
- 显示精确奇遇条件或完成率；
- 点击按钮等待青衣妇人出现；
- 把普通选错直接结算为死亡。

旧函数和旧文本若仍为迁移或后续章节所需，可以暂留代码，但不得从新旅程可达。

## 8. 当前验收与测试

当前第一阶段必须满足：

- 三个区域可自由切换，共十二个对象；
- 观察和移动不耗时，确认动作才耗时；
- 至少余火、破窗、塌墙、香架、柴堆和暗墙存在连续状态；
- 八刻内不可能完成所有对象动作；
- 雨急、脚步、来人按固定阈值自动触发；
- 桌面和手机横屏能切区、看物、行动、关卡片并进入后续场景；
- 版本11旧档可迁移，已离开破庙的旧档不倒退。

规则测试：`tests/temple-exploration.test.mjs`。

浏览器回归：`scripts/cdp-smoke.mjs`与`scripts/cdp-origins.mjs`。

## 9. 后续施工顺序

1. P0-4 乌沉药匣：原样拿走、细查、拆封及完整／检查过／已拆／遗失状态；
2. P0-5 三出身信息差：每种出身至少三处不同信息或行动；
3. P0-6 脚夫局面：救、问、搜、放弃及真实资源／时间代价；
4. P0-7 龙青鱼反馈：信任、戒心、人情和对玩家此前行为的见证；
5. P0-8 追兵危机：战斗、逃跑／藏匣、环境利用至少两条明显不同解法；
6. P0-9 见闻闭环：三至五条可更新的有效见闻；
7. P0-10 离场持久化：药匣、脚夫、人物态度、伤势、资源和见闻在下一场立即回响；
8. P1 环境资源、奇遇征兆、心法与离场路线兑现；
9. P2 区域专用美术、完整战斗、完整奇遇和更大世界系统。

下一阶段不得先用长对白掩盖对象和时间玩法。药匣、脚夫与龙青鱼都必须读取本阶段已经建立的对象状态和局面时间。
