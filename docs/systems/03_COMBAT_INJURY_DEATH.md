# SYS-03 战斗、伤势与死亡系统

## 1. 设计结论

战斗不是脱离剧情的数值小游戏，而是一场可以被读懂、利用和改写的高风险事件。

玩家每回合面对的核心问题不是“用哪招伤害最高”，而是：

> **敌人下一步想做什么，我能否用武学、位置、环境和关系把他的杀招变成自己的机会？**

完整战斗循环为：

> **读势 → 定策 → 出手 → 对招 → 留伤 → 改势 → 达成目的或付出代价离场。**

系统必须支持五种同等有效的解法：

1. 击杀敌人；
2. 制伏、逼退或俘虏敌人；
3. 保护目标并拖到援手到来；
4. 带着情报、同伴或物品撤离；
5. 夺取敌人的武器、位置、暗号或机关，反过来接管战局。

第一阶段不采用棋盘、复杂命中率或长血条。战斗深度主要来自敌人意图、距离、攻守之势、破绽、部位伤势和场景条件。

---

## 2. 当前可玩基础

现有流程已经实现一段可以作为规则基准的春风针夜战，以及一段灵猴冲突：

- 敌人的持刀逼近和后续动作可以提前观察；
- 玩家可通过灭灯、观察、出针等方式改变交锋条件；
- 同一场战斗包含两轮以上的局势变化；
- 结果包括封穴制伏、致命出针、负伤撤离和死亡；
- 伤势记录部位、严重度与效果标签，并进入后续医治；
- 死亡会熄灭命灯，保留死因记忆并返回最近因果节点；
- 灵猴冲突允许玩家用不同筹码换取不同的脱身路径。

这些内容证明了“可读意图 + 条件行动 + 长期后果”能够成立，但尚未抽成通用规则。当前缺口是：

- 战斗数据仍与具体剧情绑定；
- 没有统一的距离、攻守之势和破绽模型；
- 伤势尚未完整影响招式、移动和旅行；
- 缺少同伴、多人敌手、毒物、追逐与连续战斗；
- 缺少首领阶段转换和战场机关；
- 缺少供后续内容复用的战斗视图与结算接口。

下一步应先在不改变现有夜战结果的前提下抽出通用规则，再用王卓两阶段战验证同伴、首领和水边环境。

## 3. 战斗的三层目标

每场战斗必须同时声明三层目标，避免所有遭遇都退化为清空敌人。

### 3.1 眼前目的

玩家进入战斗时明确知道的任务，例如：

- 活过三轮；
- 护住燕惊鸿；
- 夺回账册；
- 阻止敌人敲响铜锣；
- 在官差赶到前离开；
- 逼问出接头地点。

### 3.2 可选成果

玩家通过额外观察或承担风险才能取得：

- 看清敌人武学来路；
- 夺走暗器、令牌或船钥；
- 留下活口；
- 不杀人完成脱身；
- 让某位同伴亲眼看到真相；
- 借敌人的招式毁掉机关。

### 3.3 失败底线

战斗失败不等于死亡。每场遭遇需提前定义可能的底线：

- 带伤逃离；
- 丢失物品；
- 同伴受伤或关系下降；
- 被俘并进入新场景；
- 敌人完成部分目的；
- 真正死亡并触发命灯。

只有满足明确致死条件时才进入死亡结算。

## 4. 核心战斗状态

建议通用战斗状态保持 JSON 可序列化：

```js
{
  battleId: "wang-zhuo-riverside",
  round: 1,
  phase: "tailing",
  objective: {
    primary: "protect-yan-and-leave",
    optional: ["identify-style", "capture-wang"],
    failed: []
  },
  position: {
    range: "near",
    footing: "stable",
    cover: "willow-shadow",
    exits: ["alley", "river"],
    controlledBy: null
  },
  momentum: 0,
  participants: [],
  intents: [],
  openings: [],
  terrain: [],
  statuses: [],
  knownFacts: [],
  roundLog: [],
  outcome: null
}
```

关键字段说明：

| 字段 | 作用 |
| --- | --- |
| `phase` | 当前首领阶段或剧情阶段，决定意图、环境和结束条件 |
| `position` | 不使用格子地图，以距离、落脚、掩体、出口和控制权描述空间 |
| `momentum` | 攻守之势，范围 `-2` 至 `2`，不作为可囤积的法力 |
| `intents` | 玩家本轮已经看见或推测出的敌方行动 |
| `openings` | 有时限的破绽、机会和可利用条件 |
| `knownFacts` | 已经看破的招式、习惯、毒性与场景规则，死亡回照后可保留 |
| `outcome` | 击杀、制伏、逼退、撤离、被俘、目的达成或死亡等结局 |

## 5. 一回合如何进行

每回合固定分为六步，界面不必逐步弹窗，但规则结算顺序必须稳定。

### 5.1 敌人露势

敌人根据性格、武学、伤势和当前目的生成意图。玩家至少能看到最危险的一项表面动作。

示例：

> 王卓右肩微沉，刀锋却贴在腿侧。他在等你护住上路，再从袖中打出第二件东西。

### 5.2 玩家读势

系统根据观察、悟性、已知情报、武学和环境显示不同深度的信息：

- 只看见动作；
- 判断攻击范围和目标；
- 看穿佯攻；
- 发现后手；
- 找到可以反用的破绽。

已看破的事实进入 `knownFacts`。对同一招再次交锋时，不要求玩家重复花一回合观察。

### 5.3 玩家定策

玩家从当前可用行动中选择一项主要行动；部分低承诺动作可作为附带动作。每个按钮必须显示：

- 想达到什么；
- 需要什么条件；
- 会消耗什么；
- 最主要的风险；
- 可能改变哪项局势。

### 5.4 同时对招

敌我行动按“先手条件 → 距离 → 克制关系 → 攻守之势 → 伤势限制”统一结算，而不是简单轮流扣血。

### 5.5 留下后果

依次处理：

1. 位置和出口变化；
2. 攻守之势变化；
3. 破绽生成或消失；
4. 伤势、失血、毒性和心神状态；
5. 物品、同伴、环境和任务变化。

### 5.6 判断结束

先检查目的是否达成，再检查撤离、制伏、被俘和死亡。若战斗继续，则生成下一轮意图。

## 6. 空间：不用棋盘也要有位置

### 6.1 距离

距离只设四档：

| 距离 | 典型行为 |
| --- | --- |
| 贴身 | 擒拿、短刃、封穴；长兵器难以展开 |
| 近距 | 刀剑、拳掌、短距离挪步 |
| 中距 | 钢针、长杆、飞石、冲刺 |
| 远距 | 弓弩、追逐、撤退和寻找掩体 |

招式不直接写“射程 2”，而写允许距离和改变距离的结果。

### 6.2 落脚

`footing` 表示当前能否稳定发力：

- 稳固：可以完整运劲；
- 受限：泥地、狭巷、船舱、拥挤人群；
- 失衡：被逼到水边、踩空、被勾住兵器；
- 倒地：只能使用少量应急行动。

海桩等武学可以把水边“受限”转为“稳固”，这比单纯增加伤害更能体现武学特色。

### 6.3 掩体、出口与控制权

场景至少提供一种可利用环境和一个出口：

- 灯火可以被扑灭；
- 桌案可以阻挡直线暗器；
- 柳树可以隐藏同伴；
- 船索可以绊人或放船；
- 狭门一次只能通过一人；
- 铜锣若被敌人控制，会召来援兵。

控制关键位置不是装饰。它应改变可用行动、敌人意图或结束条件。

## 7. 攻守之势与破绽

### 7.1 攻守之势

`momentum` 取值如下：

| 数值 | 名称 | 含义 |
| --- | --- | --- |
| `-2` | 受制 | 下一次高承诺行动极易被截断 |
| `-1` | 失势 | 只能稳住、冒险反击或寻找出口 |
| `0` | 相持 | 双方都能执行正常行动 |
| `1` | 得势 | 可以逼位、连续压迫或安全观察 |
| `2` | 压制 | 可尝试制伏、夺械或决定性一击 |

攻守之势每场战斗重新计算，不带出战斗，也不能无限累积。强力终结动作通常需要“得势/压制 + 对应破绽”，避免起手秒杀，也避免靠磨血收尾。

### 7.2 破绽

破绽是有来源、有时限、可被特定行动利用的条件：

```js
{
  id: "exposed-wrist",
  targetId: "wang-zhuo",
  source: "failed-sleeve-dart",
  expiresAfterRound: 3,
  tags: ["hand", "disarm", "acupoint"],
  revealed: true
}
```

常见破绽包括：

- 手腕外露：可封穴或夺械；
- 重心前倾：可借力推入水中；
- 换气停顿：可打断心法；
- 视线被遮：可救人或撤退；
- 同伴被牵制：敌人不能兼顾出口；
- 杀意锁定主角：被保护者可自行离场。

破绽应由玩家行为制造，不能只靠随机出现。

## 8. 敌人意图与看破层级

每个敌方意图包含三层信息：

```js
{
  actorId: "wang-zhuo",
  telegraph: "右肩抬起，刀锋指向你的面门",
  actionId: "high-feint-low-dart",
  targetId: "player",
  danger: "severe",
  layers: {
    surface: "上路挥刀",
    technique: "逼你抬手护面",
    followUp: "袖箭取腿，封住退路"
  },
  confidence: "suspected"
}
```

信息分三级开放：

1. **露势**：所有玩家都能看见表面动作和大致危险；
2. **识招**：属性、武学或一次亲历后看见攻击目标、距离和主要后果；
3. **破招**：结合情报、观察和环境，看见后手及可制造的破绽。

错误判断必须来自敌人的欺骗能力或玩家掌握的信息不足，不使用毫无提示的随机反转。界面用“看准”“推测”“未明”标示可靠度。

## 9. 玩家行动模型

所有行动使用同一结构：

```js
{
  id: "spring-needle-seal-wrist",
  label: "春风针·封腕",
  category: "technique",
  target: "enemy",
  requires: {
    range: ["near", "middle"],
    momentumAtLeast: 1,
    openingTags: ["hand", "acupoint"],
    usableBodyParts: ["right-arm"]
  },
  costs: { needle: 1 },
  commitment: "medium",
  counters: ["hard-cover", "deflect-projectile"],
  results: ["disable-weapon-hand", "capture-window"],
  risks: ["lose-momentum-on-failure"]
}
```

### 9.1 行动类别

| 类别 | 作用 |
| --- | --- |
| 观察 | 看清后手、武学、出口或机关；会让出部分主动权 |
| 身法 | 改变距离、落脚、掩体和出口控制 |
| 防守 | 接架、闪避、护人、卸力，为下一回合稳住局势 |
| 招式 | 攻击、封穴、夺械、打断、压制或制造破绽 |
| 物品 | 暗器、药物、绳索、火折、信物等 |
| 环境 | 灭灯、断索、翻桌、入水、关门、敲锣 |
| 同伴 | 请求掩护、夹击、救人、递物或撤离 |
| 言语 | 威慑、拖延、揭破身份、动摇立场或诱导目标 |
| 离场 | 撤退、投降、放船、带人突围或假意被俘 |

### 9.2 承诺程度

- 低承诺：观察、试探、短步，不易遭到重罚，收益也有限；
- 中承诺：正常招式、护人、使用环境，失败会失势或负轻伤；
- 高承诺：绝招、夺械、救下必死者、强行突围，成功可结束阶段，失败会产生重伤或致死条件。

高风险按钮必须提前说明主要代价，不用模糊的“试试看”。

### 9.3 不显示命中率

界面不显示百分比命中率。行动结果由已知条件决定，并展示为：

- 稳妥：当前条件足够，主要结果确定；
- 有险：能达成目的，但将承担已知代价；
- 冒险：仍有一项关键条件未知；
- 必死：已亲历并确认的直接死亡路线。

如内容需要不确定性，应从敌人未揭示意图、伤势恶化或场景变化产生，而不是暗骰让同样条件得到任意结果。

## 10. 武学必须改变行动规则

武学不以“攻击力 +10%”为主要差异，而要改变玩家能看见、能承受和能完成的事情。

### 10.1 春风针

定位：中近距离观察、封穴与精确终结。

- 基础：攻击露出的手腕、腿弯或肩井；
- 看破意图后：针对换气、发力和暗器后手；
- 得势且有破绽：封穴制伏，不必杀人；
- 高承诺：致命出针，立刻结束战斗但留下杀人、证据与关系后果；
- 限制：钢针数量、手臂伤势、遮挡和贴身压迫。

### 10.2 鱼跃龙门诀与钓竿

定位：控制距离、借力改位和水边作战。

- 钩住兵器或衣袖，改变距离；
- 借敌人前冲之力使其失衡；
- 在水边夺取落脚和出口；
- 拉回同伴或关键物品；
- 面对重兵器时不硬拼，以缠、引、卸改变攻守之势。

### 10.3 海桩

定位：水势、湿滑地面和推挤中的稳定。

- 将水边受限落脚视为稳固；
- 被推、拉、浪涌影响时少失一档攻守之势；
- 可以在浅水中完成他人无法稳定使用的招式；
- 不能免除溺水、重伤或水下闭气需求。

### 10.4 枯木桩

定位：忍痛、护身与伤后反击。

- 轻伤不会立刻中断动作；
- 可暂时压住失血或毒性一轮；
- 重伤时仍能完成一次护人或撤离动作；
- 代价是战后伤势可能加重，不能把受伤变成免费收益。

后续猿公棍等武学也按同一原则设计：至少增加一种新行动、改变一种场景条件，并提供一种独特的结束方式。

## 11. 伤势与身体功能

### 11.1 伤势结构

```js
{
  id: "knife-cut-left-arm",
  type: "cut",
  bodyPart: "left-arm",
  severity: 2,
  bleeding: 1,
  pain: 1,
  infectionRisk: 1,
  tags: ["grip-weakened", "needs-bandage"],
  source: "temple-knife-fighter",
  treated: false
}
```

### 11.2 部位影响

| 部位 | 典型影响 |
| --- | --- |
| 头颈 | 观察失真、眩晕、失声或快速致死 |
| 手臂 | 持械、发针、攀爬、护人受限 |
| 躯干 | 运劲、呼吸、承受冲击和持续行动受限 |
| 腿脚 | 移动距离、稳定落脚和撤退受限 |
| 经脉 | 心法、爆发招式和恢复受限 |

### 11.3 严重度

| 等级 | 状态 | 规则后果 |
| --- | --- | --- |
| 1 | 轻伤 | 提醒与轻微限制，简单处理后可继续 |
| 2 | 受创 | 禁用部分行动或提高对应行动风险 |
| 3 | 重伤 | 持续恶化，需要撤离、同伴或紧急医治 |
| 4 | 致命 | 进入明确倒计时，若不解除则死亡 |

伤势不是另一根血条。一次精准钢针可以直接造成“持刀手失用”，一次胸腹重击也可能让角色仍未死亡却无法继续护人。

### 11.4 战后处理

战斗结算后必须给出伤势去向：

- 当场包扎：止血但不治愈；
- 运功压制：换取赶路时间，之后可能反噬；
- 求医：消耗钱、时间或人情；
- 同伴照料：改变关系并暴露秘密；
- 放任恶化：进入感染、残损或新的奇遇条件。

伤势必须进入旅行、修炼、谈判和下一场战斗，直到被真实处理。

## 12. 毒、心神与持续状态

毒物至少包含：

```js
{
  id: "black-water-paralysis",
  latentRounds: 1,
  intensity: 2,
  symptoms: ["numb-fingers", "slowed-breath"],
  progression: ["grip-loss", "unable-to-move"],
  suppressBy: ["medicine", "deadwood-breath"],
  cureBy: ["matching-antidote"]
}
```

毒性以症状和发作阶段提示，玩家观察得越深，越能判断剩余时间和对症方法。

心神状态包括恐惧、杀意压迫、魅惑、执念和威吓。它们改变可用行动、可靠度或风险，例如“恐惧时无法选择高承诺逼近”，但不能直接夺走所有选择。玩家始终至少保留稳住、观察、求助或撤离中的一项。

## 13. 同伴参战

同伴不是第二个需要玩家逐招操作的角色。每回合玩家只为同伴指定一个意图：

- 护住自己；
- 牵制某人；
- 保护目标；
- 控制出口；
- 准备救援；
- 立即撤离。

同伴是否执行及执行深度由以下条件决定：

- 信任和关系；
- 是否理解玩家的计划；
- 是否触碰其底线；
- 自身伤势和武学；
- 玩家是否兑现过承诺。

高信任不是数值增伤，而是让同伴愿意承担风险、配合假动作或相信看似荒唐的命令。低信任同伴可能拒绝送死，但不能无提示地随机背叛。

同伴受伤、杀人、被放弃或被保护都会写回关系与后续剧情。

## 14. 多名敌人

多人战不让每个杂兵都拥有完整回合。敌人按战术角色组成一个威胁队列：

| 角色 | 功能 |
| --- | --- |
| 突击 | 直接逼近并制造伤势 |
| 封路 | 控制出口、船只或狭门 |
| 掠阵 | 等待玩家失势后补刀 |
| 暗器 | 迫使玩家寻找掩体或分心 |
| 投毒 | 推动持续倒计时 |
| 传讯 | 召来援手或启动机关 |

每轮突出一个主要危险和至多两个次要威胁。玩家的行动可以打断某个角色、改变队形，或让两个敌人的目的彼此冲突。

清理弱敌应通过一次成功的范围控制、威慑、断后或首领崩溃完成，避免逐个消耗长血条。

---

## 15. 首领阶段

首领转阶段必须由规则或剧情变化触发，不只依赖剩余气血。

常见触发方式：

- 身份或武学被看破；
- 关键机关被夺取；
- 同伴撤离或入场；
- 战场从巷口转到河岸；
- 首领第一次负伤后改用禁招；
- 玩家毁掉其任务目标，使其从灭口转为逃命。

### 王卓两阶段战示例

#### 第一阶段：柳巷尾随

眼前目的：护住燕惊鸿，确认跟踪者是谁。

- 王卓不急着杀人，先试探玩家是否拿到账册；
- 玩家可借柳影观察、分开诱敌或让燕惊鸿先走；
- 看破袖箭后获得“左手后手”事实；
- 逼王卓失势、主动退到河岸或燕惊鸿被截住时进入第二阶段。

#### 第二阶段：河岸截命

眼前目的根据前一阶段变化：

- 若燕惊鸿已离开：玩家可撤退、制伏或追问幕后者；
- 若燕惊鸿仍在场：必须同时处理她与出口；
- 若袖箭未被看破：王卓保留一次隐藏致伤后手；
- 若玩家掌握鱼跃龙门诀与海桩：可借水边夺位，将其逼入浅水；
- 若选择杀死王卓：快速断线，但失去活口并改变龙青鱼态度；
- 若制伏：需要压制之势、手腕破绽和同伴看守；
- 若夺取令牌放他离开：可尾随进入帮会据点，但敌方会提高戒备。

同一战斗因此同时验证心法、环境、同伴、情报和长期路线，而不是只验证战力。

## 16. 战斗结束与长期后果

统一的 `outcome.type` 包括：

- `objective-complete`：任务完成，无需继续交锋；
- `enemy-killed`：敌人死亡；
- `enemy-subdued`：敌人被制伏或俘虏；
- `enemy-routed`：敌人逃走或被逼退；
- `player-escaped`：玩家带着当前成果离场；
- `player-captured`：进入俘虏剧情；
- `mutual-injury`：双方带伤中止；
- `player-dead`：满足致死条件，进入命灯流程。

结算至少写回：

```js
{
  result,
  objectives,
  wounds,
  consumedItems,
  gainedItems,
  relationshipChanges,
  learnedFacts,
  witnesses,
  deaths,
  factionConsequences,
  nextScene
}
```

杀死、制伏和放走同一敌人必须产生不同后果：

- 杀死：立即消除威胁，但制造尸体、目击、心性和关系问题；
- 制伏：难度最高，可审问和交换，但要处理看守与逃脱；
- 放走：保留尾随、传假消息或长线关系，也可能让敌方提前备战。

---

## 17. 命灯、死亡与死因记忆

### 17.1 检查点

重大交锋前建立因果节点，记录进入战斗前的业务状态。节点不能放在已经承担伤害之后，避免状态重复结算。

### 17.2 真正死亡

只有出现以下情况之一才触发死亡：

- 致命伤倒计时归零；
- 玩家选择已经明确标注的致死行动；
- 场景规则明确无生还条件；
- 两盏命灯均已熄灭后的最终死亡。

负伤、昏迷、被俘和任务失败都不是死亡。

### 17.3 回照保留内容

熄灭一盏命灯后，回到最近因果节点，并保留：

- 直接死因；
- 亲眼看见的敌人招式与后手；
- 已确认的场景规则；
- 玩家经历过的关键对话和身份信息。

不保留已经消耗的战斗奖励、伤势、缴获和关系结果。已知事实会改变下一次战斗的意图展示和行动条件，但不会直接增加伤害。

### 17.4 防止反复送死刷收益

- 同一死因只首次生成新的死因见闻；
- 已知必死行动在只剩一盏命灯时隐藏或禁用；
- 重复看破的招式不再次给予奖励；
- 回照后的优势来自新选择，不来自叠加永久数值。

## 18. 手机界面结构

战斗页保持单列，信息顺序固定：

1. 场景标题与一句眼前困境；
2. 当前主要目的；
3. 最危险的敌人意图；
4. 距离、落脚和攻守之势；
5. 玩家与同伴的关键伤势；
6. 三至六个当前行动；
7. 最近一轮结果；
8. 可折叠的已知事实和更早战报。

建议示意：

```text
河岸截命 · 第二轮
护住燕惊鸿，并找到离开河岸的路

王卓：刀锋压向你，左袖仍贴着肋下
推测：正面是虚招，袖中后手未明

近距｜湿滑｜失势
你：左臂刀伤（发针受限）
燕惊鸿：退路被封

[稳住下盘，以海桩接刀]
[借钓线缠腕，让燕惊鸿先走]
[冒险扑近，封住他的左手]
[翻入河中，从水路撤离]
```

界面不使用传统红蓝血条。敌我状态用“从容、戒备、失势、负伤、重伤、濒死”等可读词语表达。

数字键 `1`～`9` 继续对应当前可用行动，禁用按钮必须解释缺少的条件。

## 19. 内容数据与规则接口

实现时建议把通用规则、战斗内容和页面状态分开：

```text
web/
  combat/
    combat-core.mjs
  content/
    combat/
      temple-needle-fight.mjs
      wang-zhuo-riverside.mjs
tests/
  combat.test.mjs
```

核心层不访问 DOM、`localStorage` 或网络。建议接口：

```js
createBattle(definition, context)
getBattleView(state, context)
getAvailableCombatActions(state, context)
resolveCombatRound(state, action, context)
applyWound(actor, wound)
advanceBattleStatuses(state)
resolveBattleOutcome(state)
createDeathMemory(state, cause)
```

单场战斗定义至少包含：

```js
{
  id,
  title,
  participants,
  startingPosition,
  objectives,
  phases,
  terrain,
  actions,
  intentRules,
  transitionRules,
  outcomeRules
}
```

`getBattleView()` 只返回当前玩家有权知道的内容，不能把隐藏意图和未揭示身份直接交给渲染层。

## 20. 数值与节奏边界

- 普通交锋以 `2～5` 轮结束；
- 首领战以 `4～7` 轮和 `2～3` 个阶段为上限；
- 每轮展示 `3～6` 个有意义的行动；
- 每场至少有一种非杀戮解法和一种撤离或失败底线；
- 首次观察可以花费主动权，已确认事实永久免除重复观察；
- 同一种最优行动不能连续解决所有意图；
- 伤势数量保持少而清晰，同一部位同类轻伤优先合并或升级；
- 不用敌人血量膨胀延长战斗，用阶段、目的和规则变化增加深度；
- 强敌可以让玩家无法正面获胜，但必须保留拖延、欺骗、撤离或利用环境的可能。

## 21. 单场战斗编写清单

新增一场战斗前必须回答：

1. 玩家为什么现在必须出手？
2. 不杀敌也能达成的主要目的是什么？
3. 敌人真正想要什么，而不只是“杀死玩家”？
4. 第一轮玩家能自然看见什么危险？
5. 哪个后手需要观察、亲历或旧情报才能看破？
6. 场景中至少哪一件东西可以改变战局？
7. 哪门已有武学能在短时间内得到兑现？
8. 如何制造破绽，如何把破绽转化为制伏或终结？
9. 负伤、撤退、被俘、制伏和杀死分别进入哪里？
10. 同伴或关系如何改变选择，而不是只提供伤害？
11. 死亡会留下哪条具体见闻？
12. 这场战斗改变了哪条后续剧情或势力状态？

若只能回答“敌人血量归零”，该战斗尚未达到制作标准。

## 22. 测试矩阵

### 22.1 纯规则测试

- 相同状态与行动得到可重复结算；
- 距离不满足时不能使用对应招式；
- 伤臂正确限制持械和发针；
- 破绽过期后不能执行对应终结动作；
- 攻守之势不超出 `-2～2`；
- 观察可揭示后手，已知事实不重复收费；
- 非致死失败不消耗命灯；
- 死亡回照只消耗一盏灯且不重复结算物品；
- 一盏灯时已确认必死行动不再出现；
- 同伴拒绝必须由关系或底线确定，不受随机影响；
- 击杀、制伏、逃离分别写回不同结果；
- 所有规则返回对象均可 JSON 序列化。

### 22.2 浏览器完整流程

- 春风针夜战原有分支和结果保持不变；
- 敌人意图、目标、位置、伤势和行动在手机首屏可读；
- 禁用行动明确显示缺失条件；
- 数字键可触发当前行动；
- 一次死亡后正确回到交锋前节点并显示新见闻；
- 王卓战可完成护人撤退、制伏和杀死三类结果；
- 同伴伤势与关系能进入战后场景；
- `390×844` 和 `1280×720` 无横向溢出；
- 页面无运行异常，动态姓名经过 `escapeHtml()`。

## 23. 分阶段实现顺序

### C0：锁定现有基准

- 为春风针夜战补齐意图、伤势、死亡和各结局回归测试；
- 明确现有玩家可见文本与状态字段；
- 不改变已经上线的故事顺序。

完成信号：现有夜战的封穴、杀死、负伤、死亡回照全部有稳定测试。

### C1：抽出通用规则

- 建立距离、落脚、攻守之势、破绽和统一行动结构；

- 建立统一伤势和战斗结算接口；
- 完成手机战斗视图。

完成信号：迁移前后的夜战结果一致，具体剧情文件不再自行编写整套结算逻辑。

### C2：王卓两阶段战

- 加入同伴指令；
- 加入柳巷与河岸环境；
- 加入首领阶段、隐藏后手和活捉条件；

- 加入多名敌人的战术角色；

完成信号：帮会清剿不依赖逐个扣血，玩家能通过战场目的和机制完成整段据点流程。

## 24. C1 完成定义

第一轮通用战斗系统只有同时满足以下条件才算完成：

- 春风针夜战已经使用通用规则，原有剧情结果不减少；
- 敌人意图至少包含露势、识招和破招三层；
- 距离、落脚、攻守之势和破绽真实改变行动；
- 至少五个身体部位与四档伤势能限制对应行为；
- 击杀、制伏、撤离、负伤和死亡是不同的规则结果；
- 死亡回照保留死因见闻，但不重复保留奖励；
- 武学提供新行动、场景优势或结束方式，而非只加数值；
- 规则层可独立测试并保持 JSON 可序列化；
- 手机界面能在行动前说明目的、条件和主要风险；
- 规则测试与完整浏览器流程通过，文档与实际状态一致。
