# 容貌纸娃娃与美术生产管线

## 1. 目标

容貌系统采用成熟二维头像生成器的组织方式：玩家仍然选择帽子、前发、后发、眼睛、眉毛、嘴巴、鼻子、脸型、后背、衣服和脸饰，但运行时不再把十一张互不相关的图片直接叠放。

系统必须保证：

- 任意可选组合都以同一人物母版为基准；
- 一个选项可以同时提供多个附件，例如帽子前层、帽子后层和遮发蒙版；
- 绘制顺序由固定插槽决定，不由文件名或 DOM 顺序偶然决定；
- 不兼容组合由规则处理，不用逐张 CSS 位移补洞；
- 装备仍不改变角色外观，服装是独立审美选择。

## 2. 成熟方案采用记录

### 2.1 Picrew

参考：

- <https://support.picrew.me/en/create_imagemaker/create_first_process>
- <https://support.picrew.me/en/creator_functions/layer_sort>
- <https://support.picrew.me/en/creator_functions/parts_rule>

采用：

- 一个可选部件可以包含多个渲染层；
- 图层顺序与界面中的选项顺序分离；
- 部件之间可以声明冲突或替代规则；
- 先用少量部件完成可验证纵切，再增加颜色和数量。

不采用：

- 不接入 Picrew 服务，也不使用第三方 Picrew 素材；
- 不把外部编辑器配置作为游戏运行时依赖。

### 2.2 Spine

参考：

- <https://esotericsoftware.com/spine-slots>
- <https://esotericsoftware.com/spine-skins>
- <https://esotericsoftware.com/spine-runtime-terminology>

采用：

- 固定插槽、附件和从后到前的绘制顺序；
- 外观选择只负责替换对应插槽的附件；
- 同一插槽一次只显示一个附件。

不采用：

- 第一版不接入 Spine 编辑器、骨骼动画或商业运行时；
- 当前容貌页是静态正面预览，不需要网格变形和 IK。

### 2.3 Universal LPC

参考：<https://github.com/liberatedpixelcup/Universal-LPC-Spritesheet-Character-Generator>

采用所有部件共享同一姿势、画布和模板的生产纪律。不直接使用其像素素材，避免画风冲突和混合许可带来的署名、派生授权与发行限制。

## 3. 母版契约

### 3.1 固定标尺

| 项目 | 规则 |
| --- | --- |
| 画布 | `1024 × 1536`，透明 RGBA |
| 人物中轴 | `x = 512` |
| 脚底线 | `y = 1460` |
| 头顶参考线 | `y = 96`，仅作制作参考，不强迫所有发饰等高 |
| 面部中心 | 男身、女身分别固定；同一体貌的全部脸型和五官不得改变 |
| 导出 | 保留完整画布，禁止 trim、自动居中、逐图缩放 |
| 光线 | 左上方柔光，所有部件保持相同色温、边缘锐度和笔触密度 |

男身和女身各有一份独立母版。部件不能跨体貌复用，也不能从另一张姿势不同的整图中硬切。

### 3.2 固定插槽

| 顺序 | 插槽 | 用途 |
| ---: | --- | --- |
| 5 | `backAccessory` | 剑匣、斗篷等后背物 |
| 10 | `backHair` | 后发；可受当前帽子的遮发蒙版影响 |
| 15 | `hatBack` | 位于头部或后发之后的帽子后层 |
| 20 | `body` | 固定透明人物标尺或身体底层 |
| 30 | `clothing` | 完整身体、衣服和露出的手脚，不含头发与可替换五官 |
| 40 | `faceShape` | 唯一连续的脸部与颈部皮肤表面 |
| 45 | `eyes` | 眼白、瞳孔、睫线和必要阴影，不含肤色底 |
| 46 | `brows` | 眉毛笔触，不含肤色底 |
| 47 | `nose` | 鼻部明暗笔触，不含肤色底 |
| 48 | `mouth` | 唇线与唇色，不含肤色底 |
| 50 | `frontHair` | 前发；可受当前帽子的遮发蒙版影响 |
| 60 | `faceAccessory` | 伤疤、面罩等脸饰 |
| 70 | `hatFront` | 帽檐、冠带和其它必须压在前发之上的部分 |

插槽名称是稳定协议。新增部件只能向现有插槽提供附件；确需新插槽时先修改本文件、纯规则和组合测试。

## 4. 复合部件与遮罩

普通部件可以只提供一个附件。帽子等跨越多个遮挡层的部件必须提供复合定义：

```js
{
  id: 3,
  name: "束发小冠",
  attachments: [
    { slot: "hatBack", asset: "male-hat-3-back-v3.webp" },
    { slot: "hatFront", asset: "male-hat-3-front-v3.webp" }
  ],
  hairMask: "male-hat-3-hair-mask-v3.webp",
  compatibility: { frontHair: "mask", backHair: "mask" }
}
```

`hairMask` 是黑白／透明遮罩，只能裁掉应被帽冠包住的头发。它不得擦除脸、皮肤、衣服或帽子本身。合成器分别在前发、后发的离屏画布上应用遮罩，再按插槽顺序绘回主画布。

兼容策略只有三种：

- `none`：无需处理；
- `mask`：使用当前部件的遮罩裁切目标附件；
- `forbid`：组合在规则层不可用，界面保留并说明冲突原因。

禁止增加只针对某个编号的 `top`、`left`、`scale` 或 `clip-path` 特例。

## 5. 资源生产流程

1. 在男身／女身母版上完成完整默认形象，锁定姿势、比例、脸部中心、光线和笔触；
2. 保留带参考线的源稿，运行时资源不包含参考线；
3. 每个新部件直接在母版上绘制，不在独立小画布上作画后再猜位置；
4. 发型可以分成前发和后发，但每张导出仍保留完整 `1024 × 1536` 画布；
5. 跨前后层的帽子、斗篷或面罩按复合附件导出；
6. 复杂透明边缘以源文件 alpha 为准，不依赖运行时色键抠图；
7. 先交付两种体貌各一套默认组件、两组发式、两顶帽子和两套衣服；该纵切全部组合通过后才扩到正式数量。

AI 图像只允许用于整体角色概念或母版候选。未经共同母版重绘和组合验收的独立生成图，不得直接进入运行时部件目录。

## 6. 运行时合成

- 纯规则模块把当前容貌解析成有序附件与遮罩计划；
- 浏览器使用原生 Canvas 2D 合成，主画布尺寸始终为 `1024 × 1536`；
- 图片加载、解码或绘制失败时保留可见错误提示，并回退到完整默认预设，不显示半个人物；
- 容貌页和人物页共用同一合成函数与资源版本；
- 存档继续保存十一类离散编号，渲染契约升级不破坏既有选择；不存在的旧编号由迁移回落到 `1`。

## 7. 验收

### 7.1 自动契约

- 每张附件和遮罩必须是 `1024 × 1536`；
- 所有运行资源存在、可解码、有正确 alpha；
- 五官层的非透明像素面积不得达到脸型层的量级；
- 遮发蒙版不得超出头部允许区域；
- 纯规则能稳定解析插槽顺序、复合附件和冲突原因；
- 相同状态输出相同附件计划。

### 7.2 组合矩阵

纵切阶段穷举：

> 性别 × 帽子 × 前发 × 后发 × 衣服 × 脸型

不以随机八张代替穷举。扩充正式数量后，至少穷举所有“帽子 × 前发 × 后发 × 性别”，其它部件使用成对覆盖矩阵。

当前纵切的九十六组验收图见[容貌组合矩阵](../assets/appearance-rig-v1-matrix.webp)，由`scripts/build-appearance-rig.py --qa-output <路径>`从正式运行资源重建，不是人工挑选的展示图。

### 7.3 浏览器

在 `1280×720`、`1280×660`、`844×390` 和 `390×844` 检查：

- 人物始终居中；
- 选项不与姓名、性别、底部按钮或人物相撞；
- 切换部件后画面无闪烁、半成品或旧缓存；
- 帽子与头发没有漂浮、横穿、露出不应存在的头发或大块空洞；
- 脸与颈部没有肤色贴片、横向接缝和异常边缘。
