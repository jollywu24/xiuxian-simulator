# SYS-12：容貌与人物美术生产管线

## 1. 当前结论

容貌页使用“可换动作的衣装底像＋固定头脸＋限定区域部件”的PSD式纸娃娃结构。玩家可以切换男身／女身，并分别选择帽子、前发、后发、眼睛、眉毛、嘴巴、鼻子、脸型、脸饰、后背和衣服。首版每类开放两个真实选项，不显示假的`1/8`。

当前边界：

- 装备不改变人物外观，服装只属于容貌；
- 新旅程十一类均从编号`1`开始，选择可保存、迁移和恢复；
- 四套推荐组合用于“随心一变”，玩家仍可逐项混搭；
- 静态WebP是正式运行资源；Spine仍受编辑器、版本和分发许可门禁约束；
- 不批量扩为八项，先保证现有二项在男女体貌、两视口和所有组合中成立。

## 2. 视觉与界面基准

容貌页以[明亮水墨确认稿 v5](../assets/references/appearance-interface-v5.jpg)为唯一视觉基准：

- `1280×720`为桌面标尺，`844×390`为手机横屏标尺；
- 雾白绢纸、浅墨江南、青玉交互条与旧金描边；
- 人物位于视口中轴，使用从头顶到大腿上段的半身构图；
- 帽子控制条位于人物上方，底边与人物头顶在桌面至少留`20px`、手机横屏至少留`10px`安全距；
- 顶部一项、左右各五项组成十一类等大控制条；
- 姓名与体貌位于左上，随机与确认固定在底部；
- `390×844`只显示横置提示，不渲染第二套容貌布局。

设计稿用于视觉目标，运行截图用于证明功能；两者不能互相替代。

## 4. 当前运行契约

### 4.1 状态与选择

`appearance-core.mjs`保存十一类离散编号。每类目录长度为`2`：

```text
body: male | female
hat / frontHair / backHair / eyes / brows / mouth / nose /
faceShape / faceAccessory / backAccessory / clothing: 1 | 2
```

编号`1`使用共同母版的默认外观；编号`2`加载对应独立层。`clothing`选择完整衣装底像，可以改变颈部以下姿势；构建时先擦除衣装源自带的头部，再由固定头层覆盖，所以换衣不能移动、重画或改变五官。前发与后发被预编译为四种完整头层，避免跨发型叠出第二张脸。

“随心一变”循环四套确定性推荐组合：男身默认、男身行衣、女身默认、女身行衣。普通逐项切换不受推荐组合限制。

### 4.2 画布与锚点

- 运行画布：`1024×1536`透明WebP；
- 人物水平中心：`x = 512`；
- 可见顶部：`y = 54 ± 18`；
- 构图止于大腿上段，底部允许自然越出运行视口；
- 底像、固定头层和所有局部层共享同一画布；
- 浏览器不为单个体貌或部件追加`top`、`left`、`scale`或`clip-path`补丁。

当前正式资源位于`web/assets/appearance/rig-v5-psd/`，共二十八张：男女各两张衣装底像、四张前后发组合头层、五张五官／脸型替换片和三张配饰层。人物与衣装源图位于`art_source/appearance/rig-v3/`和`art_source/appearance/rig-v4/`，新增帽子源与管线说明位于`art_source/appearance/rig-v5/`。构建脚本为`scripts/build-appearance-rig-v5.py`，人工组合图为[固定锚点容貌组合矩阵](../assets/appearance-rig-v5-psd-matrix.webp)。

### 4.3 绘制顺序

```text
后背 → 衣装底像 → 固定头层（前发＋后发） → 脸型 → 眼睛 →
眉毛 → 鼻子 → 嘴巴 → 脸饰 → 帽子
```

`paperdoll-system.mjs`只生成稳定绘制计划；`paperdoll-renderer.mjs`在离屏Canvas加载全部图层，成功后一次绘制，加载失败时回退默认形象。人物页与容貌页共用同一合成器。

## 5. 美术生产流程

1. 先确定男女完整人物母版，锁定年龄、头部、脸中心、光向和画风；
2. 衣装允许使用不同动作，但只把颈部以下作为有效内容；构建脚本用硬边图层遮罩移除其头部，再放回同一头脸；
3. 前发与后发必须在固定头脸上制作并编译为四种完整头层，不能在浏览器临时拼接互相冲突的发片；
4. 五官从共同母版的固定区域派生，导出全画布替换片并限制在各自ROI；不能带入整脸、头发或颈部；
5. 帽子、脸饰和后背使用固定插槽；帽子源必须是不含人物和头发的独立物件，后背层始终位于人物后方；
6. 构建脚本去除洋红色键、统一构图、导出WebP并生成组合矩阵；
7. 原尺寸检查男女四套推荐组合，再在浏览器逐项点击并切回十一类；
8. `1280×720`检查人物位置与帽子安全距，`844×390`检查同一关系和触控可达；
9. 规则、资源契约和容貌专项浏览器回归全部通过后，才进入发布门禁。

AI图像可用于完整人物母版、以通过母版为输入的衣装派生，或不依赖人体锚点的独立物件。人体部件必须从共同母版固定区域派生；独立生成一批不共享人物锚点的衣服和五官再直接叠加，视为结构失败。

## 6. 验收

### 6.1 自动契约

- 二十八张运行资源存在、可解码且均为`1024×1536`；
- 十一类目录各有两个合法值，越界旧档回到默认；
- 相同状态输出相同绘制计划；
- 每一类第二项都产生独立运行层、固定头层或衣装底像；
- 换衣后的固定头部像素逐点一致；前发／后发不能改变脸部保护区；五官替换层不得越出对应ROI；
- 所有运行资源均由资源目录引用，无缺失与孤儿；
- 缓存版本、入口样式与主模块版本一致。

### 6.2 人工矩阵

- 男女都是十九至二十二岁范围的年轻成人，不出现儿童脸；
- 两套衣装具有明显结构差异，不只换颜色；
- 人物头顶、脸中心、五官、下颌和颈部锚点不随换衣漂移；衣装自身可以改变肩线、双臂和手部动作；
- 混搭五官与发型时没有第二张脸、肤色椭圆、矩形补片或透明缺口；
- 后背物件位于身体后方，帽子与头发关系清楚；
- 透明边缘没有洋红残边或断裂。

### 6.3 浏览器专项回归

`npm run smoke:appearance`只验证容貌页：

- `1280×720`人物与帽子控制条都位于视口中轴；
- 帽子控制条底边在桌面至少早于人物头顶`20px`；
- 十一条控件等大、左右五行镜像、没有禁用箭头；
- 依次点击十一类并切回后，Canvas像素哈希每次都变化、回切结果确定且序号显示`2 / 2`；
- 换发时固定脸部ROI不变，换衣时固定头部ROI不变，五官变化不越出允许区域；
- 姓名／体貌、第一行、第五行与底部按钮不相撞；
- `844×390`无溢出，帽子仍不遮头，确认按钮完整；
- `390×844`只显示横置提示，页面无运行异常。

自动契约证明结构，矩阵和浏览器截图证明实际观感；三者不能互相替代。

## 7. 后续扩充门禁

从二项扩到八项前，每个新增部件必须：

- 从当前共同母版绘制或重绘；
- 共用同一身体、肤色、脸中心和遮挡顺序；
- 与两个体貌、两套衣装和所有相关部件生成可辨识组合矩阵；
- 不为单个编号增加CSS位置补丁；
- 通过专项浏览器逐项像素变化检查；
- 来源、许可和公开分发权记录完整。

如果某类无法在共同母版上可靠拆分，就维持当前二项，不用数量替代质量。
