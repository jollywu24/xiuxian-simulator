# SYS-12：容貌与人物美术生产管线

## 1. 当前结论

容貌页使用“完整人物母版＋同画布局部部件”的纸娃娃结构。玩家可以切换男身／女身，并分别选择帽子、前发、后发、眼睛、眉毛、嘴巴、鼻子、脸型、脸饰、后背和衣服。首版每类开放两个真实选项，不显示假的`1/8`，也不再把完整人物图映射到衣服后禁用其它十类控件。

当前边界：

- 装备不改变人物外观，服装只属于容貌；
- 新旅程十一类均从编号`1`开始，选择可保存、迁移和恢复；
- 四套推荐组合用于“随心一变”，玩家仍可逐项混搭；
- 静态WebP是正式运行资源；Spine仍受编辑器、版本和分发许可门禁约束；
- 不批量扩为八项，先保证现有二项在男女体貌、两视口和所有组合中成立。

## 2. 视觉与界面基准

容貌页以[明亮水墨确认稿 v5](../assets/references/appearance-interface-v5.jpg)为唯一视觉基准：

- `1280×720`为桌面标尺，`844×390`为手机横屏标尺；
- 雾白绢纸、浅墨江南、青玉交互条与旧金描边；
- 人物位于视口中轴，使用从头顶到大腿上段的半身构图；
- 帽子控制条位于人物上方，底边与人物头顶至少留`4px`安全距；
- 顶部一项、左右各五项组成十一类等大控制条；
- 姓名与体貌位于左上，随机与确认固定在底部；
- `390×844`只显示横置提示，不渲染第二套容貌布局。

设计稿用于视觉目标，运行截图用于证明功能；两者不能互相替代。

## 4. 当前运行契约

### 4.1 状态与选择

`appearance-core.mjs`保存十一类离散编号。每类目录长度为`2`：

```text
body: male | female
hat / frontHair / backHair / eyes / brows / mouth / nose /
faceShape / faceAccessory / backAccessory / clothing: 1 | 2
```

编号`1`使用共同母版的默认外观；编号`2`加载对应独立层。`clothing`是例外：它选择同一体貌的完整衣装底像，避免领口、肩线、双臂和手部靠局部覆盖猜位置。

“随心一变”循环四套确定性推荐组合：男身默认、男身行衣、女身默认、女身行衣。普通逐项切换不受推荐组合限制。

### 4.2 画布与锚点

- 运行画布：`1024×1536`透明WebP；
- 人物水平中心：`x = 512`；
- 可见顶部：`y = 54 ± 18`；
- 构图止于大腿上段，底部允许自然越出运行视口；
- 底像、衣装和所有局部层共享同一画布；
- 浏览器不为单个体貌或部件追加`top`、`left`、`scale`或`clip-path`补丁。

当前正式资源位于`web/assets/appearance/rig-v4/`，共二十四张：男女各两张底像／衣装和十张第二选项部件。源图位于`art_source/appearance/rig-v3/`与`art_source/appearance/rig-v4/`，构建脚本为`scripts/build-appearance-rig-v4.py`，人工组合图为[容貌组合矩阵 v4](../assets/appearance-rig-v4-matrix.webp)。

### 4.3 绘制顺序

```text
后背 → 人物／衣装底像 → 脸型 → 后发 → 眼睛 → 眉毛 → 鼻子 →
嘴巴 → 前发 → 脸饰 → 帽子
```

`paperdoll-system.mjs`只生成稳定绘制计划；`paperdoll-renderer.mjs`在离屏Canvas加载全部图层，成功后一次绘制，加载失败时回退默认形象。人物页与容貌页共用同一合成器。

## 5. 美术生产流程

1. 先确定男女完整人物母版，锁定年龄、头部、脸中心、领口、肩线、手部、光向和画风；
2. 衣装变化必须以母版做身份保持编辑，只改颈部以下，不重新生成人物身份；
3. 五官与发型从共同母版的固定区域派生，保持`1024×1536`全画布，不在浏览器写编号偏移；
4. 帽子、脸饰和后背使用固定插槽；没有对应遮挡关系时宁可缩小变化范围，也不擦除脸或衣服；
5. 构建脚本去除洋红色键、统一构图、导出WebP并生成组合矩阵；
6. 原尺寸检查男女四套推荐组合，再在浏览器逐项点击十一类；
7. `1280×720`检查人物位置与帽子安全距，`844×390`检查同一关系和触控可达；
8. 规则、资源契约和容貌专项浏览器回归全部通过后，才进入发布门禁。

AI图像只能用于完整母版或以通过母版为输入的身份保持派生。独立生成一批不共享人物锚点的帽子、衣服和五官再直接叠加，视为结构失败。

## 6. 验收

### 6.1 自动契约

- 二十四张运行资源存在、可解码且均为`1024×1536`；
- 十一类目录各有两个合法值，越界旧档回到默认；
- 相同状态输出相同绘制计划；
- 每一类第二项都产生独立运行层或衣装底像；
- 所有运行资源均由资源目录引用，无缺失与孤儿；
- 缓存版本、入口样式与主模块版本一致。

### 6.2 人工矩阵

- 男女都是十九至二十二岁范围的年轻成人，不出现儿童脸；
- 两套衣装具有明显结构差异，不只换颜色；
- 人物头顶、脸中心、领口、肩线和双手不随换衣漂移；
- 混搭五官与发型时没有第二张脸、肤色椭圆、矩形补片或透明缺口；
- 后背物件位于身体后方，帽子与头发关系清楚；
- 透明边缘没有洋红残边或断裂。

### 6.3 浏览器专项回归

`npm run smoke:appearance`只验证容貌页：

- `1280×720`人物与帽子控制条都位于视口中轴；
- 帽子控制条底边至少早于人物头顶`4px`；
- 十一条控件等大、左右五行镜像、没有禁用箭头；
- 依次点击十一类后，Canvas像素哈希每次都变化且序号显示`2 / 2`；
- 姓名／体貌、第一行、第五行与底部按钮不相撞；
- `844×390`无溢出，帽子仍不遮头，确认按钮完整；
- `390×844`只显示横置提示，页面无运行异常。

自动契约证明结构，矩阵和浏览器截图证明实际观感；三者不能互相替代。

## 7. 后续扩充门禁

从二项扩到八项前，每个新增部件必须：

- 从当前共同母版绘制或重绘；
- 共用同一身体、肤色、脸中心和遮挡顺序；
- 与两个体貌、两套衣装和所有相关部件生成可辨识组合矩阵；
- 不为单个编号增加CSS位置补丁；
- 通过专项浏览器逐项像素变化检查；
- 来源、许可和公开分发权记录完整。

如果某类无法在共同母版上可靠拆分，就维持当前二项，不用数量替代质量。
