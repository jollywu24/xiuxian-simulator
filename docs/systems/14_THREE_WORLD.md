# Three.js 世界呈现

用户要求将现有 Demo 转换为 Three.js 3D 世界。采用官方 WebGLRenderer、OrbitControls、Raycaster 与 InstancedMesh，保留原生 ES Modules 和现有叙事规则，不引入第二套游戏状态或战斗公式。

参考依据：[Three.js 安装](https://threejs.org/manual/en/installation.html)、[OrbitControls](https://threejs.org/docs/pages/OrbitControls.html)、[MIT 许可](https://github.com/mrdoob/three.js/blob/dev/LICENSE)。固定本地运行时版本，随网页分发许可证，不依赖第三方 CDN。采用程序化几何、共享材质和实例化植被；没有选用需要另行授权的角色运行时，也没有引入物理引擎、网络世界或建筑编辑器。

## 接入契约

- 原有 `createInitialState()`、存档主键、剧情和所有 handler 保持权威。
- 3D 模块只接收场景呈现、当前状态和检查对象的回调；坐标、镜头与渲染设置是表现状态，不写入剧情存档。
- 角色移动和浅观察不消耗世界时间；右侧正式行动沿用原规则与消耗。
- 破庙有庙前、大殿、庙后三个连续区域；区域按钮和步行出入口同步到现有区域 handler。
- 已知物件使用世界坐标和射线拾取，交互沿用 `data-action` 事件。故事未揭示的角色不生成可交互入口。
- WebGL2 不可用、加载失败或丢失上下文时保留原来的平面场景、热点和全部故事能力。
- 场景与角色使用确定性几何生成。新增石材与木材贴图通过 imagegen 原创生成，源母版、生成说明和发布 WebP 分开保存。

## 成本与验证

运行时固定 Three.js 0.186.0；材质以两张 1024 像素贴图为主。限制像素比、灯光阴影、雨滴与植被数量，暂停后台渲染，复用单个 WebGL 上下文。场景切换释放几何和场景独有材质。

验证覆盖原有纯规则、发布资源、3D 场景配置及空间移动边界。浏览器视觉检查未执行时必须在交付中明确说明，不能用语法检查代替美术验收。
