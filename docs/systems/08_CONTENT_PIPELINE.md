# SYS-08 内容生产与自动校验系统

## 1. 系统目标

让后续九十八章以“篇章内容包”持续生产，而不是继续把所有正文、条件、状态和选择堆进`wudao-app.mjs`。系统负责内容组织、引用校验、分支巡检、文案边界和发布前检查，不参与玩家运行时的剧情判断。

## 2. 当前问题

当前首章规模仍可由一个核心文件和一个应用文件承载，但继续扩展会产生：

- 场景函数和handler越来越长；
- 同类条件被多次重写；
- 状态字段难以发现重复和冲突；
- 新能力获得后忘记安排兑现；
- 错误跳转只能靠手动通关发现；
- 文档、规则和页面容易产生三套事实；
- 每次修改都要重走大量无关前置剧情。

## 3. 内容目录建议

保持原生ES Modules，不引入构建步骤：

```text
web/
  content/
    manifest.mjs
    arcs/
      third-lady/
        scenes.mjs
        events.mjs
        dialogue.mjs
        outcomes.mjs
      apprenticeship/
      monkey-ruins/
    catalogs/
      npcs.mjs
      items.mjs
      skills.mjs
      locations.mjs
      factions.mjs
      recipes.mjs
  rules/
    event-engine.mjs
    condition-engine.mjs
    effect-engine.mjs
    combat-engine.mjs
    ...
```

现有`wudao-core.mjs`可以逐步拆分；迁移期间保留兼容导出，不一次性重写首章。

## 4. 篇章内容包

每个篇章包必须包含：

| 文件／数据 | 职责 |
| --- | --- |
| 元信息 | 篇章ID、标题、入口、出口、剧情范围 |
| 场景 | 玩家可见地点、人物、正文和行动 |
| 事件 | 条件、状态、期限和结果 |
| 对白 | 按人物与阶段组织的原创转述 |
| 结果 | 资源、关系、伤势、事实和跳转效果 |
| 引用 | 使用的NPC、物品、武学、地点和配方 |
| 测试清单 | 主路线、失败、错过和旧存档入口 |
| 连续性 | 进入前事实、离开后事实和不能提前揭示的秘密 |

## 5. 内容清单

```js
export const CONTENT_MANIFEST = [
  {
    id: "third_lady",
    entry: "shen_third_lady_arrival",
    exits: ["needle_reward", "third_lady_missed"],
    requires: ["chapter_one_complete"],
    scenes: [/* IDs */],
    firstPayoffs: {
      purple_dragon_pill: "third_lady_treatment",
      spring_rain_needles: "first_needle_crisis"
    }
  }
];
```

清单用于加载和校验，不保存进玩家存档。

## 6. 自动校验器

校验至少包括：

### 结构

- ID唯一；
- 场景入口存在；
- 所有跳转目标存在；
- 行动至少有一个结果；
- 使用动作协议的节点必须为每项行动登记稳定动词、对象、意图，并与内容目录行动ID一致；
- 条件和效果类型已注册；
- 内容对象可序列化；
- 没有循环引用。

### 状态

- 新字段有默认值或由通用结构承载；
- 一次性奖励有唯一效果ID；
- 事件存在失败、错过或明确说明只有单结局；
- 回照点存在且可恢复；
- 退出篇章后没有悬空战斗或临时状态。

### 连续性

- NPC在首次登场前未被引用为已知人物；
- 秘密没有早于允许节点显示；
- 武学取得前没有使用；
- 死亡人物不能无解释再次出现；
- 已消耗关键物品不能重复使用；
- 能力首次兑现节点存在且位于取得后一至两个场景。

### 文案边界

玩家文本禁止：

- Demo、P0、原型、测试、构筑、玩家、自动存档；
- 现实、论坛、武道局、其他玩家；
- 归尘门、太虚命盘、乌铜矿和旧版修仙剧情；
- 未转义的动态姓名；
- 超过允许长度的原作连续引文。

文档可以讨论这些边界，校验只扫描玩家内容目录。

## 7. 分支巡检

构建纯规则分支遍历器，不启动浏览器即可检查：

- 从篇章入口能否到达任一出口；
- 是否存在无行动死路；
- 是否存在永远无法满足的行动；
- 是否能重复领取奖励；
- 所有明确死亡是否有命灯处理；
- 只剩一盏灯时是否仍暴露已确证必死重复项；
- 错过和安全退出是否真正可达；
- 关键状态是否在出口写入。

遍历器不需要穷举所有属性组合，按内容包声明的代表状态运行。

## 8. 章节制作流程

每个新篇章按顺序制作：

1. 从`STORY_BIBLE.md`提取已核对事件；
2. 写进入前事实与离开后事实；
3. 选择本篇章验证的一个主要系统闭环；
4. 绘制场景和事件节点；
5. 建立NPC、物品、武学和地点引用；
6. 写条件、成本、结果和错过；
7. 写原创场景转述与对白；
8. 运行结构与文案校验；
9. 写纯规则测试；
10. 接入界面并跑浏览器路线；
11. 更新剧情、设计和系统文档；
12. 发布GitHub并验证线上页面。

## 9. 原著核对记录

每个内容包记录：

- 对应章节范围；
- 使用的官方目录或用户提供正文；
- 已确认事实；
- 仍未确认的场景细节；
- 项目原创转写；
- 因单世界边界删除或替换的内容。

未经正文核对的具体对白、数值和人物私下动机必须标记为待核对，不冒充原著事实。

## 10. 调试入口

开发环境可提供不进入玩家页面的场景启动参数或脚本：

- 以代表状态打开指定篇章；
- 指定命灯、关系、物品和武学；
- 输出状态差异；
- 运行一个动作后序列化结果；
- 从版本3样本存档迁移后进入新篇章。

调试入口不得在公开游戏界面显示，也不能写入正式存档。

## 13. 发布门禁

以下任一失败，不得发布：

- 内容校验失败；
- 纯规则测试失败；
- 受影响浏览器路线失败；
- 玩家文本出现禁止内容；
- 新能力没有近期兑现；
- 存档迁移丢失关键物品或关系；
- 桌面或手机横向溢出；
- 工作区残留浏览器配置、日志或截图；
- README、剧情或系统文档未同步。

## 14. 完成标准

P0完成要求三夫人、拜师和灵猴三个内容包都能通过同一清单加载、同一校验器检查和同一分支巡检器验证；新增第四个篇章时无需修改校验器核心。
