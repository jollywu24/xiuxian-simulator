# SYS-10 战场地图系统

## 1. 文档状态

状态：**初版设计，等待后续专题讨论，尚未接入运行时代码**。

本文先冻结一个方向：

> **战斗需要可视化空间，但不制作完整格子战棋。采用“场景插画＋五至九个离散节点＋人物与敌招覆盖层＋右侧动作确认”。**

当前可玩版本已经拥有六节点路径、敌我位置、三档距离、遮挡、环境对象和敌方行动顺序，但主要通过独立身位图与文字呈现。本文定义它们如何成为左侧场景中可直接理解和操作的统一战场。

本文暂不最终决定推击距离、范围招式形状、节点容量、多人拥挤和同伴完整站位。这些问题列入第18节，后续结合第一张可用战场继续讨论。

---

## 2. 为什么需要战场地图

当战斗只处理“攻击、承伤、使用物品”时，纯文字足够。当前方向已经加入：

- 近距、中距、远距；
- 兵器长度和远程视线；
- 敌招目标与兑现顺序；
- 遮挡、出口和环境对象；
- 换距、绕后、护人和撤离；
- 轻功、真气催动与推拉潜力；
- 杀死、制伏、脱身、救人和取证等不同目的。

如果这些关系只写在按钮说明里，玩家需要反复阅读才能理解“为什么现在能用”。战场地图承担的是规则解释，不只是装饰：

1. 让玩家看见谁在哪里；
2. 让玩家看见敌人准备攻击谁；
3. 让玩家看见移动后会进入什么距离；
4. 让遮挡、出口和危险区域变成可理解对象；
5. 让轻功、兵器、装备和真气在同一空间兑现；
6. 减少右侧叙事栏重复解释位置关系。

---

## 3. 方案取舍

| 方案 | 优点 | 主要问题 | 结论 |
| --- | --- | --- | --- |
| 纯文字战斗 | 内容成本最低 | 空间规则难理解，环境动作像临时按钮 | 只用于无空间决策的短冲突 |
| 插画＋离散节点 | 清楚、适合手机、可复用现有规则 | 每场战斗需要设计节点、路线和安全构图 | **采用** |
| 完整方格／六角战棋 | 精确、战术上限高 | 寻路、动画、关卡、美术、敌方AI和手机操作成本过高 | 第一阶段不做 |
| 自由点击移动 | 画面自然 | 点击坐标难以成为稳定规则，难测试和复盘 | 不做 |

战场看起来是一幅完整武侠场景，规则层只认节点、连接和对象，不认像素距离。

## 4. 与其他系统的边界

| 系统 | 负责 | 不负责 |
| --- | --- | --- |
| SYS-03 战斗 | 行动、敌招、判定、气血、伤势和战果 | 节点坐标与战场渲染 |
| SYS-06 世界地图 | 地点、旅行路线、时段和地点状态 | 一场战斗内部的移动 |
| SYS-07 界面 | 双栏布局、焦点、触控、缩放和动效 | 判断路线是否合法 |
| SYS-09 统一公式 | 伤害、防御、减伤、装备和真气催动 | 战场连接关系 |
| SYS-10 战场地图 | 节点、路线、位置、视线、遮挡、出口、对象与预览 | 独立计算战斗胜负 |

战斗地图和世界行路图是两套不同视图：

- 世界行路图回答“下一程去哪里”；
- 战场地图回答“这一轮站在哪里、能影响谁”。

## 5. 玩家需要理解的规则

第一版只要求玩家理解六件事：

1. 人物站在场景中的一个位置；
2. 相连位置可以移动；
3. 移动通常消耗一点行动；
4. 位置决定近距、中距、远距以及能否看见目标；
5. 环境对象可以提供遮挡、封路或新动作；
6. 点击地图只选择对象，右侧确认后才真正行动。

不向玩家展示：

- 节点ID；
- 像素坐标；
- 寻路权重；
- 碰撞盒；
- 精确米数；
- 高度数值；
- 敌方隐藏路径；
- 调试连接线。

## 6. 战场数据模型

```js
{
  id: "jinling_rain_alley",
  backgroundId: "rain_alley",
  artboard: { width: 1280, height: 1000 },
  nodes: [],
  edges: [],
  objects: [],
  participants: [],
  exits: [],
  rules: {
    distanceBands: "graph",
    lineOfSight: true
  }
}
```

### 6.1 节点

```js
{
  id: "medicine_wall",
  label: "药铺矮墙",
  x: 0.72,
  y: 0.68,
  tags: ["cover", "escape_setup"],
  capacity: 2,
  visibleWhen: [],
  enterWhen: [],
  blocked: false
}
```

- `x/y`是相对母版的归一化视觉坐标，只负责显示；
- 规则位置始终使用节点ID；
- `tags`只记录会改变规则的特征；
- 节点不可达时保留可见，但需要显示原因；
- 节点状态可以在战斗中变为封锁、危险、坍塌或出口。

### 6.2 连接

```js
{
  id: "street_to_wall",
  from: "street_center",
  to: "medicine_wall",
  actionCost: 1,
  bidirectional: true,
  requires: [],
  hazards: [],
  blockedWhen: ["wall_sealed"]
}
```

连接负责：

- 移动是否合法；
- 最短路径；
- 行动消耗；
- 追击路线；
- 单向跳落或攀爬；
- 被环境对象关闭或打开的通路。

不通过CSS连线或画面上是否“看起来能走”判断合法性。

### 6.3 环境对象

```js
{
  id: "alley_lantern",
  label: "风灯",
  nodeId: "eaves",
  state: "lit",
  targetable: true,
  actions: ["snuff_lantern", "break_lantern"],
  visualVariants: {
    lit: "lantern-lit",
    dark: "lantern-dark"
  }
}
```

环境对象必须至少改变一项规则：

- 开放动作；
- 视线；
- 遮挡；
- 路线；
- 站位；
- 敌人意图；
- 撤离条件；
- 证据或战后结果。

只有说明文字、不会影响局面的物件继续作为普通场景热点，不进入战场对象。

### 6.4 参战者

```js
{
  actorId: "player",
  nodeId: "street_center",
  side: "player",
  visible: true,
  stateTags: []
}
```

节点ID是参战者位置的唯一事实来源。动画可以沿曲线移动，但结算前后必须落在合法节点。

## 7. 距离、移动与交战

### 7.1 三档距离

第一版由图最短路径归纳：

| 最短路径 | 距离 |
| --- | --- |
| 同一节点 | 近距 |
| 相隔一条连接 | 中距 |
| 相隔两条及以上连接 | 远距 |

特殊兵器、垂直节点和场景规则可以覆盖距离，但必须写在动作预览中。

### 7.2 移动

- 沿一条普通连接移动消耗一点行动；
- 玩家可以在有剩余行动时继续移动或出招；
- 从近距脱离可能增加代价或触发敌方追击；
- 轻功可以跨越额外连接、忽略障碍或改变脱离代价；
- 真气催动只强化已有移动动作，不创造自由飞行；
- 敌人必须沿相同连接移动，不能因动画直接传送。

### 7.3 占位

第一版允许敌我进入同一节点形成近距交锋。节点默认容量为二，杂兵群可以作为一个单位占位。

容量、夹击和多人拥挤规则仍需通过雨巷纵切验证，暂不扩展为每个角色精确碰撞。

## 8. 视线、遮挡与危险

第一版只保留三种视线结果：

| 结果 | 规则 |
| --- | --- |
| 清晰 | 可以正常使用远程动作 |
| 遮挡 | 远程动作处于不利，或本次伤害获得临时减伤 |
| 阻断 | 不能直接锁定目标 |

视线由节点、对象状态和预先配置的阻挡关系计算，不进行像素级射线碰撞。

危险位置使用具体世界状态表达：

- 火势蔓延；
- 屋瓦将落；
- 河岸湿滑；
- 毒雾；
- 弩手瞄准线；
- 下一轮封锁。

危险区域必须说明触发时机和后果，不能只用红色区域制造压力。

---

## 9. 敌方意图可视化

地图只显示玩家有理由知道的敌招：

- 移动路径：敌人下一步会向哪个节点逼近；
- 攻击线：敌人准备攻击谁；
- 范围：已经看破的扫击、坠物或毒雾区域；
- 封锁：下一轮将关闭的出口或路线；
- 后手：只有通过观察、见闻或死亡记忆才显示。

视觉语义：

| 表现 | 含义 |
| --- | --- |
| 实线箭头 | 已确认的移动或攻击 |
| 虚线箭头 | 推测路径 |
| 赤色轮廓 | 即将受影响的节点或对象 |
| 灰色遮罩 | 当前不可到达 |
| 琥珀高亮 | 玩家当前选择 |

颜色必须同时配合图标、线型或文字，不能只靠颜色区分。

## 10. 点击与确认流程

地图采用“两段确认”：

1. 点击人物、节点或环境对象；
2. 左侧高亮对象和相关路径；
3. 右侧行动区切换为针对该对象的可用动作；
4. 玩家确认动作；
5. 规则层结算行动、位置和敌招；
6. 地图播放表现并更新状态；
7. 结果写入右侧叙事卷轴。

点击地图不会直接消耗行动。再次点击当前对象或点击场景空白处，必须清除：

- 选中态；
- 路径预览；
- 目标高亮；
- 临时说明卡；
- `aria-pressed`状态。

### 10.1 行动预览

确认前至少显示：

```text
移向药铺矮墙
行动1

位置：街心 → 药铺矮墙
距离：与刀客近距 → 中距
结果：获得弩箭遮挡
风险：巷尾退路将在敌方阶段被封锁
```

攻击、轻功、环境和护人动作使用同一预览结构，只显示本次会变化的项目。

## 11. 视觉层级

从下到上：

1. 场景背景；
2. 天气、烟雾、火光等非规则气氛层；
3. 节点与连接；
4. 环境对象；
5. 人物与敌人；
6. 敌方意图；
7. 玩家选择与可达预览；
8. 轨迹、命中、位移和飘字；
9. 临时结果提示。

节点和连接不应长期全部发光：

- 未选择对象时只保留人物、敌人和关键出口；
- 选择移动时显示可达节点；
- 选择攻击时显示合法目标和视线；
- 选择环境对象时降低无关人物与节点亮度；
- 行动完成后恢复简洁战场。

## 12. 桌面与手机布局

### 12.1 桌面与手机横屏

继续使用场景／叙事约二比一的双栏：

- 左侧：战场、人物、敌招、节点与对象；
- 右侧：叙事记录、当前目标、三项推荐行动和详细条件；
- 顶部：地点、轮次、气血、行动与聚气后的真气；
- 右侧可以独立滚动，左侧战场不随叙事滚走。

844×390下：

- 不持续显示节点名称；
- 点击后才显示一个对象名称和路径；
- 敌方单位栏使用小头像、气血和意图图标；
- 触控目标不小于44×44；
- 左侧不得因节点标签撑宽；
- 关键人物、出口和敌招线不得被人物／行囊／武学入口遮挡。

### 12.2 手机竖屏

MVP阶段不制作竖屏战场。页面只显示世界内的横置设备提示，并隐藏所有战斗交互；旋转到手机横屏后继续同一场战斗。竖屏战场的信息顺序与触控布局待横屏战场完成验证后单独设计。

## 13. 美术规格

战场继续复用左侧场景母版原则：

| 项目 | 初版标准 |
| --- | --- |
| 母版 | 1280×1000、5:4、sRGB |
| 背景 | 不带文字、按钮、节点、边框或水印 |
| 坐标 | 节点使用归一化母版坐标 |
| 安全区 | 人物、出口和关键对象避开边缘入口与叙事撕纸 |
| 同场变体 | 光向、镜位、透视和节点坐标保持一致 |
| 状态变化 | 灯灭、坍塌、火势、断索等使用对象变体或独立覆盖层 |

背景图负责地点气氛，人物、敌人、意图、节点和可变化对象尽量使用独立层，避免每个战斗状态重新生成整张背景。

## 14. 雨巷样板

现有六个节点：

| 节点 | 主要作用 |
| --- | --- |
| 巷口 | 初始入口与退路压力 |
| 檐下 | 风灯、遮雨和弩箭视线变化 |
| 街心 | 正面交锋，缺少遮挡 |
| 药铺矮墙 | 远程遮挡与翻墙准备 |
| 巷尾 | 头目、封路和追查方向 |
| 屋脊 | 弩手位置，第一阶段玩家不可到达 |

环境对象：

- 风灯：熄灭后弩手失去锁定；
- 檐柱：提供遮挡或绕身动作；
- 药铺矮墙：成为撤离落点，也可能被头目封锁；
- 湿滑石面：影响普通换位，特定桩功或轻功抵消。

第一轮地图应让玩家直接看懂：

```text
刀客正沿街心逼近
屋脊弩手正在瞄准你
檐下可以灭灯
药铺矮墙可以遮箭，但尚不能立即脱身
```

这张战场是第一份实现样板，不新增第二场地图作为并行试验。

## 15. 内容生产规则

不是所有冲突都需要五至九节点：

| 冲突类型 | 建议空间 |
| --- | --- |
| 瞬间伏击或一次判定 | 纯场景动作，不进入战场地图 |
| 狭室单挑 | 三至五节点 |
| 普通多敌人战斗 | 五至七节点 |
| 重要首领或护送战 | 七至九节点 |
| 城市追逐 | 多张小战场串联，不做一张巨大地图 |

每张战场至少满足：

- 两个位置有不同战术价值；
- 一个敌方意图能被空间行动反制；
- 一个环境对象会改变可见状态和规则；
- 一个真实出口或撤离条件；
- 敌人和玩家遵守相同路线；
- 地图结果会写回伤势、关系、证据或地点状态。

如果所有位置都只改变背景，就不建立节点。

## 16. 存档与纯规则接口

```js
{
  battlefieldId: "jinling_rain_alley",
  actorNodes: {
    player: "street_center",
    knife_assailant: "alley_entrance",
    crossbowman: "roof"
  },
  nodeStates: {
    medicine_wall: "open"
  },
  objectStates: {
    alley_lantern: "lit"
  },
  revealedIntents: [],
  history: []
}
```

当前选中对象、悬停路径和临时说明属于界面状态，不写入长期存档；重载战斗后默认清空选择，但人物位置、对象状态和已经揭示的敌招必须恢复。

纯规则接口建议：

```js
getBattlefield(battlefieldId)
getReachableNodes(actorId, battleState)
getShortestPath(fromNodeId, toNodeId, battleState)
getDistanceBand(actorA, actorB, battleState)
getLineOfSight(actorA, actorB, battleState)
getBattlefieldTargets(actionId, battleState)
previewBattlefieldAction(actionId, targetId, battleState)
resolveBattlefieldMove(actorId, targetNodeId, battleState)
applyBattlefieldObjectAction(objectId, actionId, battleState)
getVisibleEnemyIntents(battleState, knowledgeState)
```

规则层不访问DOM、图片尺寸和动画。所有状态必须JSON可序列化。

## 17. 实施顺序与验收

### 第一阶段：雨巷可读

1. 把六节点直接覆盖到雨巷场景；
2. 人物、刀客、弩手和头目显示真实位置；
3. 点击节点只选择，不立即移动；
4. 右侧生成针对节点或对象的动作；
5. 显示敌方下一步路径和攻击线；
6. 移动后距离、遮挡和出口立即更新；
7. 桌面与844×390通过完整交互检查，390×844通过横置门禁检查。

### 第二阶段：空间动作

- 轻功跨节点；
- 追击和近距脱离；
- 推击、拉扯和护人移动；
- 路线封锁和环境破坏；
- 真气强化移动与护体；
- 同伴参与。

### 第三阶段：按需要扩展

- 少量范围招式；
- 高低节点；
- 多阶段首领地图变化；
- 连续追逐地图；
- 战后地点状态保留。

第一阶段完成信号：

- 玩家不阅读长说明也能指出敌人、出口和遮挡；
- 点击空白处可以清除选择；
- 一次换位真实改变距离；
- 一次灭灯真实阻断弩手视线；
- 一次封路真实关闭撤离；
- 同一战况与动作预览稳定；
- 节点和热点在目标分辨率下落在正确对象上；
- 地图不是必须操作的额外步骤，右侧行动仍可用键盘完成。

## 18. 后续待讨论

后续专题逐项确认：

1. 同一节点最多容纳几名独立角色；
2. 近距脱离是否固定增加行动，还是由敌招产生追击；
3. 推击是一条连接、一个节点，还是根据招式决定；
4. 范围招式按节点、连接还是预设区域表达；
5. 高处是否只是标签，还是独立距离修正；
