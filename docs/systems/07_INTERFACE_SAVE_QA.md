# SYS-07 界面、存档、无障碍与质量保障

## 1. 系统目标

保证八组业务系统在手机和桌面上始终可理解、可操作、可恢复。界面只呈现江湖中的处境、条件和结果；存档必须承受长期内容扩展；测试必须在发布前发现坏跳转、重复奖励和手机布局回归。

## 2. 当前基础与缺口

已有：

- 原生HTML、CSS和ES Modules；
- 单一事件委托与稳定`data-action`；
- 数字键一至九；
- 原生按钮、输入框和键盘焦点；
- 390×844与桌面响应式；
- `escapeHtml()`；
- 本地存档版本3和基础迁移；
- CDP完整浏览器流程。

缺口：

- 后续系统信息密度会远高于首章；
- 单存档无法支持坏档恢复和路线试验；
- 存档字段增长缺少统一迁移表；
- 自动流程只覆盖主要成功路线；
- 条件、伤势、证据、关系和日程缺少统一组件；
- 没有减少动态效果、高对比和屏幕阅读器检查；
- 内容错误不能在发布前统一阻止。

## 3. 信息架构

一个标准场景按以下顺序呈现：

1. 地点、时段和当前身份；
2. 眼前发生的事情；
3. 最危险或最紧迫的变化；
4. 条件、伤势、关系或证据板；
5. 可执行行动；
6. 上一步结果和资源变化；
7. 可折叠的人物卡、物品、武学、日程和记录。

手机端不得让状态栏先占满首屏。玩家进入页面后应先看见困境和至少一个行动。

## 4. 通用界面组件

| 组件 | 内容 | 主要系统 |
| --- | --- | --- |
| 场景头 | 地点、日期、天气、身份 | SYS-01、SYS-06 |
| 条件板 | 已满足、缺失、未知代价、期限 | SYS-01 |
| 行动卡 | 世界内行动、成本、风险和快捷键 | 全部 |
| 结果条 | 物品、时间、伤势、关系和入口变化 | 全部 |
| 战斗意图 | 敌人动作、距离和环境机会 | SYS-03 |
| 病例板 | 症状、推测、已确认病因和危险时钟 | SYS-04 |
| 关系卡 | 关系称谓、共同经历、承诺和已知秘密 | SYS-05 |
| 日程板 | 今日必须、临近窗口、无期限 | SYS-06 |
| 证据册 | 见闻、推测、确证、过期 | SYS-06 |
| 武学卡 | 掌握阶段、可用招式、修炼条件 | SYS-02 |

组件只接收已整理的视图模型，不直接计算业务规则。

## 5. 玩家可见文本规则

- 只出现世界、人物卡、场景、事件、条件、结果和可操作反馈；
- 不出现Demo、原型、测试、构筑、存档版本、事件ID和成功率；
- 不出现现实、论坛、武道局、其他玩家；
- 新名词首次由人物、场景或物品解释；
- 禁用行动说明世界内缺口；
- 成人情节只保留动机与压力；
- 动态姓名、物品和自定义文本经过`escapeHtml()`；
- 调试信息只在开发检查中生成，不渲染给玩家。

## 6. 存档版本4

P0系统骨架落地时把存档升至版本4。建议结构：

```js
{
  version: 4,
  meta: { createdAt, updatedAt, playTime, routeName },
  character: {/* 属性、境界、武学 */},
  inventory: {/* 物品、银钱 */},
  story: {/* 场景、事件、事实、检查点 */},
  world: {/* 日期、地点、地点状态 */},
  relationships: {/* NPC和势力 */},
  conditions: {/* 伤势、毒、心神 */},
  preferences: {/* 字号、动态效果 */}
}
```

不把渲染后的HTML、函数、Map、Set、Date对象或循环引用写入存档。

## 7. 迁移策略

- 每个版本只负责从前一版本迁移；
- `migrateV3ToV4()`把现有扁平字段转入新结构；
- 迁移前先校验基本类型；
- 缺失字段取`createInitialState()`默认值；
- 未识别字段不直接删除，先写入迁移报告；
- 迁移失败保留原始存档并提供重新开始，不覆盖坏档；
- 迁移函数必须可重复执行而不重复奖励。

版本3关键迁移：

- 五维、五禽和宝鱼属性进入`character`；
- 现有武学、医术、炼丹进入统一能力结构；
- 六枚回春丹、银柳木竿、血书、玉佩和银钱进入库存；
- 龙青鱼、曹青、王五、沈福进入关系结构；
- 当前场景和已完成奇遇进入事件状态；
- 命灯检查点迁入`story.checkpoints`。

## 8. 存档槽与恢复

P0继续保留一个自动进度，但增加：

- 写入前内存校验；
- 上一次成功存档备份；
- 读取失败回退备份；
- 显示世界内的“续行”入口，不显示自动保存术语。

P3再增加三个手动旅程槽和关键节点复制，不允许在战斗结算中任意读档绕过命灯。

## 9. 无障碍与手机要求

- 390×844无横向滚动；
- 最小触控目标44×44；
- 正文、条件和行动保持足够对比；
- 不只用颜色区分满足、危险和锁定；
- 焦点顺序跟随视觉顺序；
- 场景切换后焦点回到新场景标题；
- 数字键不抢占输入框；
- 支持浏览器放大至200%；
- 尊重`prefers-reduced-motion`；
- 图标有文本标签；
- 战斗和倒计时不要求快速反应。

## 10. 测试层级

### 纯规则测试

覆盖条件、效果、战斗、伤势、配方、关系、时间、调查和迁移。

### 内容校验

由SYS-08检查节点引用、奖励幂等、首次解释、禁用术语和能力兑现节点。

### 浏览器主路线

每个里程碑至少一条完整成功路线。

### 浏览器风险路线

至少覆盖：

- 一次死亡回照；
- 一次非致命失败；
- 一次错过窗口；
- 一次关系破裂；
- 一次炼丹失败；
- 一次旧存档恢复；
- 一次手机完整操作。

### 布局检查

1280×720、390×844、200%缩放，无横向溢出和关键按钮截断。

## 11. 浏览器流程矩阵

| 路线 | 目的 |
| --- | --- |
| 首章原路线 | 防止已有内容回归 |
| 三夫人完整救治 | 验证P0新系统联动 |
| 三夫人错诊／错过 | 验证失败和事件状态 |
| 第一次战斗死亡回照 | 验证伤势、见闻和命灯 |
| 两套桩功各一条 | 验证成长路线差异 |
| 八月十五准时／迟到 | 验证时间地图 |
| 灵猴非战斗解决 | 验证关系和物品分配 |

## 12. 发布检查

每次修改完成后：

1. 运行规则测试；
2. 运行内容校验；
3. 运行受影响浏览器路线；
4. 检查桌面和手机；
5. 确认运行异常为空；
6. 清理配置、日志和截图；
7. 更新README、设计和系统文档；
8. 提交并推送GitHub；
9. 确认线上地址返回成功且包含新内容。


## 14. 完成标准

P0完成要求版本3首章存档可以无损迁移到版本4；七条浏览器流程在桌面和手机通过；业务规则无需读取DOM；玩家界面没有内部字段、旧剧情或产品术语。
