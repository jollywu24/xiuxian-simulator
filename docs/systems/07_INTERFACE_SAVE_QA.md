# SYS-07 界面、存档、无障碍与质量保障

## 1. 系统目标

保证各组业务系统在手机和桌面上始终可理解、可操作、可恢复。界面只呈现江湖中的处境、条件和结果；存档必须承受长期内容扩展；测试必须在发布前发现坏跳转、重复奖励和手机布局回归。

## 2. 当前基础与缺口

已有：

- 原生HTML、CSS和ES Modules；
- 单一事件委托与稳定`data-action`；
- 数字键一至九；
- 原生按钮、输入框和键盘焦点；
- 390×844与桌面响应式；
- 844×390手机横屏双栏；
- 四处2D场景、可查看物件、人物站位和折叠行路图；
- 场景在左、叙事行动在右的集中布局，以及人物／行囊／武学三个边缘入口；
- 独立全屏行囊、六类图标筛选、二十四格容量、品质底边、数量、银两和条件化使用；
- 独立全屏人物页、九个等大装备槽、二十四格装备行囊、品质底框、分类筛选和即时穿戴／卸下；
- 可回看的右侧叙事卷轴，统一保存旁白、人物对话、玩家选择与当前行动；
- 行动内嵌条件摘要、可展开判定详情，以及普通／重要／危险／不可用四种文字语义；
- `escapeHtml()`；
- 本地存档版本6以及版本2／3／4／5迁移；
- CDP完整浏览器流程。
- 入口样式、主模块及其依赖使用同一发布版本参数，阻止GitHub Pages与手机浏览器缓存混用新旧文件；
- 主模块超过三点五秒仍未渲染时显示世界内恢复入口，玩家可以强制取回最新资源而不是停留在白屏。

缺口：

- 后续系统信息密度会远高于首章；
- 单存档无法支持坏档恢复和路线试验；
- 存档字段增长缺少统一迁移表；
- 自动流程只覆盖主要成功路线；
- 条件、伤势、证据、关系和日程缺少统一组件；
- 没有减少动态效果、高对比和屏幕阅读器检查；
- 内容错误不能在发布前统一阻止。

## 3. 信息架构

一个标准场景按以下顺序呈现：

1. 地点、时段和当前身份；
2. 2D场景、可查看物件和在场人物；
3. 眼前发生的事情；
4. 最危险或最紧迫的变化；
5. 条件、伤势、关系或证据板；
6. 可执行行动；
7. 上一步结果和资源变化；
8. 可折叠的行路图、人物卡、物品、武学、日程和记录。

手机端不得让状态栏先占满首屏。玩家进入页面后应先看见困境和至少一个行动。

桌面与横屏的信息空间固定为两块：场景区只负责地点、人物、热点和当前所见；叙事区以连续卷轴呈现此前旁白、人物对话、玩家选择、当前文字、条件反馈和行动。横屏以1672×941为视觉坐标系等比缩放，场景与叙事宽度约为2:1，超宽或非16:9设备使用留黑而不是分别压缩文字、按钮与间距。热点保存的是原始场景图坐标；界面必须根据背景图的实际缩放、对齐和裁切实时换算显示位置，禁止为单一分辨率另写一套目测坐标。点击场景热点时，原地热点切换为琥珀色双环，由细线连接场景内的半透明“所见”卡；卡片只说明当前发现和察觉依据，不推进右侧剧情，再次点击同一热点、点击场景空白处均会收起，点击其他热点则直接替换内容。选择右侧行动后，旧选项先转为玩家记录，结果旁白紧随其后，“接下来”和下一组选项继续排在同一信息流末端；刷新后以最新玩家记录为锚点，停在右栏约24%高度，不整页替换。资源变化在左侧场景中心以短暂飘字表达，右栏不重复同一数值。新场景渲染后自动滚到“眼下”，但不删除此前经过。人物、行囊与武学放入三个独立边缘入口，不再作为常驻第三、第四块阅读区域；人物与行囊切换到独立全屏层，武学保持轻量抽屉；此前经过直接留在叙事卷轴，不另设重复入口。

### 3.1 左侧场景美术规格

横屏外层画布与左侧场景资产必须分开定义。1672×941只是完整界面标尺；扣除约68像素顶栏并为右侧叙事栏保留33.37%宽度后，左侧场景的实际窗口约为1114×873，宽高比约1.276:1。因此，不再直接把16:9插画作为左侧背景。

| 项目 | 标准 |
| --- | --- |
| 外层界面标尺 | 1672×941，场景／叙事约2:1 |
| 左侧场景母版 | 1280×1000，5:4，sRGB WebP |
| 输出质量 | WebP质量85—90；不得带文字、按钮、热点、边框或水印 |
| 填充方式 | `background-size: cover`、居中对齐；目标横屏的有效裁切应低于2%，其他验收尺寸不得裁掉关键对象 |
| 关键物件安全区 | 横向7%—93%，纵向10%—84%；画面右缘为撕纸分界预留呼吸区 |
| 固定遮挡区 | 左下角为人物／行囊／武学入口预留暗部与低信息密度区域 |
| 同地点变体 | 基础图、人物入场图、受损图等保持同一镜位、透视、物件坐标、光向和色调，只改变剧情要求的对象 |

场景制作先确定必须同时可见的剧情锚点，再生成构图。雨夜破庙的固定锚点为主角、余火、无像供桌与山桃、新砌暗墙、雨中庙门；青衣妇人变体还需保证人物全身位于门内且不遮挡暗墙或余火。不能通过把热点钳制到画面边缘来伪装物件仍然可见。

热点的`x/y`始终描述原始场景母版坐标。渲染层读取母版宽高比，根据当前背景的`cover`缩放、背景对齐和裁切偏移换算实际屏幕坐标；尺寸改变后必须重新换算。热点卡打开后，再次点击该热点或点击场景图空白处，应同时移除卡片、连接线、`selected`状态和`aria-pressed`状态。

### 4.1 全屏行囊

行囊是覆盖设备视口的独立界面，不受场景16:9信箱画框约束。桌面和手机横屏采用约三分之二物品栏、三分之一详情栏；手机竖屏先展示物品栏，再展示详情。顶部固定保留人物、行囊、武学、银两与返回，切到人物或武学时关闭全屏层并打开相应抽屉。

| 项目 | 标准 |
| --- | --- |
| 分类 | 全部、丹药、材料、兵具、信物、线索；入口只显示图标，必须带可访问名称 |
| 分类标题 | 分类图标下方显示当前分类名，不在每个图标旁重复文字 |
| 容量 | 固定二十四格，横屏六列四行；显示“已占格 / 上限”，堆叠数量不额外占格 |
| 物品格 | 只显示物品图，不显示名称；数量位于右下角；品质用细底边表达，不显示品质图例 |
| 详情 | 名称、品质、类型、持有量／堆叠上限、描述与效用；不重复显示物品来处 |
| 使用 | 只有可消耗物品出现使用按钮；条件不足时置灰并显示原因；成功后数量、伤势或饥饿立即同步 |
| 选择 | 打开时优先保持当前分类中的已选物品，否则选择第一件；空分类显示世界内空态 |
| 背景 | 使用独立深色武侠行囊背景，寺院只留边缘暗影、右侧只留抽象墨迹与烟气；物品与文字保持最高对比，不得显示开发字段或内部ID |

物品统一按稳定ID收集、去重并按固定图鉴顺序陈列。旧顶层字段与`p0.items`同时存在时，不得把同一批回春丹显示两次。开场玉佩、血书和山桃必须随玩家查身、食桃等真实动作逐步进入行囊，不能提前泄露。使用规则位于纯规则层，渲染层只负责执行通过校验的消耗和状态反馈。

美术资源统一位于`web/assets/inventory/`：独立背景负责寺院暗影、墨纸与烟气；十六件物品来自同一4×4生成图集并裁成独立方图；回春丹详情使用单独高分辨率静物图；分类图标、银锭、宣纸选中态和空格纹样使用可缩放SVG。运行时不得再使用从确认效果图直接裁下、含有旧边框或文字的图片。

### 4.2 章末江湖留痕

M4开始在篇章收势生成五至八句“江湖留痕”，用于回答玩家做了什么、失去了什么、谁记住了这件事、下一步还能依靠谁。它不是开发总结，也不显示未见路线。

规则：

- 每句话都引用一个已发生事件、人物记忆、关系／身份变化、物品来源或地点状态；
- 点击可展开世界内依据，例如“沈福已失踪；沈家侧门无人再为你开门”；
- 同一事实只生成一次，不用形容词堆叠虚假成就；
- 至少包含一项玩家主动选择和一项永久代价；
- 只汇总业务状态，不在界面层创造新的剧情事实。

### 4.3 已掌握流程的快结算

安全、重复且不存在新判断的日常差事或旅行可以合并为一次结果。只要存在限时窗口、人物请求、关系选择、追踪风险、新能力首次兑现或资源不足，就必须恢复完整交互，不能用快结算跳过有意义的选择。

## 5. 玩家可见文本规则

- 只出现世界、人物卡、场景、事件、条件、结果和可操作反馈；
- 不出现Demo、原型、测试、构筑、存档版本、事件ID和成功率；
- 不出现现实、论坛、武道局、其他玩家；
- 新名词首次由人物、场景或物品解释；
- 禁用行动说明世界内缺口；
- 条件信息直接随选项显示，点击可展开完整说明；
- 普通、重要、危险、不可用分别使用青、金、赤、灰，并同时显示文字状态；
- 成人情节只保留动机与压力；
- 动态姓名、物品和自定义文本经过`escapeHtml()`；
- 调试信息只在开发检查中生成，不渲染给玩家。

## 6. 存档版本6

装备与统一战斗公式落地时把存档升至版本6。当前仍保留顶层兼容字段，并在`p0`嵌套状态中保存当前武学、战斗履历、死劫履历和夜袭计划；顶层新增`equipment`与`characterVitals`，分别保存九个槽位、装备行囊以及跨战斗的当前气血／真气。`fateSeed`固定同一旅程的因果骰，`narrativeLog`最多保留六十四条已发生场景与玩家选择。旧存档缺失种子时根据原有角色与首条事件生成稳定兼容种子，不能因刷新页面改变骰点：

```js
{
  version: 6,
  fateSeed: "一条旅程固定使用的因果种子",
  meta: { createdAt, updatedAt, playTime, routeName },
  character: {/* 属性、境界、武学 */},
  inventory: {/* 物品、银钱 */},
  equipment: {/* 二十四格装备行囊与九个穿戴槽 */},
  characterVitals: { health, qi },
  story: {/* 场景、事件、事实、检查点 */},
  world: {/* 日期、地点、地点状态 */},
  relationships: {/* NPC和势力 */},
  conditions: {/* 伤势、毒、心神 */},
  narrativeLog: [{ id, context, title, lines, choice, choiceSource, choiceKind }],
  p0: {
    battleHistory: [{ battleId, round, action, intent, result, rating, check }],
    battleOutcomeGrade,
    battleEdge
  },
  preferences: {/* 字号、动态效果 */}
}
```

不把渲染后的HTML、函数、Map、Set、Date对象或循环引用写入存档。

## 7. 迁移策略

- 每个版本只负责从前一版本迁移；
- 版本2／3继续先补齐P0默认状态，版本4／5补齐`activeMartial`、`battleHistory`、`deathRecords`与`assailantPlot`，随后统一进入版本6装备迁移；
- 迁移前先校验基本类型；
- 缺失字段取`createInitialState()`默认值；
- 未识别字段不直接删除，先写入迁移报告；
- 迁移失败保留原始存档并提供重新开始，不覆盖坏档；
- 迁移函数必须可重复执行而不重复奖励。

版本3关键迁移：

- 五维、五禽和宝鱼属性进入`character`；
- 现有武学、医术、炼丹进入统一能力结构；
- 六枚回春丹、银柳木竿、血书、玉佩和银钱进入库存；
- 龙青鱼、曹青、王五、沈福进入关系结构；
- 当前场景和已完成奇遇进入事件状态；
- 命灯检查点迁入`story.checkpoints`。

版本4关键迁移：

- 已有武学不重复发放，缺失的当前运用位置取空值；
- 字符串死因记忆转换为兼容死劫履历；
- 夜袭回报条件链从`unknown`开始，不倒推发放鱼鳞铜签；
- 既有战斗、伤势、桩功、关系和终章结果保持不变。

版本6关键迁移：

- 版本2至5统一补齐二十四格装备行囊、九个穿戴槽与安全的初始装备；
- 未知物品ID、错误槽位和重复装备在纯规则迁移时丢弃，不写入玩家界面；
- 当前气血与真气没有旧值时保持`null`，首次派生时再按五维、境界、内功、装备和伤势计算；
- 迁移不改变既有剧情位置、武学、关系、命灯或章节结果。

## 8. 存档槽与恢复

P0继续保留一个自动进度，但增加：

- 写入前内存校验；
- 上一次成功存档备份；
- 读取失败回退备份；
- 显示世界内的“续行”入口，不显示自动保存术语。

P3再增加三个手动旅程槽和关键节点复制，不允许在战斗结算中任意读档绕过命灯。

## 9. 无障碍与手机要求

- 390×844无横向滚动；
- 390×844战斗页的敌方单位栏、战场热点和身位图互不遮挡，阶段条与三项推荐行动在预留手机浏览器底栏后仍完整可见；
- 1672×941标尺下顶栏、2:1分栏、开局三个行动和三个羊皮纸入口的相对尺寸符合确认效果图；
- 844×390横屏无横向滚动，等比缩放后的场景与叙事必须同时在首屏出现；
- 行囊在1280×720、844×390下覆盖完整设备视口，不继承场景信箱留黑；六类图标、二十四格、容量、银两和详情栏不得截断；
- 行囊在390×844下按物品格、详情顺序纵向滚动，不得产生横向滚动；数量必须位于物品格右下角；
- 横屏叙事栏可独立滚动，不能拖走左侧场景；
- 叙事栏默认定位最新行动的阅读锚点，向上滚动可回看先前旁白、对话和玩家选择；近期行文记录最多保留64条，关键关系、死亡、物品与路线仍由结构化状态永久保存；
- 不可用选项保留可读灰色文字，并可展开查看为什么无法执行；
- 最小触控目标44×44；
- 场景热点具备文本标签、键盘焦点和点击后的文字说明；横屏展开卡必须留在场景边界内，不遮挡主角、关键热点和三个边缘入口，连线随画布缩放重算；
- 正文、条件和行动保持足够对比；
- 不只用颜色区分满足、危险和锁定；
- 焦点顺序跟随视觉顺序；
- 场景切换后焦点回到新场景标题；
- 数字键不抢占输入框；
- 支持浏览器放大至200%；
- 尊重`prefers-reduced-motion`；
- 图标有文本标签；
- 战斗和倒计时不要求快速反应。

## 10. 测试层级

### 纯规则测试

覆盖条件、效果、战斗、伤势、配方、关系、时间、调查和迁移。

### 内容校验

由SYS-08检查节点引用、奖励幂等、首次解释、禁用术语和能力兑现节点。

### 浏览器主路线

每个里程碑至少一条完整成功路线。

### 浏览器风险路线

至少覆盖：

- 一次死亡回照；
- 一次非致命失败；
- 一次完整的“我方消耗行动—催动真气或保留真气—提前或自动收势—三名敌人依序行动—下一轮恢复行动”；
- 一次换位改变距离、一次遮挡降低远程伤害，以及一次封锁矮墙改变脱身条件；
- 同一夜战节点读取两次仍得到相同骰点；
- 大成、带伤与失手结果都进入叙事、存档和后续状态；
- 一次错过窗口；
- 一次关系破裂；
- 一次联系人失踪、死亡或被替代后旧入口关闭；
- 一次M4章末江湖留痕，并逐句核对来源状态；
- 一次已掌握安全差事快结算和一次因突发窗口被迫展开完整流程；
- 一次炼丹失败；
- 一次旧存档恢复；
- 一次手机完整操作。

### 布局检查

1280×720、390×844、844×390、1672×941与200%缩放，无横向溢出和关键按钮截断。破庙场景必须在1672×941与844×390下同时看见主角、余火、供桌山桃、暗墙和庙门；四个环境热点中心应落在对应对象上，不得触发边缘钳制；青衣妇人入场后，人物热点仍需落在其身体范围内。打开任一“所见”卡后点击场景空白，卡片、连线和选中状态必须全部消失。全屏行囊额外检查六类图标无可见文字、二十四个格位、品质底边、右下角数量、已用容量、银两、无来处字段、可用物品消耗和场景信箱外的完整横屏覆盖。全屏人物页额外检查小号姓名与境界、气血和真气、五维、防御和减伤、九个等大装备槽、中央人物、二十四格装备行囊、品质底框与穿戴／卸下即时反馈；不得显示潜能或命灯。战斗页额外检查单位栏与场景分区、环境热点与身位节点互不覆盖、阶段、行动与真气始终可见，以及三项去重后的推荐行动在首屏安全区内完整出现。

浏览器主路线同时记录场景ID、热点数量、人物揭示名称、路线节点数量、随身册数量、叙事记录数量、条件详情数量、右栏横向溢出和场景／叙事是否按方向正确分栏，防止视觉层存在但没有跟随剧情切换。
