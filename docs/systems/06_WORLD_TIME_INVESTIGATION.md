# SYS-06 世界时间、旅行与调查系统

## 1. 系统定位

时间是玩家决定“什么时候做什么”的江湖资源。它负责昼夜、行动成本、路线到达、已知时机和当前局面推进，不是隐藏倒计时，也不模拟玩家视野外的完整世界。

核心规则：

> **只有一套玩家可见时间。观察通常免费，真正动手才耗时。时间只推动玩家正在经历的局面。**

系统最终要让玩家自然理解：

- 现在是什么时辰；
- 眼前行动要花多久；
- 这段时间可能令什么局面发生变化；
- 掌握“某时某地”的见闻后，可以主动选择正确时机；
- 错过宽时间窗口会产生新结果，而不是无提示地删掉主线。

## 2. 成熟方案与采用边界

本设计沿用仓库已经完成的成熟游戏拆解，不再另造一套时间模拟：

- 采用《大侠立志传》“时辰会改变地点与人物机会”的价值，但只为关键人物制作有限存在表，不建设全NPC实时路线；
- 采用《烟雨江湖》“地点、时辰、天气共同形成江湖门路”的结构，但舍弃隐藏坐标、精确窄窗口、现实等待和迫使查攻略的前置链；
- 采用跑团场景时钟的节奏：观察免费，承诺行动后推进压力；但场景只读取世界时间，不再向玩家显示第二条行动点或倒计时；
- 采用现有雨夜破庙的手工局面：有限对象、明确代价、阶段事件和失败推进，不为时间系统扩建开放世界模拟。

详细分析见[《大侠立志传》系统设计参考](../HEROES_ADVENTURE_DESIGN_REFERENCE.md)与[《烟雨江湖》系统设计参考](../YANYU_JIANGHU_DESIGN_REFERENCE.md)。

明确不采用：

- 真实分钟和现实时间等待；
- NPC逐分钟移动与玩家不在场时的完整后台剧情；
- 第二套“余裕6/8”“剩余行动点”或场景倒计时环；
- 依赖某一刻精确触发的重要内容；
- 每个地点制作十二个时辰版本；
- 不告知玩家的隐藏任务期限。

## 3. 唯一世界时钟

### 3.1 时间单位

- 一日十二时辰：子、丑、寅、卯、辰、巳、午、未、申、酉、戌、亥；
- 每个时辰八刻；
- 一日九十六刻；
- 第一版日期按每月三十日、每年十二月换算；
- 玩家只看“大曜427年8月12日 · 亥时二刻”一类世界内文字，不显示现代时间。

运行状态只保存绝对刻数与当前天气：

```js
worldTime: {
  totalKe: 147_000_000,
  weather: "rain"
}
```

日期、时辰、当前刻、昼夜和完整文案都由`totalKe`派生。不得同时保存一份可独立变化的`day`、`segment`或场景`elapsed`作为第二事实源。

### 3.2 统一接口

现行纯规则位于`web/world-time.mjs`：

```js
calendarToTotalKe(calendar)
totalKeToCalendar(totalKe)
createWorldTime(saved)
advanceWorldTime(worldTime, cost, changes)
formatWorldTime(worldTime)
migrateWorldTime(savedGame)
elapsedKeSince(worldTime, enteredAtKe, cap)
```

所有接口返回JSON可序列化值，不访问DOM、存储或网络。

## 4. 行动时间成本

基础分类：

| 行动 | 是否耗时 | 示例 |
| --- | --- | --- |
| 浅观察 | 否 | 看火堆、看墙、看人物、查看已有见闻 |
| 区域切换 | 否 | 在庙前、大殿、庙后之间切换 |
| 一般行动 | 一刻 | 细查砖缝、添柴、详细询问 |
| 深入行动 | 两刻起 | 医治、拆解、练功、制作 |
| 旅行 | 按路线 | 官道、水路、山路分别计算 |
| 等待／休息 | 玩家选定 | 后续阶段接入 |

所有耗时操作必须在确认前直接显示，例如：

> **沿空响找出夹层边界　耗时二刻**

执行顺序固定为：

```text
检查条件与资源
→ 承诺行动
→ 支付资源
→ 推进唯一世界时间
→ 检查当前局面跨过的事件阈值
→ 写入行动结果和真实时刻
→ 刷新场景与当前上下文
```

同一行动重复点击不得重复推进时间、事件或奖励。

## 5. 当前局面如何读取时间

场景可以保存进入时的绝对刻数：

```js
templeExploration: {
  enteredAtKe: 147_000_000,
  phase: "quiet"
}
```

局面经过时间始终由以下公式派生：

```text
sceneElapsed = worldTime.totalKe - enteredAtKe
```

它只是规则输入，不是玩家可见的第二条时间。场景内不能再保存可独立推进的`elapsed`或`limit`，也不能再显示“剩余几刻”。

阶段事件可以读取经过刻数、地点、人物状态和对象状态：

```text
事件触发 = 当前地点 + 当前局面状态 + 人物状态 + 世界时间条件
```

时间只决定条件是否成熟，不替玩家决定行动意图。

## 6. 第一阶段：雨夜破庙纵切（已实现）

破庙是统一世界时间的第一个可玩验证场景：

- 入庙时为大曜427年8月12日亥时，天气为夜雨；
- 查看对象、阅读右侧上下文和切换三区不耗时；
- 正式行动按一刻或两刻推进`worldTime.totalKe`；
- 第四刻雨势转急；
- 第七刻门外脚步靠近；
- 第八刻进入次日子时，来客自动入庙，未获救的脚夫死亡；
- 玩家不需要点击“等待来人”；
- 顶部只显示夜雨与当前世界时辰，场景不再显示第二个时钟或剩余刻数；
- 正式行动在右侧历史卷轴记录实际完成时刻和耗时；
- 阶段变化紧随本次行动结果写入历史；
- 破庙状态只保存`enteredAtKe`，旧`elapsed`仅在迁移时读取一次。

示例：

```text
亥时
你醒在漏雨的破庙。

亥时一刻 · 耗时一刻
你拨开湿灰，救回一点余火。

亥时四刻
雨势忽然压低，檐水连成白帘。
```

详细场景规则见[SYS-14 雨夜破庙垂直切片](14_RUINED_TEMPLE_VERTICAL_SLICE.md)。

## 7. 第二阶段：主动等待与休息（待实现）

第二阶段才开放点击时辰盘。等待与休息共用目标时间选择，但意义不同：

- 等待：留在当前位置消磨时间，不提供大量恢复；
- 休息：只在客栈、家宅、安全营地等合理地点开放，按地点和时长恢复；
- 破庙等危险地点最多提供低效小憩，并继续检查局面事件。

选择界面默认按时辰选择，必要时只开放初、二刻、四刻、六刻，不让玩家管理九十六个小刻度。

等待必须逐刻检查玩家当前所在场景。若中途事件满足条件，立即中断等待：

```text
当前戌时三刻
→ 等候至子时
→ 亥时六刻有人叩门
→ 中断等待并进入新局面
```

等待不能绕过来客、袭击、伤势恶化或已知期限。

## 8. 第三阶段：时机、地点与路线（待实现）

### 8.1 已知时机

只有玩家获得相关见闻后，时辰界面才显示提示：

> 【耳闻】沈福常在子时后从货门离开。

未知事件不得提前在时辰盘上留下攻略标记。重要事件使用“子时至寅时”“入夜以后”等宽窗口，或允许后续以更高代价重新进入。

### 8.2 地点时段

地点只配置少量有玩法意义的粗粒度版本。例如秦淮外港：

- 卯至酉：鱼市、牙人和公开货运；
- 戌至寅：夜船、暗货和漕帮人物。

NPC使用场景存在表，只决定进入地点时“在／不在／处于何种状态”，不模拟途中走路。

### 8.3 路线时间

路线在选择前展示耗时和预计到达时间：

```text
官道前往沈家　耗时四刻　到达：子时一刻
紫金河顺流　耗时二刻　到达：亥时七刻
```

路线还可读取体力、饱腹、天气、宵禁、权限、被跟踪风险和途中事件。当前八月十五水路／官道／山路结果会逐步改为读取统一世界时钟，不再保留旧粗时段状态。

## 9. 时间窗口、期限与错过

任务只有在人物或事实明确告知期限时才展示期限。准备执行会跨过已知期限的操作时，界面提醒一次：

> **此举可能错过与沈福的约定。**

玩家可以继续。错过必须进入已写好的后果，例如人物离开、价格变化、证据被取走或关系受损；不得只弹“失败”并要求读档。

## 10. 地图、地点状态与调查

时间系统继续服务既有世界与调查规则：

- 地点因人物和选择改变状态，不复制新地点ID掩盖变化；
- 地图只显示已知地点和路线；
- 调查结果分见闻、推测、确证和过期情报；
- 错误推测允许存在，必须由第二证据验证；
- 跟踪失败优先增加警觉、错误去向或地点风险，不直接强制战斗；
- 身份、人情、口令、换岗、水道和制度流程都可成为进入地点的方式；
- 戒严、天气与NPC时段只有能改变行动、代价或回响时才模拟。

后续跟踪、潜入与戒严仍按本系统原有M4／M5边界推进，不因引入精确刻数扩张成通用城市模拟。

## 11. 玩家界面

- 主场景顶部只显示一个世界时辰与天气；
- 日期可在展开时间界面或需要跨日时显示；
- 右侧动作按钮在执行前写明耗时；
- 时间推进时，场景中央只飘“一刻过去”等短反馈；
- 正式行动完成后，历史卷轴记录真实时刻；
- 重大局面变化可以单独带时刻，但普通旁白无需每句重复；
- 浅观察只替换当前上下文，不写历史，也不推进时间；
- 日程使用“今夜前”“次日辰时”等自然语言；
- 不显示内部`totalKe`、`enteredAtKe`、事件阈值或可靠度。

## 12. 存档与迁移

版本14新增唯一`worldTime`并移除新P0状态中的旧`clock`：

- 版本13及更早的破庙存档，用默认入庙时刻加旧`templeExploration.elapsed`生成世界时间；
- 已进入后续P0且保存了旧粗时段的存档，将黎明、上午、午后、黄昏、夜映射到卯、辰、申、酉、亥；
- 破庙旧`elapsed`换算为`enteredAtKe`后不再保存；
- 既有姓名、出身、剧情、人物、装备、武学、物品、见闻和奖励不变；
- 迁移不得重复触发阶段事件或重复发奖。

## 13. 分阶段验收

### 第一阶段（已实现）

- 十二时辰、每时辰八刻和跨日换算正确；
- 新档与旧档都只有一个`worldTime`事实源；
- 破庙观察免费，正式行动推进一至两刻；
- 第四、七、八刻事件跨阈值时按顺序触发；
- 顶部时辰、行动反馈和历史记录显示一致；
- 场景没有第二个可见时钟、余裕或剩余刻数；
- 旧档迁移到版本14后不保留破庙`elapsed`和P0旧`clock`。

规则测试：`tests/world-time.test.mjs`、`tests/temple-exploration.test.mjs`、`tests/p0-systems.test.mjs`。

### 第二阶段

- 可以等候至目标时辰；
- 合理地点可以休息并恢复；
- 等待途中当前场景事件会中断；
- 跨日提示清楚，不会跳过已知期限。

### 第三阶段

- 已知时机来自见闻而不是攻略提示；
- 关键地点至少有一组昼夜差异；
- 路线显示耗时和到达时刻；
- 错过窗口会推进可见后果；
- 关键NPC只实现有限存在表。

## 14. 一句话定义

> **时间不是催玩家赶路的倒计时，而是玩家用来决定何时观察、动手、赶路与等人的江湖资源。**
