# 《博德之门3》系统设计拆解与《大曜江湖》适配参考

更新日期：2026-07-15

本文是内部设计参考，不是玩家可见文案，也不是对《博德之门3》的玩法复刻方案。分析对象以正式版的稳定系统为主，结合 Larian 官方产品说明、社区更新、补丁说明、GDC 议题简介和开发者访谈；所有迁移建议都服从本项目“纯高武、单人叙事、条件可见、代价真实、新能力尽快兑现”的既有边界。

## 1. 结论先行

《博德之门3》最值得本项目借鉴的，不是 D20、四人小队、海量职业或三维环境，而是以下设计公式：

> **有限而稳定的行动语法 × 手工制作的具体局面 × 可持续回响的世界状态 = 玩家感受到的自由。**

这里的“自由”不是为每个选择续写一条完全独立的长线。更常见的做法是：

1. 让身份、能力、物品、位置、关系和情报成为可复用输入；
2. 让一个局面接受谈判、潜行、调查、准备、战斗、撤退等多种解法；
3. 允许失败、错过、人物死亡和资源损失改变后续状态；
4. 让不同路线在必要时重新汇合，但保留伤势、债务、关系和世界认知的差异；
5. 在后续人物反应、地点变化、能力入口和结局回顾中再次确认玩家做过什么。

对《大曜江湖》的直接判断如下。

| 判断 | 对本项目的意义 |
| --- | --- |
| 最应采用 | “局面”作为内容生产单位；同一能力跨对话、调查、战斗和旅行复用；失败继续推进；人物与世界记住关键结果 |
| 应压缩采用 | 身份反应、路线探索、战斗准备、休息回响、关系立场和可配置的信息透明度 |
| 不应照搬 | 通用 D20 随机判定、四人队伍、多人协作、职业海洋、三维物理与表面模拟、海量装备、频繁读档试错 |
| 当前最重要的落点 | 把“曹青离场—沈福反目”制作成第一个跨关系、经济、追踪、调查和战斗的持久状态局面 |
| 生产侧最重要的落点 | 在内容目录中加入局面输入、稳定事实、解法矩阵、结果状态、回流节点和验证清单，而不是继续增加专用分支 |

本文最终建议不是“把网页文字冒险做成小型 BG3”，而是借用其最小可迁移原则：

> 玩家获得的每一项能力，都应成为解决问题的新动词；玩家承担的每一个结果，都应成为世界后续反应的新条件。

## 2. 证据边界与分析口径

### 2.1 三类信息

本文区分三类内容：

- **已核对事实**：来自 Larian 官方页面、官方更新与补丁说明；
- **开发者解释**：来自 GDC 议题简介或对 Larian 开发者的公开访谈；
- **本文推导**：根据前两类资料与游戏公开结构做出的设计归纳，均以“本文判断”“可视为”或“建议”表述。

### 2.2 不做的事情

本文不承担以下职责：

- 不罗列全部职业、法术、装备、任务和结局；
- 不把 D&D 5e 规则改写成项目规则书；
- 不以销量、奖项或内容总量证明所有设计都适合本项目；
- 不根据未公开的内部代码猜测 Larian 的具体实现；
- 不以模组、攻略 Wiki 或玩家口耳相传作为核心系统事实来源；
- 不建议引入多人、队伍构筑、开放世界或许可素材。

### 2.3 参考版本

分析以 2023 年正式版形成的系统骨架为主，也引用正式版之后的荣誉模式、自定义模式、尾声和流程修复，用来观察同一套状态系统如何扩展以及组合复杂度如何产生维护成本。补丁后的功能不等同于首发设计，本文只提炼其长期有效的设计信号。

## 3. 系统总图：自由来自五层相乘

《博德之门3》的官方介绍把自由探索、身份反应、回合战斗、环境互动、人物关系和世界记忆放在同一产品承诺中。本文将其压缩为五层：

```text
身份层
种族／职业／背景／起源／既往选择
        ↓
行动层
交谈／调查／潜行／移动／环境互动／战斗／消耗物
        ↓
局面层
人物目标＋空间结构＋资源压力＋可变化对象＋失败出口
        ↓
状态层
人物生死／关系／任务事实／地点变化／秘密／资源／时间
        ↓
回响层
新选项／新路线／营地谈话／传闻／敌意／援助／结局回顾
```

任何一层单独存在都不足以形成自由：

- 只有身份，没有重复反应，车卡就只是开场装饰；
- 只有很多按钮，没有可变化对象，动作就只是同义文案；
- 只有局部分支，没有持久状态，选择就无法积累；
- 只有状态，没有后续可见回响，玩家就不知道世界记住了什么；
- 只有大量回响，没有稳定生产边界，内容和测试成本会失控。

《大曜江湖》已经具备五层的纵切基础：

| BG3 抽象层 | 本项目已有基础 | 下一步缺口 |
| --- | --- | --- |
| 身份层 | 出身、初心、五维、逆天改命、武学、见闻 | 身份与既往行动跨篇章复用不足 |
| 行动层 | 选择按钮、调查、炼丹、钓鱼、旅行、文字战斗 | 动词仍多为场景专用，跨系统组合较少 |
| 局面层 | 破庙、丹房、夜袭、灵猴遗迹 | 旧章节仍以线性 screen 与专用 handler 为主 |
| 状态层 | 物品、关系、伤势、时间、地点、死因、事件状态 | 长期势力、联系人、秘密传播和追捕仍待建设 |
| 回响层 | 条件板、资源变化、关系反馈、结尾记录 | 中远期人物反应和地点变化还不够密集 |

因此下一阶段不应先扩大世界，而应提高五层之间的乘法关系。

## 4. 核心循环：准备不是前戏，而是解题的一部分

### 4.1 短循环

《博德之门3》的短循环可以概括为：

```text
观察局面
→ 发现可以利用的人、物、位置和条件
→ 选择动作并支付行动、法术、物品或暴露风险
→ 判定或执行
→ 立即看到位置、生命、关系、资源或事件状态变化
→ 重新评估局面
```

官方战斗与潜行说明特别强调，玩家可以在探索中主动切入回合制，利用位置、光照、巡逻和陷阱为高风险行动做准备。开发者对战斗设计的解释也把玩法描述为“风险缓释”：玩家通过站位、环境和能力降低单次坏骰决定全局的概率。

### 4.2 中循环

中循环不是“接任务—打怪—领奖”，而是：

```text
进入一个有矛盾的地点
→ 认识人物目标与限制
→ 收集情报／结交人物／准备物品／寻找路线
→ 选择解决方式
→ 接受成功、部分成功、失败或错过
→ 地点和人物进入新状态
```

这解释了为什么非战斗解法也必须获得承认。Larian 在早期更新中专门补上了和平、对话和环境解法的经验奖励，并调低了会因一次高难判定锁死整个局面的情况。

### 4.3 长循环

长循环是玩家身份与世界记忆互相塑造：

```text
人物选择形成身份
→ 身份打开特殊解法
→ 解法造成长期结果
→ NPC与世界确认结果
→ 新关系、新敌人和新能力改变下一局面
```

### 4.4 对《大曜江湖》的改写

本项目的核心循环已经是：

> 看见奇遇条件 → 支付资源、关系或命灯 → 获得武学和门路 → 立刻用新能力打开下一条路。

BG3 提供的补强不是替换这条循环，而是为“看见条件”和“打开下一条路”之间增加更多主动准备：

- 条件不只读最终属性，也读见闻、地点、时段、伤势、关系记忆和物品来源；
- 同一个门槛至少允许两种准备方式，而不是只有刷数值；
- 失败后保留已经获得的信息，让下一次选择发生变化；
- 结果至少改变资源、关系、人物去留、地点状态、后续入口中的一项；
- 新武学在一至两个场景内至少改变一次可选动作或风险结构。

## 5. 人物车卡：身份必须持续参与世界

### 5.1 BG3 的设计价值

官方资料把角色身份放在体验中心：自建角色以种族、职业、背景和外观形成身份，预设起源角色则把个人秘密、欲望和主线纠缠在一起。官方还明确说明，种族、职业等会产生不同反应；起源角色既可作为主角，也可作为同伴存在。

重要的不是选项数量，而是身份会重复改变：

- 对话选项；
- 可识别的信息；
- 某些人物的第一印象；
- 解决问题的合法性；
- 资源和技能组合；
- 个人剧情和结局解释。

### 5.2 “自建”与“预设”的折中

BG3 同时提供完全自建角色和带强叙事的起源角色。本文判断，这解决了角色扮演的两种需求：

- 自建角色给玩家投射空间；
- 起源角色保证人物债务、秘密和戏剧抓手。

《大曜江湖》已经采用更适合文字单人叙事的折中：默认主角陈司命拥有明确身世谜团，同时允许玩家选择出身、初心和五维。无需再增加多名可选主角。

### 5.3 本项目的身份复用规则

每一个开局选项都应至少满足以下两项：

1. 在首章提供一次明显不同的判断或行动；
2. 在后续篇章再次被一个 NPC、地点或门槛识别；
3. 改变一种资源获取方式；
4. 改变一种失败后的恢复方式；
5. 改变一个人物对主角行为的解释。

建议把身份反应分成三类：

| 身份输入 | 适合改变什么 | 不应只改变什么 |
| --- | --- | --- |
| 出身 | 旧识、行业知识、门路、起始债务 | 一句寒暄 |
| 初心 | 面对诱惑与责任时的自我解释、关系立场 | 固定善恶值 |
| 五维与武学 | 可执行动作、风险、观察深度、战斗解法 | 纯成功率 |
| 逆天改命 | 条件信息、重分方案、因果代价 | 自动奖励 |
| 死因与见闻 | 重进局面的特殊警告、反制动作 | 单纯收藏条目 |

### 5.4 重分的真正作用

BG3 在早期开放重置职业构筑，官方解释是鼓励试验，避免玩家因不了解庞大规则而被早期错误永久惩罚。

本项目已有更有叙事意义的版本：玉佩点数重分和“逆天改命”。应继续保持以下差异：

- 重分发生在明确因果节点；
- 重分支付资源、机会或长期代价；
- 重分服务眼前难题，不变成随时切换最优解；
- 重分后的新能力立刻获得一次亲手兑现；
- 不引入可无限重置的职业菜单。

## 6. 判定与失败：把随机命运改写成风险管理

### 6.1 BG3 的判定结构

BG3 以 D&D 5e 的属性检定、熟练、优势／劣势、修正值和灵感重掷构成可见判定。其设计价值不在骰子动画本身，而在四件事：

1. 玩家知道哪些能力影响结果；
2. 玩家可以在事前准备与事中资源投入之间做取舍；
3. 失败通常产生后果，不等于游戏停止；
4. 某些不可逆局面仍保留真正风险。

官方在早期更新中明确调整了会因一次高难对话判定锁死内容的情况，但没有取消失败；正式版前的官方说明则强调“没有错误答案，但有大量后果”。

### 6.2 为什么不能直接移植 D20

通用 D20 不适合当前《大曜江湖》：

- 单人角色缺少四人队伍提供的能力冗余；
- 当前核心乐趣是看见条件并改写条件，不是反复碰概率；
- 命灯已经承担高风险回照，若再叠加高频随机死亡，会稀释命灯意义；
- 浏览器文字流程容易被读档试错支配；
- 玩家更难从纯文本中判断一次坏骰是否公平。

### 6.3 建议采用的四段式结果

本项目应优先使用可解释的条件结果：

| 结果 | 规则 | 例子性质 |
| --- | --- | --- |
| 完整成功 | 满足核心条件，并支付正常代价 | 取得目标且保住关系或资源 |
| 带价成功 | 条件不足一部分，但可追加资源、暴露或债务 | 达成目标，同时受伤或欠下人情 |
| 失败推进 | 未达成眼前目标，但获得信息、改变地点或进入替代路线 | 错过人物，却知道新的追踪方向 |
| 明确错过／死亡 | 玩家已看见足够警告，仍选择承担 | 事件永久关闭或消耗命灯回照 |

如果未来加入随机判定，应限制为“已满足行动资格之后的风险波动”，并允许玩家通过准备、物品、关系或代价改变结果区间，而不是用随机数代替条件设计。

### 6.4 条件板的标准

条件板不应只显示“能／不能”，而应显示：

- 你已经确认的进入条件；
- 仍未知但可调查的条件；
- 本次行动会支付的资源；
- 已知的失败类型；
- 可以降低风险的准备；
- 为什么当前不能采用某个方案。

逆天改命的优势应是看见更多条件关系和可调整方案，不是提前剧透所有结果。

## 7. 探索与地点：把三维空间翻译成路线语法

### 7.1 BG3 的空间设计价值

官方产品页和战斗说明反复强调垂直空间、跳跃、攀爬、推击、潜行、光照与环境互动。探索中可主动切入回合制，让巡逻、陷阱和时间敏感机关从即时操作变成可规划问题。

这套设计的关键不是三维地图，而是：

- 地点中存在多个可辨认层次；
- 通用动作在许多地点复用；
- 位置改变战斗、潜行和发现；
- 环境对象既是叙事物，也可成为工具；
- 探索准备会带入后续冲突。

### 7.2 文字游戏的等价物

《大曜江湖》不需要坐标和自由移动模拟。可把“垂直空间”翻译成路线层：

| BG3 空间语言 | 本项目等价语言 |
| --- | --- |
| 高处、低处、侧翼 | 官道、水路、屋脊、地道、内院、后山 |
| 光照与视野 | 天色、灯火、遮蔽物、熟人耳目、警戒程度 |
| 跳跃与攀爬 | 轻功、体魄、工具、地图见闻 |
| 环境对象 | 药炉、门闩、船索、香灰、尸痕、雨水、机关 |
| 强制回合制 | 危险窗口中的离散行动轮次 |
| 队伍拆分 | 不采用；改为提前布置、联系人协助或多地点取舍 |

### 7.3 地点不是选路菜单

一个地点至少应包含：

1. 一个眼前困境；
2. 一个可调查事实；
3. 一个可改变的环境对象；
4. 两条以上真实路线；
5. 一个与时间或警戒有关的变化；
6. 一个能被近期新能力改变的入口；
7. 一个离开后仍保留的地点状态。

### 7.4 路线的真实差异

路线差异不能只是换一段描述。不同路线至少改变一项：

- 抵达时间；
- 体力、饱腹、伤势或消耗品；
- 是否被看见；
- 遇见谁；
- 掌握什么情报；
- 后续战斗位置或先手；
- 地点的敌意和可重复访问状态。

紫金河水路已经是正确范例：心法不是加一行属性，而是改变能否及时抵达沈家的路线。后续轻功、医术、打鱼杆法、桩功和针法都应按同一标准设计路线兑现。

## 8. 战斗：准备、目标和环境比招式数量重要

### 8.1 BG3 的战斗骨架

官方资料确认其战斗建立在回合制、先攻、优势／劣势、修正值、环境互动和团队行动顺序之上。开发者访谈进一步说明：

- 玩家可以充分思考，但动作执行需要快速；
- 相邻的同阵营回合允许灵活组合；
- 多数冲突可以通过交谈或潜行绕开；
- 战场位置与环境能改变相同敌人的解法；
- 首领设计应回应玩家能力，而不是只增加生命和伤害；
- NPC 是否存活会继续改变后续内容。

### 8.2 对本项目最有价值的六条原则

1. **战斗前准备属于战斗。** 调查杀招、选择地点、服药、布置退路都应改变首轮局面。
2. **每场战斗有一个独特问题。** 保护、拖延、取物、逃离、制伏、隐瞒身份都比单纯清空生命更有记忆点。
3. **敌人有可读意图。** 玩家应能看见正在蓄力、试探、封路、呼援或针对伤处。
4. **环境提供有限但强力的动作。** 一场战斗保留一至三个关键环境对象即可。
5. **撤退和非杀结果是正式结果。** 逃离、制伏、杀死应改变追查、关系、秘密和资源。
6. **首领改变规则，不只放大数字。** 新阶段应改变行动窗口、可用位置、保护目标或已知情报的价值。

### 8.3 不采用队伍行动经济

四人队伍和多人同步行动不符合项目边界，也会削弱陈司命的单人身世与债务叙事。可以保留的只有抽象价值：

- 同一轮次允许先准备再出手；
- 联系人协助作为一次性资源或世界状态，不作为永久可控队友；
- NPC 有独立目标，可能帮忙、撤退、背叛或被保护；
- 多角色冲突用敌人意图和优先目标表达，不做队伍编成。

### 8.4 战斗信息最小集

每回合至少让玩家知道：

- 敌人当前意图；
- 主角可用动作类别；
- 当前伤势和资源限制；
- 哪个条件使动作变强、变弱或被锁；
- 逃离、制伏和杀死是否仍可达成；
- 上一动作造成的具体状态变化。

当前春风针夜战已经具备敌人意图、左袖杀招和三种结果。下一场首领战应重点增加“场地与目标变化”，而不是先扩展大规模招式表。

## 9. 叙事局面：收束目标，开放过程

### 9.1 “局面”比“分支树”更准确

BG3 的公开表现容易被描述成巨大分支树，但开发者对生产流程的解释更接近“可能性盒子”：区分不受玩家决定影响的内容与需要因玩家决定重新检查的内容，从核心想法开始，逐步扩展不同接近方式，并为常见“如果玩家这样做呢”准备系统支持。

本文把一个局面定义为：

> 在一个有限时间和地点内，多名人物带着不同目标，玩家可以调用已有身份、能力、物品、关系和环境对象改变结果的一组状态变化。

### 9.2 稳定事实与可变结果

每个局面必须先写稳定事实：

- 这个局面为什么现在发生；
- 哪些人物目标不能随路线改变；
- 哪条信息必须在本篇章揭示；
- 哪个世界变化是后续剧情所需；
- 玩家最迟可以在哪里重新接回主线。

然后再写可变结果：

- 谁活着、受伤、离开或改变立场；
- 玩家掌握多少真相；
- 付出哪一种资源；
- 哪个地点变得可用、危险或永久关闭；
- 哪个联系人、敌人或债务进入后续；
- 玩家以何种身份进入下一个共同节点。

### 9.3 汇合不等于取消选择

不同路线可以抵达同一后续地点，但必须携带不同状态。例如同样抵达城中：

- 一条路线带伤、但没有暴露；
- 一条路线得到证据、但欠下人情；
- 一条路线杀死目标、导致追捕升级；
- 一条路线错过目标、但保住资源和另一段关系。

后续文本、可用动作或人物态度至少要确认其中一项差异。

### 9.4 失败必须有作者意图

失败不能只写“你失败了”。每个失败出口应属于以下一种：

| 失败类型 | 继续方式 |
| --- | --- |
| 信息失败 | 得到错误、不完整或迟到的结论，后续可被新证据纠正 |
| 资源失败 | 目标仍可追求，但需要支付伤势、银钱、物品、潜能或时间 |
| 关系失败 | 人物仍存在，但入口、价格、信任或合作方式改变 |
| 时间失败 | 事件错过，世界进入新状态并开放追查或善后 |
| 生死失败 | 消耗命灯回照，保留死因见闻并改变可选动作 |
| 永久结果 | 玩家在充分警告后主动承担，不提供伪装成回照的撤销 |

## 10. 人物关系：人物有立场，不是奖励条

### 10.1 BG3 的关系设计价值

Larian 官方说明强调：同伴拥有自己的价值判断，会对玩家、其他人物和势力选择作出反应；不同关系沿着不同人物弧光变化，不以“顺从就领奖”作为唯一逻辑。官方甚至明确提出，挑战或反对人物也可能是关系的一部分。

营地承担两种功能：

- 恢复资源与调整同行者；
- 让人物对当天事件作出更私密的反应。

因此关系不是单一数值，而是“行为记忆＋人物立场＋剧情阶段＋亲密程度”的组合。

### 10.2 本项目已有优势

《大曜江湖》的多维关系已经比单一好感更适合文字叙事：

- 情分说明愿不愿亲近；
- 信任说明愿不愿交付秘密和性命；
- 人情债说明谁欠谁；
- 戒心说明对方是否防备主角的动机和手段。

下一步不是增加更多通用维度，而是让人物立场参与判断。

### 10.3 关系判定公式

建议关系场景读取：

```text
当前关系维度
＋人物见证过的关键行为
＋人物自己的底线与欲望
＋当前剧情阶段
＋秘密是否已知、由谁告知
＝本次反应与可用行动
```

这意味着：

- 未被人物看见或得知的行为，不应自动改变其态度；
- 高情分不能覆盖严重背叛；
- 高戒心不等于敌意，也可能让人物更尊重主角的能力；
- 人情债可以迫使合作，但不能自动产生信任；
- 同一句拒绝，对不同人物和不同阶段应有不同解释；
- 关系阈值必须与事件里程碑共同决定重要场景。

### 10.4 不建立永久营地

永久营地和可控同伴不符合本项目。可采用“阶段性落脚点”：

- 丹房、客舍、帮口、医馆或临时藏身处；
- 休息时结算当天行动与人物反应；
- 人物因剧情加入、离开、提供服务或留下消息；
- 落脚点状态随人物去留和势力变化而改变；
- 休息会推进时间，可能错过窗口，不是免费领取剧情。

## 11. 成长、物品、炼制与休息：每项资源都要服务选择

### 11.1 构筑深度来自组合，不只来自数量

BG3 以大量职业、子职业、法术和动作提供构筑空间，并允许多职业和早期重置。对本项目可迁移的不是数量，而是三条原则：

1. 能力有明确行动身份；
2. 不同能力可以共同改变一个局面；
3. 新玩家犯下早期构筑错误后仍有叙事合理的修正机会。

《大曜江湖》应控制在少量高价值动作：

- 每门武学至少有一种战斗用途；
- 至少一部分武学拥有调查、旅行、交涉、治疗或准备用途；
- 两门能力组合时改变解法，不只是把数值相加；
- 高阶能力优先扩大动作边界，再提高数值上限。

### 11.2 物品应是动词携带物

物品只有在以下情况下值得存在：

- 提供一次新动作；
- 改变已知动作的代价或风险；
- 证明身份、承诺、来源或债务；
- 作为调查证据；
- 在炼制或治疗中形成可追溯因果；
- 让地点或人物进入新状态。

纯卖钱杂物、只有小幅数值差的装备和无后续用途的收藏品不应扩张。

### 11.3 炼制的适配

BG3 的炼金把野外材料转成提取物，再制成药剂、毒药和涂油，核心用途是为之后的战斗做准备。它是轻量支持系统。

本项目的医术与炼丹是主线能力和人物关系的重要组成，不能压缩成自动配方菜单。可借鉴的是：

- 材料来源决定可用性与人物后果；
- 炼制发生在风险之前，构成准备选择；
- 成品用途在短时间内兑现；
- 配方、品质和失败结果都可追溯；
- 消耗品改变解法，不只回复数值。

### 11.4 休息的适配

BG3 用短休、长休和营地物资恢复战斗资源，同时触发人物场景。其优点是把资源节奏和关系叙事放进同一行为；风险是玩家可能为了看剧情频繁休息，或担心休息错过事件。

本项目应保持更清楚的时间因果：

- 休息恢复体力、饱腹或伤势中的明确部分；
- 休息推进时段或日期；
- 即将错过的事件必须给世界内警告；
- 人物回响按当天关键事件排队，但避免无提示积压；
- 同一场景不能因重复休息重复发奖；
- 命灯回照与普通休息严格分离。

## 12. 信息与界面：复杂规则必须变成可操作反馈

### 12.1 BG3 的可见性策略

官方更新展示了多种降低复杂度的做法：

- 把灵感点显示在界面中；
- 把同一法术的不同等级收进一个展开入口，减少热栏拥挤；
- 提供对话历史；
- 在战斗日志中按轮次分组；
- 通过自定义模式允许隐藏难度值、敌人生命或失败的察觉检定；
- 在字幕字号、背景和提示频率上提供可调节选项。

共同原则是：**先决定玩家此刻需要做什么判断，再决定暴露多少规则。**

### 12.2 本项目的信息层级

建议把玩家信息分为四层：

| 层级 | 玩家看见什么 | 载体 |
| --- | --- | --- |
| 眼前行动 | 当前能做什么、支付什么、已知风险 | 行动按钮与条件板 |
| 即时结果 | 数值、关系、伤势、地点和时间变化 | 结果反馈条与叙事 |
| 当前局面 | 人物目标、已知事实、未解决问题 | 场景摘要与见闻 |
| 长期履历 | 关键选择、死因、承诺、敌人、门路 | 人物卡与江湖记录 |

### 12.3 行动按钮规格

一个复杂行动的按钮与邻近说明至少包含：

- 世界内动作名称；
- 已知前置条件；
- 明确消耗；
- 风险类别；
- 被锁时的世界内原因；
- 数字键编号；
- 执行后的资源和关系变化。

禁止把内部字段、概率公式、内容阶段名或产品术语暴露给玩家。

### 12.4 记录不是补丁说明

对话历史和战斗日志的价值是帮助玩家恢复情境。项目内的记录应使用故事语言：

- “你答应替沈福保守银子的来源”；
- “王五亲眼见你放回幼鱼”；
- “左臂旧伤令出针慢了一线”；
- “八月十五已过，破庙山道不再有猴群脚印”。

不要显示 `flag=true`、`relationship +5`、`event failed` 等内部表达。

## 13. 难度、存档与死亡：尊重不同玩法，但不稀释因果

### 13.1 BG3 的两种方向

正式版后的荣誉模式提高首领变化并限制反复读档，自定义模式则允许玩家分别调整信息透明度、恢复、死亡豁免等规则。这说明难度不只是敌人数字，也可以来自：

- 信息是否完整；
- 失败能否撤销；
- 资源恢复速度；
- 首领是否拥有新行为；
- 玩家是否知道某次暗中检定发生过。

### 13.2 本项目的取舍

当前不应制作多套难度模式。双灯照命已经提供独特且与故事一致的风险框架：

- 死亡消耗有限命灯；
- 回到最近因果节点；
- 保留死因见闻；
- 重进后改变条件信息和行动方案；
- 命灯耗尽后不再显示无意义的重复必死选项。

建议只借鉴“难度由信息、撤销和敌人行为共同构成”的认识，用于检查每个篇章：

- 玩家是否提前得到足够警告；
- 命灯是否换来真正的新信息；
- 首领是否因路线或准备改变行为；
- 失败是否有除读档外的继续方式；
- 资源压力是否可预测而非突然扣除。

## 14. 内容生产：从分支写作转为局面制作

### 14.1 可核对的 Larian 生产信号

GDC 议题简介显示，BG3 的规模和反应性迫使工具、团队和工作方式持续调整。Larian 关联主创在公开访谈中把内容过程描述为：

```text
叙事提案
→ 白盒
→ 橙盒
→ 完善
```

同一访谈还提到：

- 从核心点子向不同接近方式扩展；
- 预先列出常见的“如果玩家……”；
- 调整系统，让编剧／脚本人员不用为常见能力每次重新发明处理；
- 过于昂贵或过于疯狂的方案需要舍弃；
- 脚本人员同时承担设计协作，而非只执行文本；
- 多人和不同路线显著增加连续性检查成本。

### 14.2 本项目的四阶段流程

本项目可压缩为：

| 阶段 | 交付物 | 通过条件 |
| --- | --- | --- |
| 局面提案 | 人物目标、稳定事实、玩家困境、新能力兑现 | 能用一段话说明为什么值得玩 |
| 规则白盒 | 输入状态、行动、条件、效果、失败、回流 | 纯规则测试可跑，分支不会坏跳转 |
| 文本完整 | 场景、人物反应、世界内原因、结果反馈 | 每个行动有真实后果且无产品语言 |
| 视觉完善 | 渲染、模式、移动端、键盘、存档迁移 | 完整浏览器流程与两种视口通过 |

任何阶段发现核心局面无趣或代价不真实，都允许退回上一阶段，而不是用更多文案掩盖。

### 14.3 限定“如果玩家……”的预算

每个局面优先支持：

- 三种主解法；
- 一种安全退出或错过；
- 一种高风险死亡或永久结果；
- 一种从最近节点重新进入；
- 三到五个最可能破坏连续性的既往状态；
- 一次近期新能力兑现；
- 一次后续回响。

只有当新增变体会改变资源、关系、情报、人物去留、地点状态或后续入口时，才值得增加。纯措辞差异可由条件化文本承担，不独立扩展状态树。

### 14.4 系统先支持常见异常

与其为每个场景编写专用补丁，应优先让通用系统支持：

- 关键人物已死、离开或拒绝合作；
- 物品已经消耗、转交或来源不同；
- 玩家先知道了后揭示的信息；
- 玩家从非标准路线进入地点；
- 玩家带伤、饥饿、受追捕或错过时辰；
- 玩家已经在死亡回照中见过杀招；
- 奖励已经领取，场景被重复进入；
- 旧存档缺少新增字段。

## 15. 主要成本与反面教训

### 15.1 组合爆炸

BG3 后续补丁长期修复人物反应、对白优先级、营地夜间场景、死亡与复活、非标准流程和跨章节状态，说明高反应性会把成本转移到连续性与 QA。本文不据此推断其内部代码，只确认一个公开可见事实：组合越多，边缘流程越需要持续维护。

本项目的防线：

- 稳定 ID；
- 幂等效果；
- 单一事实来源；
- 章节目录和坏跳转校验；
- 奖励首次兑现校验；
- 关键人物状态枚举；
- 旧存档迁移；
- 主要状态组合的浏览器回归矩阵。

### 15.2 内容量掩盖规则噪音

BG3 可以用大量职业、物品和场景容纳边缘能力，本项目不能。每增加一个武学、物品或关系字段，都必须回答：

- 它在哪个局面第一次有用；
- 它以后还会被谁读取；
- 玩家如何知道它生效；
- 没有它时是否仍有别的路；
- 它会增加哪些存档和测试组合。

### 15.3 随机判定诱发读档

BG3 允许自由存档，也在荣誉模式中主动限制读档。对本项目而言，这说明“随机＋无替代失败”容易把玩家推向撤销结果。应以条件、准备、代价和命灯回照为主，而不是让读档成为默认解法。

### 15.4 通用动词变成万能钥匙

如果每个冲突都能用同一高属性、同一毒药或同一武学解决，所谓系统自由会退化成固定最优解。每个局面必须改变约束：

- 目标不同；
- 时间不同；
- 人物底线不同；
- 环境对象不同；
- 使用同一手段的关系或暴露代价不同。

### 15.5 隐藏内容过多

大量身份反应和特殊解法有重玩价值，但本项目当前更需要一条首次游玩就完整的体验。重要人物弧、核心武学兑现和世界基础不能依赖冷门条件；隐藏内容优先承载捷径、代价变化、额外真相和特殊回响。

## 16. 采用、改造与舍弃清单

| BG3 设计 | 处理 | 《大曜江湖》版本 |
| --- | --- | --- |
| 手工局面接受多种系统输入 | 直接采用 | 条件、行动、效果、回流组成局面盒 |
| 身份持续触发世界反应 | 直接采用 | 出身、初心、武学、见闻、死因跨篇章复用 |
| 失败继续推进 | 直接采用 | 带价成功、失败推进、错过、死亡分开设计 |
| 人物拥有独立立场 | 直接采用 | 多维关系＋底线＋见证行为＋剧情阶段 |
| 环境改变战斗和潜行 | 改造采用 | 路线层、时段、警戒、环境对象和准备动作 |
| 营地连接恢复与关系 | 改造采用 | 阶段性落脚点，休息推进时间并结算人物回响 |
| 对话检定与优势／劣势 | 改造采用 | 透明条件、准备修正、追加代价和失败推进 |
| 多职业与自由重置 | 改造采用 | 有因果和代价的五维重分、武学选择与有限改易 |
| 炼金制作消耗品 | 改造采用 | 保持医术、材料来源、火候、品质和人物债务深度 |
| 荣誉／自定义模式 | 暂不采用 | 用双灯、条件信息和首领行为构成单一作者体验 |
| 四人队伍与可控同伴 | 舍弃 | NPC 独立行动，联系人提供有限协助 |
| 多人协作与玩家投票 | 舍弃 | 始终保持单人叙事 |
| 三维物理、表面与自由投掷 | 舍弃 | 每个地点精选一至三个可交互对象 |
| 海量职业、法术和装备 | 舍弃 | 少量武学与物品，每项都有近期和长期用途 |
| 通用 D20 作为核心判定 | 舍弃 | 条件可见、代价可控、命灯回照 |
| 频繁读档试不同结果 | 舍弃 | 安全退出、失败推进、有限命灯和结果履历 |

## 19. “曹青离场—沈福反目”的验证框架

下一阶段不需要复制 BG3 的大型任务，只需用一个局面验证跨系统回响。剧情事实仍以 `STORY_BIBLE.md` 为准，以下只规定系统问题。

### 19.1 必须共同读取的状态

- 曹青好感、身份揭示与传授结果；
- 沈福门路、银子选择和既有关系；
- 主角掌握的医术、炼丹、针法和武学；
- 沈家密会与已知秘密；
- 材料、丹药、银钱与联系人；
- 当前伤势、日期、地点和追捕状态。

### 19.2 至少三种过程

不预设具体剧情答案，但局面应允许三类方法共同存在：

1. 以关系、债务和人物底线处理正面冲突；
2. 以医术、见闻、证据和地点调查还原真相；
3. 以跟踪、绕路、设伏或正面战斗处理追逐与暴力。

### 19.3 共同后续不抹平的状态

无论最终进入哪个共同章节，都应保留并在后续读取：

- 曹青是否仍为联系人、留下什么门路或秘密；
- 沈福是否敌对、失踪、死亡、负债或仍可交易；
- 丹房和药材渠道是否可用；
- 主角是否被某势力警戒或追捕；
- 哪条证据链成立；
- 是否杀人、制伏、放走或错过关键人物；
- 新能力在追踪、调查或冲突中如何被亲手兑现。

### 19.4 验证成功信号

这一局面只有在以下条件同时成立时才算完成：

- 三条过程至少有两种不以战斗为中心；
- 同一能力至少在两个系统中可用；
- 失败不只进入死亡页；
- 至少一个 NPC 的反应读取“见证行为”，而非只读好感；
- 结尾共同节点能显示不同资源、关系、地点或追捕状态；
- 重复进入、回照和旧存档不会重复发奖或丢失人物状态；
- 下一篇章至少一次明确回响本局面结果。

## 20. 落地优先级

### A级：下一轮内容就采用

1. 使用“局面盒＋解法矩阵”设计曹青离场与沈福反目；
2. 为每项新武学写第一次、第二次和长期兑现；
3. 把带价成功、失败推进、安全错过和死亡分开；
4. 为关系事件增加人物底线、见证行为和秘密知情者；
5. 为每场战斗写非杀目标、撤退和一个环境变化；
6. 在结果页明确显示资源、关系、伤势、时间和地点变化；
7. 为共同节点保留不同进入状态，不用一句文案抹平结果。

### B级：P1 城市与调查系统推进时采用

1. 建立通用路线层、警戒和地点持久状态；
2. 建立联系人离场与替换规则；
3. 建立证据的来源、可信度、冲突和纠错；
4. 建立休息时的人物回响队列；
5. 建立势力耳目、传闻和追捕的有限传播；
6. 在内容校验器中加入主解法覆盖、回流和回响检查；
7. 扩大跨篇章身份反应，但保证首次游玩主线完整。

### C级：长期再评估

- 多套难度与信息透明度设置；
- 更广泛的武学组合与环境反应；
- 多地点同时推进的局面；
- 更长周期的势力传闻与身份伪装；
- 非核心支线的更多重玩差异。

以下内容不进入路线图：

- 多人；
- 可控队伍；
- 通用 D20；
- 三维自由地图；
- 海量职业、装备和法术；
- 以频繁读档为默认体验。

## 21. 验收问题

设计或评审一个新篇章时，逐项回答：

1. 玩家进入局面前，是否先认识人物、困境和代价？
2. 局面的稳定事实是什么，哪些结果可以变化？
3. 至少三种解法是否真的读取不同能力与状态？
4. 是否存在一个明显最优、可重复套用的万能解？
5. 失败是否会推进信息、关系、时间或地点状态？
6. 安全退出、错过和死亡是否彼此不同？
7. 新能力是否在一至两个场景内改变了按钮、路线或风险？
8. 同一能力是否在另一个系统中再次有用？
9. NPC 是否只对自己见证或得知的行为反应？
10. 高好感是否错误地覆盖人物底线？
11. 战斗是否有清空生命以外的目标？
12. 战前调查和准备是否改变首轮或失败结果？
13. 不同路线汇合时，伤势、债务、关系和情报是否仍被保留？
14. 后续是否至少一次明确确认玩家造成的结果？
15. 玩家是否知道当前行动会支付什么、承担哪类风险？
16. 重复点击、重复进入和死亡回照是否保持幂等？
17. 关键人物已死、已走或已拒绝时，流程是否仍可继续？
18. 旧存档缺字段时，是否有明确默认值和迁移？
19. 手机与键盘操作是否仍能读懂复杂局面？
20. 删除任一新增系统后，是否会失去真实选择，而不只是少一段文案？

## 22. 进一步问题与限制

本文仍保留以下开放问题：

- 现有旧章节专用 handler 何时迁移到统一局面结构，需根据维护收益单独排期；
- 跨篇章反应的密度需要实际游玩验证，过密会打断节奏，过稀会让世界失忆；
- 条件透明度应由逆天改命、普通观察和人物告知分别承担多少，仍需界面试验；
- P1 的追捕、势力和联系人系统应先服务一个完整闭环，不应提前做全城模拟；
- BG3 的内部状态模型、脚本工具和完整 QA 方法没有公开，本文的生产建议是基于公开资料的适配推导，不是对其技术实现的还原。
