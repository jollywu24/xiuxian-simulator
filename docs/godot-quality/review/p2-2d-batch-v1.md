# P2 完整二维动作整组 v1 评审（2026-09-24）

用户要求先批量制作一组完整二维动作，再只修有问题的帧。本轮已照此执行，不再以单帧小样阻止整组生成。所有动作图都是完整人物和剑的独立透明 PNG；没有拼身体部件，也没有将 3D 母版伪称为当前角色源。

## 实际产物

- `art_source/linshui-quality/v1/characters/hero-v2/2d-batch-v1/source/`：S 步行 8 张、SE 直刺 12 张完整人物高分辨率源图。其中直刺 07 沿用此前已有的完整二维关键帧，其余 19 张为本轮生成；原图均保留。
- `revisions/`：只针对 S 步行 05、08 和 SE 直刺 04 各重做一稿；打包采用修订稿，原稿没有覆盖。提示词与采用记录见 `generation-record.md`，逐帧来源、SHA256、Alpha 边界见 `frame-contract.json`。
- `frames/`：S/SE 待机各 4、S 步行 8、SE 直刺 12，共 28 张独立 256×256 PNG。统一脚锚 `(128,220)`、固定源图采样和画布位置；不逐帧按包围盒居中、缩放或拆层补位。
- `scripts/godot-quality/package_2d_batch.py` 可从保留的源图重建上述帧和合同。Godot 验证场景通过 `SpriteFrames`/`AnimatedSprite3D` 播放，运行时没有为某帧改像素尺寸、缩放或偏移。

## 实机结果

在本机 Godot 4.7.2 Forward+、RTX 5060 上，1280×720 与 1920×1080 都已实际渲染并保存每一帧。两个技术报告记录步行依次播放 0–7、直刺依次播放 0–11；按空格起招时移动锁定、重复空格不重启动作、结束后解除锁定。逐帧截图是停止播放后用同一人物变换抓取的真实引擎视口，连续播放顺序另行计时验证，二者不能混称实时录屏。

证据：`evidence/p2-character-2d-batch-v1-report-{720,1080}.json`、同前缀 `s-walk-01..08` 与 `se-thrust-01..12` 截图；自动检查命令为 `python scripts/godot-quality/review_composition.py --character2d-batch --height 720` 和 `--height 1080`。窗口中 `F3` 循环 S 步行，`Space` 播放一次 SE 直刺，`F4` 切换 S/SE 静止姿态。该窗口是 P2 诊断入口，不是最终默认游戏入口。

3. 尚未制作可编辑分层像素修订母版，也没有 90 秒连续真实游玩录屏或完整互动命中事件。当前攻击仅验证展示与输入锁定；木桩命中未接入此诊断场景。
